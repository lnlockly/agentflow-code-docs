# Debug stuck project

## TL;DR

Стуки чаще всего в одном из 5 мест: (1) `approved` + 0 plan_tasks → auto-bot / scrape провал; (2) `running` + все tasks done но `status≠done` → preview-gate hold (placeholder); (3) `running` + task in_progress >15min → pod crash / kubectl exec hang; (4) `awaiting_approval` без `proposed_plan` → Maestro propose failed; (5) `paused_until > now()` → token-budget rate-limit. Этот runbook — точная последовательность SQL + grep команд для каждого случая.

## Diagnostic flow (по симптому)

```
1) Узнать текущий статус
   SELECT id, status, kind, plan_id, workspace_project_name, paused_until,
          bot_username, preview_url, updated_at
     FROM projects WHERE id = :id;

2) Лента событий
   SELECT kind, payload, created_at
     FROM project_events
    WHERE project_id = :id
    ORDER BY id DESC LIMIT 30;

3) Plan tasks
   SELECT id, assignee_slug, status, retry_depth, parent_task_id,
          is_amendment_dispatch, depends_on, claimed_at
     FROM plan_tasks WHERE plan_id = (SELECT plan_id FROM projects WHERE id = :id)
    ORDER BY id ASC;
```

### Case A — `status='approved'`, 0 plan_tasks

```
project_events kind list?
  ├─ есть 'workspace_ready' но нет 'plan_started':
  │   └─ kind=tg_bot? → проверь auto-bot:
  │        grep "\\[auto-bot\\] getMe network error" pod-logs   (auto-bot.ts:299)
  │        grep "pool empty and FF_AUTO_BOT_CREATE_BOTFATHER"   (auto-bot.ts:161)
  │        фикс: расширить BOT_TOKEN_POOL ИЛИ FF_AUTO_BOT_CREATE_BOTFATHER=1
  │   └─ есть @handles в brief? → auto-scrape:
  │        grep "auto_scrape_post_ws_failed"                     (projects.ts:1983)
  │        фикс: дернуть Jarvis pod (kubectl exec ... — проверь Telethon session)
  └─ нет 'workspace_ready':
      grep "pod_provision_failed" / "failure_kind:.*node_cpu_exhausted"
      → orphan sweep: ORPHAN_SWEEP_ENABLED=true (services/orphan-sweep.ts)
      → или вручную: kubectl describe statefulset project-<slug>
```

### Case B — `status='running'`, все plan_tasks done

```
project_events последнее событие?
  ├─ 'preview_gate_blocked':
  │   curl -sI https://<slug>.preview.agentflow.dev/  → 200?
  │   curl -s  https://<slug>.preview.agentflow.dev/  → body? title?
  │     "Workspace ready" в HTML?     → Caddy всё ещё stub → placeholder-repoint
  │       services/pingers/placeholder-repoint.ts:94 — должен подхватить sweep
  │     SHA256 ∈ src/config/placeholder-hashes.json? → coder положил boilerplate как-есть
  │     body < 2048b? → недостаточно контента, retry coder
  │     api kind: GET /health → JSON {ok:true}?
  │   → reload Caddy в pod'е: curl -X POST 127.0.0.1:2019/load (с plan.json payload)
  └─ нет 'preview_gate_blocked' но всё-равно не финализит:
      grep "stuck_project_detected"                              (healer.ts)
      → ручной trigger: POST /internal/projects/:id/admin-approve   (routes/internal.ts:685)
```

### Case C — `plan_tasks` в `in_progress` > 15min

```
claimed_at старый (>15 min) → pod крэш во время выполнения
   UPDATE plan_tasks SET status='pending', claimed_at=NULL WHERE id = :task_id;
   (или дождаться pool-worker — он сам подхватывает на следующем тике, claim.ts:33)

retry_depth > MAX_AUTO_RETRY?  → grep "auto_retry_cap_reached"
   → запустить amendment dispatch вручную (maestro escalation)
```

### Case D — `status='awaiting_approval'`, `proposed_plan IS NULL`

```
grep "propose_project_plan_failed" в логах
проверь budget: SELECT budget_cents_remaining FROM users WHERE id = project.owner_user_id;
  → если 0 → POST /admin/users/:id/budget (routes/internal.ts:1098) restock
проверь providers: SELECT slug, enabled FROM llm_provider_configs;
```

### Case F — `workspace_provision_retry attempt=N/8` без `workspace_ready`

Workspace pod не поднимается: vcluster syncer не может создать STS / PVC.
Чаще всего — переполненная per-tenant `code-exec-quota` ResourceQuota.

```
1) Подтвердить причину — syncer логи внутри vcluster pod:
   kubectl -n af-tenant-<userId> logs user-<userId>-0 -c syncer --tail=200 \
     | grep -i 'exceeded quota\|forbidden\|failed to create'
   → ищем: `persistentvolumeclaims "..." is forbidden: exceeded quota:
            code-exec-quota, requested: requests.storage=5Gi,
            used: requests.storage=240Gi, limited: requests.storage=100Gi`

2) Recovery через документированный endpoint:
   curl -X POST -H "x-agentflow-secret: $INTERNAL_API_SECRET" \
     'https://api.agentflow.website/internal/tenant/<userId>/expand-quota?storage=500Gi&pvc=100'
   → ожидается 200 с {ok:true, applied:{...}, kicked_sts:[...]}
   → endpoint автоматически rollout-restart'ит все stuck STSs

3) Ручной bypass (если endpoint недоступен или вернул 500):
   # admin kubeconfig vcluster'a лежит в syncer'е
   kubectl -n af-tenant-<userId> exec user-<userId>-0 -c syncer -- \
     wget -qO /tmp/kubectl https://dl.k8s.io/release/v1.30.0/bin/linux/amd64/kubectl \
     && chmod +x /tmp/kubectl
   kubectl -n af-tenant-<userId> exec user-<userId>-0 -c syncer -- \
     /tmp/kubectl --kubeconfig=/data/pki/admin.conf -n default \
     patch resourcequota code-exec-quota --type=merge \
     -p '{"spec":{"hard":{"persistentvolumeclaims":"100","requests.storage":"500Gi","limits.cpu":"80","limits.memory":"128Gi","pods":"80","requests.cpu":"32","requests.memory":"32Gi"}}}'
   # потом kick stuck STSs:
   kubectl -n af-tenant-<userId> exec user-<userId>-0 -c syncer -- \
     /tmp/kubectl --kubeconfig=/data/pki/admin.conf -n default \
     rollout restart sts/project-<name>
```

### Case E — `paused_until > now()`

```
SELECT paused_until FROM projects WHERE id = :id;
  → auto-pinger очистит в положенное время (services/rate-limit.ts)
  → можно вручную: UPDATE projects SET paused_until = NULL WHERE id = :id;
```

## DB tables / env / API surface

**Полезные SQL views:**
```sql
-- Все застрявшие projects
SELECT id, status, kind, updated_at,
       extract(epoch from (now() - updated_at))/60 AS minutes_idle
  FROM projects
 WHERE status IN ('approved','running','awaiting_approval')
   AND updated_at < now() - interval '20 minutes'
 ORDER BY updated_at ASC;

-- Stuck tasks
SELECT pt.id, pt.plan_id, pt.assignee_slug, pt.status, pt.retry_depth, pt.claimed_at
  FROM plan_tasks pt
 WHERE pt.status = 'in_progress'
   AND pt.claimed_at < now() - interval '15 minutes';
```

**Env / admin endpoints:**
- `POST /internal/projects/:id/admin-approve` (`routes/internal.ts:685`) — force-approve bypass.
- `POST /admin/users/:id/budget` (`routes/internal.ts:1098`) — restock budget.

## Failure modes / fast fixes

| Симптом | Лог-строка для grep | Где починить |
|---|---|---|
| Approved + 0 tasks | `[auto-bot] getMe network error` | `services/auto-bot.ts:299` |
| Running + preview hold | `preview_gate_blocked` | `pool-worker/preview-gate.ts:211` |
| Task in_progress >15 min | (нет — claimed_at старый) | manual UPDATE → pending |
| Awaiting approval, no plan | `propose_project_plan_failed` | budget / providers |
| Paused (token budget) | `rate_limit_paused` | `services/rate-limit.ts` |
| Stuck warn в логах | `stuck_project_detected` | `services/pingers/healer.ts:44` |
| Caddy всё ещё stub | `placeholder_repoint_skipped` | `services/pingers/placeholder-repoint.ts:94` |
| `workspace_provision_retry` без `workspace_ready` | `exceeded quota: code-exec-quota` (vcluster syncer log) | `POST /internal/tenant/:userId/expand-quota` или ручной `kubectl patch` (см. Case F) |
| expand-quota endpoint возвращает 500 | `Cannot read properties of undefined (reading 'url')` at `request.js#query` | агент-pod нужен передеплой с PR #208 (fix c.req.query binding). До деплоя — bypass через `kubectl exec user-<userId>-0 -c syncer` |
| Cold-tenant approval race: project flipped to `failed`, потом снова `running` | `approval_in_flight` event без matching `approval_provisioned`/`approval_failed`, и `approval_exhausted` через 5-15 мин | `services/pingers/approval-retry.ts` пропускает retry пока есть незакрытый `approval_in_flight` < 15 мин ИЛИ `users.tenant_status IN ('provisioning','pending')`. Если пинговать всё равно фейлит — проверь, что `runProjectApprovalBackground` дошёл до своего try/catch и записал `approval_failed` (`services/projects.ts:1742`). |
