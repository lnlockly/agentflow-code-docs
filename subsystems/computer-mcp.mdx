# Desktop / Computer-Agent bridge

## TL;DR
Server bridge for `agentflow-desktop` (the on-Mac daemon). Maintains a long-lived WS tunnel
per device, dispatches high-level tasks (`task_dispatch`), persists `task_action / task_complete /
task_error` to `device_action_log`, and proxies the daemon's local MJPEG capture to cabinet as
`multipart/x-mixed-replace`.

## DB / Env / API
- Tables:
  - `user_devices` — owner, scope, status, secret hash, enrollment token
  - `device_sessions` — one per dispatched task; agent_id `'desktop-task'`
  - `device_action_log` — `task_id` + `kind` (`tool_call|task_action|task_complete|task_error`)
- Env: `API_KEY_HMAC_SECRET` (or `AUTH_JWT_SECRET` fallback for `:apikeys` salt)
- Routes:
  - `POST /me/devices/:id/dispatch_task` → 202 `{task_id, session_id}` / 409 `device_offline`
  - `GET  /me/devices/:id/tasks/stream` → SSE (device-wide)
  - `GET  /me/devices/:id/tasks/:task_id/stream` → SSE (per-task, closes on complete/error)
  - `GET  /me/devices/:id/live_stream` → `multipart/x-mixed-replace; boundary=frame`
  - `POST /me/telegram/send` → 200 `{ok, message_id}` / 503 `tg_account_not_linked` / 503 `tg_primary_login_missing` / 502 MCP error. Body `{chat_id, text}`. `chat_id="me"` routes to Saved Messages.
  - `POST /me/matrix/send` (alias `POST /me/matrix/post`) → 200 `{ok, event_id}` / 404 `room_not_found` / 502 `bridge_error` / 502 `matrix_bridge_unreachable`. Body `{room_id, text}`. Posts as the caller's Dendrite puppet via `issueMatrixTokenForAfUser`.
- WS protocol additions (`WsMessage` in `packages/shared-types/devices.ts`):
  - S→C: `task_dispatch`, `subscribe_stream`, `unsubscribe_stream`
  - C→S: `task_action`, `task_complete`, `task_error`, `stream_frame`
- Project kind: `desktop_agent` is user-facing and bypasses the spa-collapse path.

### SSE pub/sub contract

`deviceTaskStream` (in `services/device-task-stream.ts`) is the single subscription primitive used by both `/tasks/stream` and `/tasks/:task_id/stream`. It wraps the existing `taskEvents` EventEmitter and adds:

- **Filtering** — `subscribe(deviceId, taskId | null, send)` either fans out every event for a device, or just one task.
- **History replay** — `loadRecentEvents(deviceId, taskId | null, limit=100)` reads the last N rows of `kind IN ('task_action','task_complete','task_error')` from `device_action_log` joined through `device_sessions.device_id`. SSE handlers replay those before subscribing, so the cabinet timeline is non-empty on open.
- **Unified payload** — `TaskStreamEvent` carries a `kind` discriminator (`task_action | task_complete | task_error`), `device_id`, `task_id`, `ts`. Action variant adds `action`, `detail?`, `screenshot_b64?`, `screenshot_url?`. Complete variant adds `answer`, `iterations?`, `tokens_used?`, `cost_usd?`. Error variant adds `error`.

The SSE writer in `routes/me-devices.ts:writeTaskStreamEvent` emits each event twice: once as a named SSE event (`action` / `complete` / `error`) carrying the legacy camelCase shape the existing cabinet (`CabinetDeviceLive.tsx:319-322`) listens for, and once as a default `message` event carrying the unified `{kind, …}` payload for new consumers. Per-task subscriptions auto-close after `task_complete` or `task_error`.

## Auto-start guarantees (updated 2026-05-22)

| OS | Boot trigger | Restart policy | linger needed | Notes |
|---|---|---|---|---|
| macOS (launchd) | `RunAtLoad=true` in `com.agentflow.desktop.plist` | `KeepAlive{Crashed:true, SuccessfulExit:false}`, `ThrottleInterval=10` | N/A | `ProcessType=Background` + `LowPriorityIO=true` added to prevent Jetsam kills under memory pressure. `launchctl bootstrap gui/<uid>` on install. |
| Linux (systemd user) | `WantedBy=default.target` + `systemctl --user enable --now` | `Restart=on-failure`, `RestartSec=10`, `StartLimitIntervalSec=0` | Yes — `loginctl enable-linger <user>` (best-effort; installer warns if it requires sudo) | Without linger the unit starts only after the user's first login session. |
| Windows (Task Scheduler) | `AtLogon` (current user) **+** `AtStartup` (system boot) | `RestartCount=5`, `RestartInterval=PT1M` via `ScheduledTaskSettingsSet` | N/A | `RunLevel=Limited` — daemon does not require admin. Python detection falls back `python` → `py -3`; links to download page if neither found. |

### selftest subcommand

`agentflow-desktop selftest` is the recommended liveness probe. It checks:
1. `capture_screen_fast` — screen capture backend works (required).
2. `capture_screen (png)` — full PNG capture (required).
3. `window_list` / `clipboard_read` — OS permissions in place (required).
4. `read_terminal` — optional; FAIL here does not fail the overall exit code.
5. `auth_file` — `~/.agentflow/auth.json` present and contains `api_key` (required).
6. `scope_file_parseable` — `~/.agentflow/computer-scope.toml` parseable TOML (required).
7. `ws_endpoint_reachable` — TCP + TLS handshake to the WS host succeeds (required).

Exit 0 = PASS; exit 1 = one or more required checks failed.
Both `install.sh` and `install.ps1` call `agentflow-desktop selftest` at the end of installation.

Source: `agentflow-computer-mcp/src/agentflow_computer_mcp/desktop_cli.py:225` (`cmd_selftest`).

## Failure modes
| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| `dispatch_task` returns 409 | none — synchronous response | check `/me/devices/:id` status, daemon offline |
| Task progress missing from cabinet SSE | `[devices-ws] persist_task_row_failed` | DB connection / migration not applied |
| Synthetic session row appears | none — silent fallback | daemon resumed task across pod restart (expected) |
| MJPEG returns headers but no frames | `[device] online ... tools=0` | daemon hasn't subscribed yet OR daemon never pushes `stream_frame` |
| `subscribe_stream` never sent | `streamSubscriberCount` flips 0→1 silently if connection missing | device offline; daemon must come online + cabinet re-opens stream |
| Live viewport black until page reload (cabinet user reports "have to refresh"); fixed 2026-05-22 | look for `[device] resync subscribe_stream device=... pending=N`; if MISSING after `[device] online` while a live tab is open, the daemon never received the re-arm | `services/devices-ws.ts:hello` calls `resyncStreamSubscription(deviceId, send)`; if absent, the daemon stays unsubscribed across reconnects (heartbeat timeout, sleep/wake) |
| Daemon ignores `task_dispatch` | `ws task_dispatch id=... task=...` missing from `agentflow-desktop` log | upgrade daemon to ≥0.2.1 (PR auto/ws-client-task-dispatch-2026-05-22 wired routing) |
| `task_action` SSE silent though daemon is online | `current_task_id` empty inside `DriverState` | local-input path: viewer's `POST /task` now assigns `local-*` id via `enqueue_task` — old viewer builds put raw strings and never tag the task |
| `af_send_telegram_message` returns 503 `tg_account_not_linked` | none — synchronous response | caller has no `chat_tg_links` row; bind via cabinet → Telegram |
| `af_send_telegram_message` returns 503 `tg_primary_login_missing` | none — synchronous response | `chat_tg_links.primary_login_id` is null or non-numeric; user must pick a primary via `POST /me/chat/tg/set-primary` |
| `af_post_matrix_room` returns 502 `matrix_bridge_unreachable` | `[chat-tg] ... token issue failed` (pattern reused) | Dendrite down or `MATRIX_AUTH_KEY` rotated; user re-login via Element SSO |
| Cabinet timeline empty after `/tasks/stream` connect | `[device-task-stream] history_load_failed` | SQL replay failed; the live path still works — check `device_action_log` join with `device_sessions` and migration `2026-05-22a-device-tasks.sql` |
| New SSE consumer reads `data` but sees only `action/complete/error` | none — wire-shape issue | bind to default `message` event for the unified `{kind, …}` payload; named events ship the legacy camelCase shape |
| Daemon Jetsam-killed on Mac at night (device goes offline) | `agentflow-desktop` absent from `launchctl list` | Re-run `install.sh` (adds `ProcessType=Background` + `LowPriorityIO=true` to plist) |
| Linux daemon not running after reboot | `systemctl --user status agentflow-desktop` → not found | Run `sudo loginctl enable-linger $USER`; without linger user units don't start at boot |
| Windows daemon missing after cold boot (not user logon) | Task Scheduler history → task never ran | Re-run `install.ps1` (adds `AtStartup` trigger alongside `AtLogon`) |
| `agentflow-desktop selftest` fails `ws_endpoint_reachable` | TCP connection refused or TLS error | Check firewall / VPN; endpoint is `wss://agentflow.website/_agents/_devices/connect` |

## Performance (streamer, updated 2026-05-22)

PR lnlockly/agentflow-computer-mcp#8 applied three optimisations to `driver/streamer.py` and `platform/mac.py`:

| Optimisation | Before | After | Effect |
|---|---|---|---|
| `width_cap` | 1400px | 1280px | ~17% fewer pixels through Pillow resize |
| JPEG `quality` | 68 | 58 | ~25% smaller frame at negligible visual loss for monitoring UX |
| blake2b-8 content-hash dedup | every frame emitted | identical hash → skip WS emit | static desktop: ~660 KB/s → ~0 KB/s |
| Adaptive back-off | fixed 10 fps emit | doubles interval on publish failure (max 1s), restores on success | prevents WS queue pile-up under backpressure |

Measured frame size on a 5K Retina display: **28 KB** (was ~50 KB). Dedup eliminates ≥50% of WS emits when screen content is unchanged (regression-tested in `tests/test_streamer_perf.py`).
