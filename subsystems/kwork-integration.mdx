# Kwork Integration (`POST /me/integrations/kwork`)

## TL;DR

Kwork is one entry (`slug='kwork'`) in the generic integration registry
at `agentflow-agents/src/services/integration-providers.ts`. The desktop
daemon scrapes Kwork cookies from the operator's logged-in browser and
POSTs them to either `/me/integrations/kwork` (compat alias for PR #796
callers) or the generic `/me/integrations/:provider`. The handler
repacks cookies into Playwright `storage_state` JSON, seals the payload,
and writes a row in `project_secrets` keyed `KWORK_SESSION_JSON` inside
the operator's `integration_hub` sentinel project. Studio templates read
that row when surfacing account pickers.

For the generic flow + every other provider, see
[Generic Integrations](/subsystems/generic-integrations).

**Read path (load-bearing):** `resolveSessionCookies` (`kwork-inbox.ts:148`) calls `resolveCredential(userId,'kwork')`, which treats the `user_credentials` **vault** as PRIMARY and only falls back to `project_secrets` when the vault has no active row. Because `/connect` historically wrote ONLY to `project_secrets`, an older active vault row could shadow freshly-pasted cookies → kwork served a logged-out `/inbox` → `window.chatList` absent → empty dialogs. `/connect` now mirrors into the vault too.

## Data flow

```
agentflow-desktop daemon
   │  connect_integration('kwork')
   │  POST /me/integrations/kwork {cookies: [...]}
   ▼
me-integrations.ts: compat wrapper at /me/integrations/kwork
   └── delegates to handleProviderPost(getProvider('kwork'), userId, body)
        ├── zod parse cookies                      → 400 invalid_body
        ├── any cookie domain in financial denylist → 403 domain_denied
        ├── required_cookie_names check             → 400 no_kwork_session_cookie
        ├── pickOrCreateHubProject(userId)
        ├── upsertHubSecret(hubId, 'KWORK_SESSION_JSON', 'kwork:storage_state', sealed, why)
   ▼
201/200 { ok, project_id, secret_id, secret_created, hub_created,
          session_cookie_present, csrf_cookie_present, cookie_domains }
```

The PR #795 fork-a-preset flow is removed. Cookies no longer create a
per-account project; one `integration_hub` per user holds the secret
and every studio template's account picker reads it from there.

## DB / Env / API

- **Tables:**
  - `projects` — one `kind='integration_hub'` row per owner.
  - `project_secrets` — sealed `KWORK_SESSION_JSON` (load-bearing) keyed `(project_id, key)`.
- **Env:** `AGENTS_MASTER_KEY` (32-byte base64) — fail-loud if absent.
- **Routes:**
  - `POST /me/integrations/kwork` (compat alias, daemon-fed)
  - `POST /me/integrations/:provider` (generic — also accepts `kwork`)
  - `POST /me/integrations/kwork/connect` (paste-JSON UX, separate router)
- **Preset slug:** `kwork-account-replier` (must be `status='active'` in `agent_presets`).

## Failure modes

| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| Daemon POST returns 400 on every cookie batch | `no_kwork_session_cookie` | Kwork rotated cookie names → update `required_cookie_names` in the `kwork` registry entry (`integration-providers.ts`) |
| Daemon POST returns 403 with `domain_denied` | `domain_denied` | Cookie batch contained a banking/exchange domain — daemon-side bug |
| Same cookies create N hub projects | (no log — `SELECT count(*) FROM projects WHERE owner_user_id=X AND kind='integration_hub'`) | `pickOrCreateHubProject` lookup broke — should return ≤1 |
| 200/201 but studio account picker is empty | (no log — `SELECT * FROM project_secrets WHERE project_id=<hub> AND key='KWORK_SESSION_JSON'`) | `default-studio-flow-account.ts → listKworkSecretRows` not reading from the hub project |
| `entities=[]` from `/me/accounts/kwork:owner/entities?kind=dialogs` even after fresh cookies re-loaded; parser works in isolation | (no log — `SELECT id,status,updated_at FROM user_credentials WHERE user_id=X AND kind='kwork'` vs `project_secrets.updated_at`) | Stale **active vault row** shadowed the fresh `project_secrets` cookie header because `resolveCredential` reads the vault FIRST. Fix: `/me/integrations/kwork/connect` now mirrors the payload into the vault via `saveUserCredential` (revokes the stale active row). `me-integrations-kwork.ts` |
