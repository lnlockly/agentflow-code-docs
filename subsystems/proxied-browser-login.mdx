# Proxied browser login (backend)

> **Status: shipped 2026-06-04 (#1115).** PIECE 2 of the proxied-cloud-browser-connect design. Registry-driven + generic — per-platform login config is an existing integration-registry row plus a small `PLATFORM_VAULT_KIND` map; no `if (platform === …)` control flow, no DB schema change (the sticky proxy ref rides in `user_credentials.meta`). The owner's platform password is typed into the real login page and is **never** stored or logged.

## TL;DR

The connect drawer asks the backend to launch a chromium **inside the pod**, bound to the account's sticky residential proxy ([per-account proxy session](/subsystems/per-account-proxy-session)), and navigate to the platform `login_url`. The FE drives that headless browser through a **screenshot-poll + input-POST** contract (no CDP socket is exposed). When the owner finishes logging in, `confirmAndCapture` reads `context.cookies()`, builds a Playwright storage-state payload, and saves it into the **same credential vault** the `/me/integrations/:platform/connect` path writes to — so the session is minted ON the residential exit IP the connector will reuse.

## Data flow

```
ConnectDrawer / ProxiedBrowserFlow (FE)
  │ POST /me/integrations/kwork/browser-login/start
  ▼
ProxiedBrowserLoginService.startLogin(ownerUserId, 'kwork')
  ├─ loginConfigFor('kwork') → { login_url, logged_probe_js, vaultKind }
  ├─ accountRef = config.vaultKind
  ├─ proxyUrl = proxySession.proxyUrlForAccount(ownerUserId, accountRef, {platform})
  ├─ proxyRef = proxySession.proxyRefForAccount(...)            // persisted later
  ├─ driver.launch({ loginUrl, proxy: proxyUrlToPlaywright(proxyUrl) })
  └─ sessions.set(sessionId, { handle, config, proxyRef, ownerUserId })
  → { session_id, login_url, proxied, screenshot_url, input_url, status_url }
        │
        ▼ FE poll loop
  GET  …/screenshot   → handle.screenshot()        (PNG base64)
  POST …/input        → handle.input({click|type|press|navigate})
  GET  …/status       → handle.evaluate(logged_probe_js) → connected?
        │
        ▼ owner asserts "logged in"
  POST …/confirm → confirmAndCapture
        ├─ cookies = handle.cookies()
        ├─ { payload, cookieCount } = buildStorageStatePayload(cookies, domains)
        ├─ cookieCount === 0 → refuse (no empty session)
        └─ saveCredential(ownerUserId, vaultKind, payload,
                          { meta:{ proxy_ref:{ sid, country } } })
  → connector later resolves the SAME sticky proxy + this session
```

## DB / Env / API

- **Tables:** none new. Cookies land in `user_credentials` (the same vault `/connect` uses); the sticky proxy ref rides in `user_credentials.meta.proxy_ref` (`{ sid, country }`).
- **Env:** `NODEMAVEN_PROXY_USER` / `NODEMAVEN_PROXY_PASS` / `NODEMAVEN_PROXY_GATEWAY` (proxy disabled ⇒ `proxied:false`, the browser launches direct). Playwright ships transitively via `@playwright/test` → `playwright@1.60.0`.
- **Routes (all owner-auth via `requireSession`):**
  - `POST /me/integrations/:platform/browser-login/start`
  - `GET  /me/integrations/:platform/browser-login/:session_id/status`
  - `POST /me/integrations/:platform/browser-login/:session_id/confirm`
  - `GET  /me/integrations/:platform/browser-login/:session_id/screenshot`
  - `POST /me/integrations/:platform/browser-login/:session_id/input`
  - `POST /me/integrations/:platform/browser-login/:session_id/cancel`
- **Registry contract:** a platform is login-capable iff it has an integration-registry row (`login_url` + `logged_probe_js`) AND an entry in `PLATFORM_VAULT_KIND`. Extend by adding a row, never an `if`.

## Failure modes

| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| `404 unsupported_platform` on start | `unsupported_platform` | `routes/me-integrations-browser-login.ts:94` — platform missing from `PLATFORM_VAULT_KIND` or registry (`services/proxied-browser-login.ts:87`) |
| `404 session_not_found` on status/screenshot | `session_not_found` | session expired (idle sweep at `services/proxied-browser-login.ts:274`) — restart `start` |
| confirm refuses to save | `cookieCount === 0` guard hit | `services/proxied-browser-login.ts:457` — owner confirmed before the login set cookies; keep driving the page |
| status never flips to `connected` | `hint:'no_ready_probe'` | `services/proxied-browser-login.ts:90` — registry row has no `logged_probe_js`; owner must use explicit confirm |
| chromium fails to launch in pod | playwright launch error (no `--no-sandbox` parity) | `services/proxied-browser-login-driver.ts:125` — pod needs the `--no-sandbox` / `--disable-dev-shm-usage` args |
| pod cold-start pulls playwright unnecessarily | n/a (perf) | `services/proxied-browser-login-driver.ts:31` — `loadChromium` is lazy; keep imports `import type` only |
| `403 navigate_blocked` on a navigate action | `navigate_blocked` | `services/proxied-browser-login.ts` `isSafeNavigateUrl` refused the target — financial domain (`FINANCIAL_DOMAIN_DENYLIST`), internal/private/metadata host (`169.254.169.254`, `10.x`, bare cluster name, `.svc`/`.internal`/`.local`), or a non-http(s) scheme. Guards SSRF (browser egresses DIRECT from the pod when NodeMaven proxy is unset) + financial-cookie capture that would bypass the `start` denylist. |
