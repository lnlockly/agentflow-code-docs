# LLM router

## TL;DR

Все LLM-вызовы внутри agentflow-agents идут через `invokeAI()` → mini-registry, которая выбирает провайдера по `ModelType` (`TEXT_SMALL`/`TEXT_BIG`/`EMBEDDING_*` и т.п.), приоритету (desc) и owner_user_id-скоупу. Перед вызовом — budget gate (`assertUserBudget`), после — запись в `agent_usage`. DB-таблица `llm_provider_configs` позволяет добавлять providers (anthropic-compat или openai-compat) без деплоя — `refreshDbProviders` тикает каждые N секунд и подкидывает новые handlers в registry.

## Data flow

```
Agent / service вызывает invokeAI({ ctx, model_type, messages, max_tokens })
   ↓
instrumented.invokeAI (line 112)
   ↓ assertUserBudget(ctx.user_id, estimated_cost) → BudgetExceededError → emit budget_cap_hit
   ↓
registry.useModel (registry.ts:158)
   ↓ select providers WHERE supports(model_type) AND (owner=null OR owner=ctx.user_id)
   ↓ ORDER BY priority DESC, registered_at ASC
   ↓ try first → on rate_limit / 5xx → try next (candidate fallback chain)
provider handler (anthropic-compat | openai-compat | custom)
   ↓ POST upstream API → parse → return TextGenerationResult
   ↓
instrumented.invokeAI logs to agent_usage:
   { user_id, project_id, model, provider, prompt_tokens, completion_tokens, cost_usd }
   ↓
return result
```

## DB tables / env / API surface

**DB:**
- `llm_provider_configs` — `{ slug, kind: anthropic_compat|openai_compat, base_url, api_key_sealed, model_id, priority, owner_user_id?, supports_model_types[], max_tokens, enabled }`.
- `agent_usage` — append-only usage log: `{ user_id, project_id, agent_slug, model, provider, prompt_tokens, completion_tokens, cost_usd, created_at }`.
- `users.budget_cents_remaining` — counter, decremented в budget gate.

**Env:**
- `XAI_API_KEY` — opt-in registration for xAI provider в bootstrap.
- `OPENROUTER_API_KEY` — legacy fallback (ai-router/bootstrap.ts:21).
- `LLM_DB_REFRESH_MS` — cadence для refreshDbProviders.

**API surface:**
- `invokeAI(ctx, opts)` — единственная точка входа из application кода.
- `useModel(...)` — низкоуровневый bypass (без budget gate; для системных вызовов вроде embed-on-write).
- `POST /admin/users/:id/budget` (`routes/internal.ts:1098`) — restock budget.

## Failure modes

| Симптом | Лог-строка для grep | Где починить |
|---|---|---|
| Budget exceeded — agent застрял | `BudgetExceededError` или `budget_cap_hit` | `ai-router/instrumented.ts:112` |
| Ни один provider не отвечает | `AiRouterError: no_provider_for_model` | `ai-router/registry.ts:158` (useModel) |
| Все рейт-лимитнули | `ai_router_all_candidates_failed` | `ai-router/registry.ts:158` (fallback chain) |
| DB provider не подтянулся | `refresh_db_providers_failed` | `llm-providers/db-driven.ts:454` |
| Owner-scoped provider не виден | `provider_owner_mismatch` | `ai-router/registry.ts:158` (filter clause) |
| Stream aggregate упал в середине | `aggregate_openai_stream_failed` | `llm-providers/db-driven.ts:80` |
