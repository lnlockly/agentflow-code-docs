# LLM router

## TL;DR

Все LLM-вызовы внутри agentflow-agents идут через `invokeAI()` → mini-registry, которая выбирает провайдера по `ModelType` (`TEXT_SMALL`/`TEXT_BIG`/`EMBEDDING_*` и т.п.), приоритету (desc) и owner_user_id-скоупу. Перед вызовом — budget gate (`assertUserBudget`), затем exact-match response cache (опц. `LLM_CACHE_ENABLED=1`), после — запись в `agent_usage`. DB-таблица `llm_provider_configs` позволяет добавлять providers (anthropic-compat или openai-compat) без деплоя — `refreshDbProviders` тикает каждые N секунд и подкидывает новые handlers в registry.

## Response cache (exact-match)

`response-cache.ts` хеширует канонический payload `{modelType, model, temperature, system, messages, tools, tool_choice, max_tokens}` через SHA-256 и пишет/читает строку из `llm_response_cache`. Кешируются только детерминированные пути: TEXT_* при явном `temperature===0` и OBJECT_* (любые). IMAGE/VIDEO/TTS/embedding/streaming — пропускаются на гейте `isCacheable`. TTL — 7 дней (read-time фильтр + cleanup sweep). На `hit` пропускается upstream + `agent_usage` (чтобы не дублировать billing); на `miss` — обычный fallback chain через `useModel`, ответ кладётся в кеш. Опт-ин через env флаг — выключенный cache no-op'ит и оба пути работают как раньше.

Backlog: semantic / pgvector lookup для случаев когда exact-match промахивается на пунктуации/пробелах.

## Data flow

```
Agent / service вызывает invokeAI({ ctx, model_type, messages, max_tokens })
   ↓
instrumented.invokeAI (line 112)
   ↓ assertUserBudget(ctx.user_id, estimated_cost) → BudgetExceededError → emit budget_cap_hit
   ↓ isCacheable + computeCacheKey → lookupCached → HIT? return cached response (skip usage record)
   ↓
registry.useModel (registry.ts:158)
   ↓ select providers WHERE supports(model_type) AND (owner=null OR owner=ctx.user_id)
   ↓ ORDER BY priority DESC, registered_at ASC
   ↓ try first → on rate_limit / 5xx → try next (candidate fallback chain)
provider handler (anthropic-compat | openai-compat | custom)
   ↓ POST upstream API → parse → return TextGenerationResult
   ↓
instrumented.invokeAI logs to agent_usage:
   { user_id, project_id, model, provider, prompt_tokens, completion_tokens, cost_usd }
   ↓ storeCached(hash, response) — fire-and-forget on miss
   ↓
return result
```

## DB tables / env / API surface

**DB:**
- `llm_provider_configs` — `{ slug, kind: anthropic_compat|openai_compat, base_url, api_key_sealed, model_id, priority, owner_user_id?, supports_model_types[], max_tokens, enabled }`.
- `agent_usage` — append-only usage log: `{ user_id, project_id, agent_slug, model, provider, prompt_tokens, completion_tokens, cost_usd, created_at }`.
- `llm_response_cache` — `{ hash (sha256), model_type, provider, model, prompt_preview, response (jsonb), created_at, last_hit_at, hit_count }`. 7-day TTL at read time.
- `users.budget_cents_remaining` — counter, decremented в budget gate.

**Env:**
- `XAI_API_KEY` — opt-in registration for xAI provider в bootstrap.
- `OPENROUTER_API_KEY` — legacy fallback (ai-router/bootstrap.ts:21).
- `LLM_DB_REFRESH_MS` — cadence для refreshDbProviders.
- `LLM_CACHE_ENABLED` — `1`/`true` to enable exact-match response cache (default off).

**API surface:**
- `invokeAI(ctx, opts)` — единственная точка входа из application кода.
- `useModel(...)` — низкоуровневый bypass (без budget gate; для системных вызовов вроде embed-on-write).
- `POST /admin/users/:id/budget` (`routes/internal.ts:1098`) — restock budget.

## Failure modes

| Симптом | Лог-строка для grep | Где починить |
|---|---|---|
| Budget exceeded — agent застрял | `BudgetExceededError` или `budget_cap_hit` | `ai-router/instrumented.ts:112` |
| Ни один provider не отвечает | `AiRouterError: no_provider_for_model` | `ai-router/registry.ts:158` (useModel) |
| Все рейт-лимитнули | `ai_router_all_candidates_failed` | `ai-router/registry.ts:158` (fallback chain) |
| DB provider не подтянулся | `refresh_db_providers_failed` | `llm-providers/db-driven.ts:454` |
| Owner-scoped provider не виден | `provider_owner_mismatch` | `ai-router/registry.ts:158` (filter clause) |
| Stream aggregate упал в середине | `aggregate_openai_stream_failed` | `llm-providers/db-driven.ts:80` |
| Stale cache return для подобных но разных промптов | `[llm-cache] hit` без ожидаемого upstream call | `ai-router/response-cache.ts:64` (computeCacheKey — добавь missing field в payload). |
| Cache lookup/store падает — но запросы проходят | `[llm-cache] lookup_failed` / `store_failed` | `ai-router/response-cache.ts:154` (Postgres reachable? миграция применена?). |
| Cache double-bills юзера | `[llm-cache] hit` + agent_usage row с теми же tokens | `ai-router/instrumented.ts` (cacheHit guard на usage insert). |
