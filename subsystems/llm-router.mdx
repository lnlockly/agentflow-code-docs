# LLM router

## Post-refactor canonical (2026-05-28)

PR #913 consolidated ~50 hard-coded model strings (`gpt-5.3-codex`, `claude-*`) across `env.ts`, `character.ts`, `project-daemon.ts`, `tenant-bootstrap.ts`, `agent-importer.ts` onto a single alias: **`flow`**. The `ANTHROPIC_TO_ANY_ALIAS` const that used to live alongside `pickFlowUpstream` was deleted; its six rows now live in `llm_model_aliases` and `pickFlowUpstream` consults the DB first.

What this means for callers:
- Don't pass a model string. Pass `model: 'flow'` (or omit it and inherit the default).
- The alias resolves through `llm_model_aliases` → `FLOW_PREFERENCE_ORDER` → upstream pick.
- DB row for `flow` is now reachable; if you see fall-through to `legacy-callwithfallback` despite priority-50 DB rows, check the auth key on the matching `llm_provider_configs` row (the lazy fall-through is the silent-401 failure mode).

## TL;DR

Все LLM-вызовы внутри agentflow-agents идут через `invokeAI()` → mini-registry, которая выбирает провайдера по `ModelType` (`TEXT_SMALL`/`TEXT_BIG`/`EMBEDDING_*` и т.п.), приоритету (desc) и owner_user_id-скоупу. Перед вызовом — budget gate (`assertUserBudget`), затем exact-match response cache (опц. `LLM_CACHE_ENABLED=1`), после — запись в `agent_usage`. DB-таблица `llm_provider_configs` позволяет добавлять providers (anthropic-compat или openai-compat) без деплоя — `refreshDbProviders` тикает каждые N секунд и подкидывает новые handlers в registry.

## `flow` alias multi-provider failover (T1.10, 2026-06-03)

The `flow` alias resolves to a **TEXT_LARGE chain**, not a single pinned provider. Ordering is owned by `llm_provider_configs` (priority DESC), so the live chain is:

| Pri | Provider | Role |
|---|---|---|
| 30 | `db:codexsale` (codex.sale) | primary — intermittently flaps |
| 20 | `db:designapi-text` | first fallback |
| 15 | `db:claudecodeapi` | second fallback |
| 10 | `db:claude-oauth` | last resort |

There is **no `preferredProvider` hard-pin** for `flow` — codex.sale leads purely by priority, so when it flaps the `useModel` loop advances down the chain on its own. The loop fails over on a thrown error AND on `healthy()===false`, and only raises `AiRouterError` (listing every attempt) when the whole chain is exhausted. The chain ordering and which providers are enabled is an owner-tunable DB concern: `UPDATE llm_provider_configs SET priority=… / enabled=…` + `POST /admin/llm-providers/refresh`. No code change needed to reorder.

### Flapping-aware unhealthy cache (always-on)

When codex.sale throws, the loop records it into the per-provider unhealthy cache (`markUnhealthy`, 60s TTL, `agentflow-agents/src/services/ai-router/health-probe.ts:120`). On the **next** `flow` call within that TTL the candidate is moved to the back of the queue (`agentflow-agents/src/ai-router/registry.ts:187`), so the call goes straight to designapi instead of replaying the 3-attempt transient-retry storm against the flapping primary. After the TTL the provider is retried — the cache self-heals. This is **always on**, independent of `PICK_HEALTHY_ENABLED` (that env still only gates the pre-call probe). Cached-unhealthy providers are demoted, never removed: if the entire chain is cached-unhealthy they are still tried as a last resort so a transient cluster-wide blip surfaces a clean `AiRouterError`, not a false `no_provider`.

Verified locally (codex.sale forced to throw 503):

```
[ai-router] provider db:codexsale failed, falling through type=TEXT_LARGE owner=platform err=503 Сервис временно недоступен
MODEL_RETURNED=db:designapi-text   # served from the next provider, no error to the caller
```

## Response cache (exact-match)

`response-cache.ts` хеширует канонический payload `{modelType, model, temperature, system, messages, tools, tool_choice, max_tokens}` через SHA-256 и пишет/читает строку из `llm_response_cache`. Кешируются только детерминированные пути: TEXT_* при явном `temperature===0` и OBJECT_* (любые). IMAGE/VIDEO/TTS/embedding/streaming — пропускаются на гейте `isCacheable`. TTL — 7 дней (read-time фильтр + cleanup sweep). На `hit` пропускается upstream + `agent_usage` (чтобы не дублировать billing); на `miss` — обычный fallback chain через `useModel`, ответ кладётся в кеш. Опт-ин через env флаг — выключенный cache no-op'ит и оба пути работают как раньше.

Backlog: semantic / pgvector lookup для случаев когда exact-match промахивается на пунктуации/пробелах.

## Data flow

```
Agent / service вызывает invokeAI({ ctx, model_type, messages, max_tokens })
   ↓
instrumented.invokeAI (line 112)
   ↓ assertUserBudget(ctx.user_id, estimated_cost) → BudgetExceededError → emit budget_cap_hit
   ↓ isCacheable + computeCacheKey → lookupCached → HIT? return cached response (skip usage record)
   ↓
registry.useModel (registry.ts:158)
   ↓ select providers WHERE supports(model_type) AND (owner=null OR owner=ctx.user_id)
   ↓ ORDER BY priority DESC, registered_at ASC
   ↓ try first → on rate_limit / 5xx → try next (candidate fallback chain)
provider handler (anthropic-compat | openai-compat | custom)
   ↓ POST upstream API → parse → return TextGenerationResult
   ↓
instrumented.invokeAI logs to agent_usage:
   { user_id, project_id, model, provider, prompt_tokens, completion_tokens, cost_usd }
   ↓ storeCached(hash, response) — fire-and-forget on miss
   ↓
return result
```

## DB tables / env / API surface

**DB:**
- `llm_provider_configs` — `{ slug, kind: anthropic_compat|openai_compat, base_url, api_key_sealed, model_id, priority, owner_user_id?, supports_model_types[], max_tokens, enabled }`.
- `agent_usage` — append-only usage log: `{ user_id, project_id, agent_slug, model, provider, prompt_tokens, completion_tokens, cost_usd, created_at }`.
- `llm_response_cache` — `{ hash (sha256), model_type, provider, model, prompt_preview, response (jsonb), created_at, last_hit_at, hit_count }`. 7-day TTL at read time.
- `users.budget_cents_remaining` — counter, decremented в budget gate.

**Env:**
- `ANTHROPIC_LARGE_MODEL` — default model for `legacy-callwithfallback` provider when caller doesn't pin one. Live flip lever for TEXT_LARGE — set to `claude-opus-4-7` (2026-05-14) or any other model the upstream proxy serves.
- `ANTHROPIC_SMALL_MODEL` — same idea for TEXT_SMALL (currently `claude-sonnet-4-6` — haiku-4-5 is broken on the proxy per `claudecodeapi.ts:54`).
- `EAST_API_3_KEY` (canonical) / `ANTHROPIC_API_KEY` (DEPRECATED alias — one release of back-compat) + `ANTHROPIC_BASE_URL` — proxy creds. Production uses east-api-3.org (NOT real api.anthropic.com — the prefix `sk-ant-03-*` is proxy-format). The env var was renamed 2026-05-27 because every new contributor pasted a real Anthropic key into `ANTHROPIC_API_KEY` and watched every request return 401; `EAST_API_3_KEY` makes the upstream obvious. `env.ts:eastApi3Key()` reads new name first, falls back to old. Migration `2026-05-27d-rename-east-api-3-key.sql` flips `llm_provider_configs.api_key_env` from `ANTHROPIC_API_KEY` → `EAST_API_3_KEY` for east-api-3 rows.
- `XAI_API_KEY` — opt-in registration for xAI provider в bootstrap.
- `OPENROUTER_API_KEY` — legacy fallback (ai-router/bootstrap.ts:21).
- `LLM_DB_REFRESH_MS` — cadence для refreshDbProviders.
- `LLM_CACHE_ENABLED` — `1`/`true` to enable exact-match response cache (default off).

**API surface:**
- `invokeAI(ctx, opts)` — единственная точка входа из application кода.
- `useModel(...)` — низкоуровневый bypass (без budget gate; для системных вызовов вроде embed-on-write).
- `POST /admin/users/:id/budget` (`routes/internal.ts:1098`) — restock budget.

## Failure modes

| Симптом | Лог-строка для grep | Где починить |
|---|---|---|
| Budget exceeded — agent застрял | `BudgetExceededError` или `budget_cap_hit` | `ai-router/instrumented.ts:112` |
| Ни один provider не отвечает | `AiRouterError: no_provider_for_model` | `ai-router/registry.ts:158` (useModel) |
| Все рейт-лимитнули | `ai_router_all_candidates_failed` | `ai-router/registry.ts:158` (fallback chain) |
| `flow` primary (codex.sale) flaps — fell through to designapi | `provider db:codexsale failed, falling through` | `ai-router/registry.ts:287` — expected behaviour; chain advanced. If it falls through on EVERY call, codex.sale is down longer than the 60s unhealthy TTL — check upstream codex.sale status. |
| `flow` chain re-hits a dead codex.sale on every call (retry storm) | repeated `provider db:codexsale failed, falling through` with `<400ms` between, never reaching designapi cache | `ai-router/registry.ts:187` — flapping-aware skip not demoting; confirm `health-probe.markUnhealthy` ran (the loop calls it on throw at `registry.ts:279`). |
| All four `flow` providers down | `AiRouterError: all_providers_failed for TEXT_LARGE: db:codexsale=…; db:designapi-text=…; db:claudecodeapi=…; db:claude-oauth=…` | `ai-router/registry.ts:158` — every provider in the chain threw. Rotate keys / check `llm_provider_configs.enabled`. |
| DB provider не подтянулся | `refresh_db_providers_failed` | `llm-providers/db-driven.ts:454` |
| Owner-scoped provider не виден | `provider_owner_mismatch` | `ai-router/registry.ts:158` (filter clause) |
| Stream aggregate упал в середине | `aggregate_openai_stream_failed` | `llm-providers/db-driven.ts:80` |
| Stale cache return для подобных но разных промптов | `[llm-cache] hit` без ожидаемого upstream call | `ai-router/response-cache.ts:64` (computeCacheKey — добавь missing field в payload). |
| Cache lookup/store падает — но запросы проходят | `[llm-cache] lookup_failed` / `store_failed` | `ai-router/response-cache.ts:154` (Postgres reachable? миграция применена?). |
| Cache double-bills юзера | `[llm-cache] hit` + agent_usage row с теми же tokens | `ai-router/instrumented.ts` (cacheHit guard на usage insert). |
| Top-priority DB rows silently 401 — routing falls through to lower priorities | DB rows id=23/6/1 enabled but never hit; logs show `selected=legacy-callwithfallback` despite higher-priority rows | `llm_provider_configs` — rotate the auth key matching each row's `base_url`, OR set `enabled=false` to stop the lazy-fallthrough overhead. |
| Tenant pod still on sonnet after agentflow-agents was flipped to opus | Tenant runtime logs show `model=claude-sonnet-4-6` even after the env flip on agentflow-agents | `services/tenant-bootstrap.ts:341-342` hardcodes `ANTHROPIC_LARGE_MODEL=claude-sonnet-4-6` into spawned pod env. Patch the hardcode or thread the env through from agentflow-agents. |
| Caller requested Opus on the static `claudecodeapi` provider but got Sonnet | response `model=claude-sonnet-4-6` despite `params.model='claude-opus-4-7'` | `llm-providers/claudecodeapi.ts:56-58` — stale opus→sonnet rewrite from when the proxy didn't serve Opus. East-api-3 and claudecodeapi.cloud both serve opus-4-7 as of 2026-05-14 (probed). Backlog: drop the rewrite. |
