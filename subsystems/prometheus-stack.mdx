# Prometheus Stack

## TL;DR

Audit-4 + Audit-7 found Grafana dashboards + scrape annotations committed, but no Prometheus pod actually running. `k8s/prometheus.yaml` fixes that — a single-replica `prom/prometheus:v3.0.1` in the `monitoring` namespace, ClusterRole + ServiceAccount for service/pod discovery, two scrape jobs (`kubernetes-pods` and `kubernetes-services`). Phase 5 also wires three new metric families on the existing `/metrics` route so billing-loss incidents (`recordusage_failures_total`) and upstream LLM regressions (`llm_request_duration_seconds`, `llm_retry_attempts_total`) become alertable.

## Data flow

```
Prometheus (monitoring/prometheus)
  │
  ├──[kubernetes-pods]──> any pod with prometheus.io/scrape=true
  │      ├── agentflow-agents (api)    :4100/metrics  (bearer)
  │      └── agentflow-workers         :4100/metrics  (bearer)
  │
  └──[kubernetes-services]──> any Service with prometheus.io/scrape=true
         ├── mautrix-telegram-metrics   :8001/metrics
         ├── dendrite-metrics           :8008/_dendrite/metrics
         └── agentflow-agents-metrics   :4100/metrics  (bearer)
```

Scraped series:
- `recordusage_failures_total{reason}` — billing-loss canary.
- `llm_request_duration_seconds{upstream, status}` — per-upstream latency + outcome.
- `llm_retry_attempts_total{reason}` — fallback rate.
- `matrix_bots_events_total{bot, kind}` — chat-stack activity.
- `matrix_bots_handler_duration_seconds{bot}` — bot handler latency.
- `matrix_bots_ready{bot}` — readiness gauge.
- `node_*` — prom-client default node metrics.

## DB / Env / API

- **Env:** `MATRIX_METRICS_AUTH_TOKEN` — bearer required by `/metrics` on the agentflow-agents pod. When empty the endpoint returns 404 and Prom marks the target DOWN (acceptable until ops sets the secret).
- **Routes:** `GET /metrics` on `:4100`, `GET :9090/targets` for the Prometheus UI.
- **Namespaces:** `monitoring` (prom), `franchise-factory` (everything else).
- **No MCP tools.** Operate via standard kubectl from `ssh ff-france`.

## Failure modes

| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| Prom target DOWN with 404 on `:4100/metrics` | `metrics_disabled` in agents pod logs | Set `MATRIX_METRICS_AUTH_TOKEN` env on `agentflow-agents` + matching `bearer_token` in Prom scrape config |
| Prom pod CrashLoopBackOff | `parsing YAML file /etc/prometheus/prometheus.yml` | Validate `prometheus-config` ConfigMap, kubectl rollout restart |
| RBAC denied on discovery | `forbidden: User "system:serviceaccount:monitoring:prometheus"` | Re-apply ClusterRole + ClusterRoleBinding from `k8s/prometheus.yaml` |
| Cardinality blow-up on `recordusage_failures_total` | n/a (silent — visible in `/metrics` size) | `classifyRecordUsageError` collapses unknowns to `other`; reject any new `reason` value not enumerated in `services/matrix-bots/metrics.ts` |
| Histogram missing the `error` bucket label | `llm_request_duration_seconds_count` series with only `2xx`/`5xx` | Catch path in `callUpstreamWithFallback` must call `.observe()` with `status: 'error'` before `continue` |

## Operational runbook

```bash
# Apply once
ssh ff-france "kubectl apply -f k8s/prometheus.yaml"

# Verify
ssh ff-france "kubectl get pods -n monitoring"
ssh ff-france "kubectl port-forward -n monitoring svc/prometheus 9090:9090 &"
# Browse http://localhost:9090/targets — kubernetes-pods + kubernetes-services jobs should list discovered pods.

# Enable the bearer-gated /metrics path on agents
ssh ff-france "kubectl set env deploy/agentflow-agents -n franchise-factory MATRIX_METRICS_AUTH_TOKEN=<token>"
```
