# Landing app shell + design tokens

## TL;DR

All v2 pages (`/studio`, `/projects`, `/marketplace`, `/my/agents`, `/inbox`, `/triggers`, `/account/usage`, `/account/billing`, `/account/settings`, `/admin/hub`, `/status`) wrap their bodies in `AppShellV2`. The shell renders a 240px sidebar + 70px topbar with a single set of design tokens defined in `dark-tokens.css`. Two sidebar variants exist: the regular nav for everyday browsing and an ADMIN nav that activates only when the user is on `/admin/*` AND `user.is_admin === true`. Admin entries never bleed into the regular workspace shell.

**Apps-cleanup 2026-05-29 (UX overhaul §3):** the regular nav is now grouped by outcome, not one flat list. `WORKSPACE_SECTIONS` renders «Создать» (`CREATE_NAV`: Кабинет/Проекты/Устройства/Навыки) then «Работа» (`WORK_NAV`: Мои агенты/Маркетплейс/Приложения); `INSIGHTS_NAV` is the «Кабинет» group (Биллинг/Партнёрка/Настройки). Removed from the sidebar: **Singularity** (`/singularity` — static duplicate hub, no own backend) and **Квесты** (`/start` — gamification stub). The `/apps` launcher dropped its **Души** (`/workspace/souls`) tile — graph-executor was unwired (PR #917), souls is tombstoned. All three routes still resolve by direct URL (archive-not-break; souls `/me/souls` still answers 200 pre-Phase-3). Audit + per-item evidence: `plans/autonomous/_apps-cleanup-audit.md`. i18n keys `app.shell.section.{create,work,cabinet}` in ru/en/zh.

**«Маркетплейс» = the flows app (IA 2026-05-30).** Owner correction: "the
marketplace" is the rebranded templates/automation app at
`flows.agentflow.website` (seam-2 SSO via `/flows` → `FlowsLaunch` →
`POST /me/flows/sso`), **not** the in-app agent catalog. So the prominent
`CORE_NAV` «Маркетплейс» now points at `/flows` (`AppShellV2.tsx` CORE_NAV +
mobile BOTTOM_NAV). The in-app hire-an-agent catalog (`MarketplaceV2` at
`/marketplace`) is a separate `MORE_NAV` item **«Нанять агента»** (i18n
`app.shell.nav.hire_agents`, `UserPlus` icon) — distinct from «Мои агенты»
(`/account/agents`, owned agents). The duplicate «Автоматизации»
(`flows_app → /flows`) MORE entry was dropped. Legacy `/account/marketplace`
(old `AccountMarketplace` → `Marketplace.tsx`, an embedded duplicate of the
unified grid) is retired: route redirects to `/marketplace`, both components
deleted, `FloatingGuide` refs repointed. Seam-2 SSO verified live:
`POST /me/flows/sso` → 200 + activepieces JWT + `publicUrl
flows.agentflow.website` (`FF_ACTIVEPIECES_ENABLED` on). Nav map summary:
«Маркетплейс»→`/flows` · «Нанять агента»→`/marketplace` · «Мои агенты»→`/account/agents`.

## Admin section split (2026-05-15)

Owner complaint: admin links surfaced inside the regular workspace shell. Fix:

1. `AppShellV2` swaps `WORKSPACE_NAV + INSIGHTS_NAV` → `ADMIN_NAV` when `isAdminPath(location.pathname) && user.is_admin` is true. A "Back to workspace" row sits above the admin section.
2. Admin avatar dropdown gets an "Admin" entry only when `user.is_admin === true` — one click to `/admin/hub`.
3. `AccountHeader.tsx` dropped its inline `🛡 Admin` pill — admin entry no longer bleeds into Hub/Account chrome.
4. `Hub.tsx` extraNav dropped its admin link for the same reason.

## Routes wired in the shell

`agentflow-landing/src/main.tsx` mounts:

- `/admin` → redirect to `/admin/hub`
- `/admin/hub` → `AdminHubV2` (gated by `AccessGate`)
- `/account/admin/projects`, `/admin/campaigns`, `/admin/ads`, `/admin/flow`, `/admin/billing`, `/admin/workspace` — admin-only pages, all wrapped in `AppShellV2` so the ADMIN_NAV sidebar shows automatically.

## Plain-language copy rule (h-polish 2026-05-30)

User-facing strings stay plain human Russian. **Banned jargon** in any user-visible
string: `казна`, `саплай`, `treasury`, `supply`, `operator`, `protocol`, plus any
crypto/DAO/insider lingo. Also banned: `бесплатно` / `free` (AgentFlow is paid). The
token-launchpad crypto product (`pages/LaunchToken.tsx`, `components/launch-token/*`,
`components/token-pages/*`, `pages/Whitepaper.tsx`, `prod.economy.*` / `app.launch_token.*`
i18n keys) is the one allowed exception — `treasury` / `supply` there are correct domain
terms for that audience, not core-cabinet copy. The **public front door**
(https://agentflow.website — `App.tsx` + `sections/landing-v3/*`) is verified clean via
browser-MCP snapshot.

Empty-states must read "no X yet, do Y" in Russian, never raw English `Loading…` / `Error:`
or a dev string. Good references already in tree: `pages/ProjectsDashboard.tsx:549`
(`EmptyProjects`), `pages/MarketplaceV2.tsx:698` (error + no-results), `app.agents.empty`
i18n key. h-polish PR 1 Russified `Profile.tsx` modal, `LiveProject.tsx` + `LiveProjectNewsPost.tsx`
loading/empty, and reworded the `Desktop.tsx` demo card off `бесплатно`.

**Static `index.html` meta.** The pre-hydration `<title>` / `description` / OG / Twitter
fallback (what crawlers + first-paint see before `useHead` runs) lives in `index.html`.
Keep it plain RU, no `operator` / `decentralized marketplace` jargon — h-polish follow-up
aligned it to the runtime `seo.home.title/desc` (`AgentFlow — AI собирает твой проект`) and
flipped `<html lang>` + `og:locale` to `ru`. `useHead` (`src/lib/useHead.ts:122`) overrides
`document.documentElement.lang` per active language at runtime.

## Failure modes

| Symptom | Log / grep signature | Where to fix |
|---|---|---|
| Admin sees admin links inside `/studio` or `/projects` | `ADMIN_NAV` rendering when `isAdminPath` returns false | `AppShellV2.tsx:87` — extend `isAdminPath` |
| Non-admin lands on `/admin/hub` and bounces to `/account` | `AdminHubV2` `Navigate to="/account"` | `AdminHubV2.tsx:62` — gate uses `user.is_admin` |
| Hardcoded hex in a new page diverges from the palette | `grep -nE "'#[0-9A-Fa-f]{3,8}'" src/pages/<page>.tsx` | Replace with `var(--af-*)` from the table above |
| Banned jargon / English copy reaches a user page | `grep -rniE "казна\|саплай\|treasury\|\bfree\b\|бесплатн\|Loading…\|Failed:" src/pages` (exclude launch-token) | Swap to plain RU per the copy rule above |
