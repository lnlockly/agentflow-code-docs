# Desktop daemon: live screen stream + cabinet toggle

## TL;DR

Before 2026-05-25 the cabinet «скрыть экран» button only unmounted the
MJPEG `<img>`. The daemon's `CaptureLoop` kept running at ~20 fps —
mss capture, Pillow resize, JPEG encode, blake2b dedup all ran for a
screen nobody was watching. The fix wires the toggle to a new explicit
endpoint `POST /me/devices/:id/stream` and parks the daemon's capture
loop on a wake event when no consumer (cabinet subscriber OR local
viewer) is around.

## Data flow

```
Cabinet «скрыть экран»          POST /me/devices/:id/stream
   │                              {enabled: false}
   ▼                                │
showFeed=false → setStream(false)   ▼
                                  conn.send({type: unsubscribe_stream})
                                    │
                                    ▼
                              daemon clears stream_subscribed
                                    │
                                    ▼
                              CaptureLoop waits on capture_wake — zero mss

Cabinet «показать экран»        POST /me/devices/:id/stream
   │                              {enabled: true}
   ▼                                │
showFeed=true → setStream(true)     ▼
                                  conn.send({type: subscribe_stream})
                                    │
                                    ▼
                              daemon sets stream_subscribed + capture_wake.set()
                                    │
                                    ▼
                              loop resumes within ~50ms → first frame to MJPEG
```

## DB / Env / API

- Tables: none.
- Env: none new.
- Routes:
  - `POST /me/devices/:id/stream { enabled: boolean }` — explicit toggle, returns 202 `{ok, accepted, enabled}`.
  - `GET /me/devices/:id/live_stream` — unchanged; still bumps the legacy `acquireStream` counter.
- WS: `S→C`: `subscribe_stream`, `unsubscribe_stream`. `C→S`: `stream_frame`.
- LocalStorage: `dlive:showFeed:<deviceId>` — `'0'` off, `'1'` on, missing = default ON.

## Failure modes

| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| Cabinet shows frozen frame after hide click | (no log — `<img>` unmounted) | Expected. Re-show pulls a fresh frame. |
| Daemon never sees set_stream | `ws stream subscribed=` absent in daemon log after POST | Check `getConnection(id)` in `device-registry.ts` — null → 409 device_offline. |
| Capture loop keeps running after unsubscribe | continuous `[stream] capture err` OR `local_viewer_count > 0` | Stale local /stream.mjpg client on localhost:8765 holding the counter open. |
| First frame after show takes 1+ s | (no log) | Daemon idle; the 1 s ceiling on `_wait_for_consumer` caught it. `on_stream_subscribe` must call `capture_wake.set()` (see `desktop_cli.py:91`). |
| Toggle flips locally but daemon never gets the frame | `device_offline` from POST /stream | Daemon offline at click time. Daemon picks up the state via `resyncStreamSubscription` on reconnect. |
| Cabinet floods POST /stream every render | `[device] POST /stream` flood | `lastSyncedRef` guard missing in `CabinetDeviceLive.tsx`. |
