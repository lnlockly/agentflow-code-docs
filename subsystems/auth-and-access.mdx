# Auth + access

## TL;DR

`requireSession` middleware пробует три пути в порядке: **x-api-key** (`af_live_*` HMAC-SHA256 lookup) → **Bearer JWT** (HS256) → **af_session cookie**. После N подряд invalid auth с одного IP — 429 `too_many_auth_failures`. Platform-admin gate (`requireAdmin`) кэшит лукап на 60s. Project access: owner OR platform_admin. API-key tiers (PRO 300 RPM / FREE 60 RPM) — опциональный gate за `FF_API_KEY_TIERS=1`.

## Data flow

```
HTTP request → Hono middleware chain
   ↓
requireSession (middleware/auth.ts:151)
   ├─ if header x-api-key present
   │    ↓ check brute-force ban (per IP)
   │    ↓ hashApiKey(raw) → findUserByApiKey
   │    ↓ ok → claims.source='api_key' → next
   │    ↓ fail → bump IP counter, 401 invalid_api_key
   │
   ├─ else if Authorization: Bearer <jwt>
   │    ↓ verify HS256 with AUTH_JWT_SECRET
   │    ↓ ok → claims.source='jwt' → next
   │    ↓ fail → 401 jwt_invalid
   │
   ├─ else if Cookie: af_session=<jwt>
   │    ↓ verify HS256
   │    ↓ ok → claims.source='cookie' → next
   │    ↓ fail → 401 bad_session
   │
   └─ else 401 unauthenticated

Route handler reads c.get('session') → SessionClaims
   ↓ per-route ACL:
userCanAccessProject(user_id, project_id)  — access.ts:39
   ↓ project.owner_user_id === user_id  OR  isPlatformAdmin(user_id)
   ↓ deny → 403 forbidden

Optional: FF_API_KEY_TIERS=1 →
   api-key-rate-limit middleware → 429 rate_limited if RPM exceeded
```

## DB tables / env / API surface

**DB:**
- `users` — `id`, `email`, `is_platform_admin` boolean.
- `api_keys` — `{ id, user_id, hash (HMAC-SHA256 hex), prefix, label, tier?, revoked_at?, last_used_at }`.
- `auth_settings` — singleton row (PK=1) `{ jwt_revision INT, last_revoked_at, last_revoked_reason }`. Bumped by `POST /internal/auth/revoke-all`; baked into every minted session JWT as the `rev` claim. См. emergency-revoke section ниже.
- (см. `src/db/schema.ts`)

**Env:**
- `AGENTS_MASTER_KEY` — base64-32, используется и для api-key HMAC, и для seal/unseal.
- `AUTH_JWT_SECRET` — HS256 secret (shared с tg-mcp).
- `INTERNAL_API_SECRET` — for `/internal/*` и x-agentflow-secret header.
- `FF_API_KEY_TIERS=1` — включает per-tier RPM limits.
- `API_KEY_RPM_PRO=300`, `API_KEY_RPM_FREE=60` — лимиты.
- `BRUTE_FORCE_WINDOW_MS`, `BRUTE_FORCE_LIMIT` — за сколько подряд invalid auth блокируем IP.

**API surface:**
- `requireSession` mounted на all `/me/*`, `/admin/*` routes (`server.ts:428` mount table).
- `requireAdmin` — `/admin/*` strict.
- `requireInternalSecret` — `/internal/*` (см. `routes/internal.ts:49+`).
- `POST /internal/auth/revoke-all` `{reason}` — emergency-logout всех cookie-сессий (см. ниже).
- `GET /internal/auth/revoke-status` — observability для current jwt_revision.

## Emergency revoke-all (kill every cookie session at once)

Owner-only knob для случаев, когда юзеры зацикливаются в re-auth (stale legacy cookies, partial deploys, suspected token leak). Один HTTP call → `auth_settings.jwt_revision++` → каждый `requireSession` с `claims.rev < current` отвечает `401 session_revoked` → landing'овский AuthProvider treat'ит как logged-out → юзер на `/login` → обычный login flow.

**Что НЕ ломается:**
- `x-api-key` auth (`af_live_*`) — валидируется через `api_keys` table, не trip'ает `rev`.
- Device tokens (`/me/devices/*`) — отдельная таблица.
- Internal-secret routes — никакой JWT involved.

**Mint-сайты, которые штампуют `rev`:**
- `agentflow-agents/src/routes/auth-magic-link.ts:174` — `mintSessionJwt` (магик-линк).
- `agentflow-agents/src/routes/auth-password.ts:161` — `mintSessionJwt` (пароль login + reset + register).
- `agentflow-agents/src/routes/auth-password.ts:525` — `/me/auth/mint-session` (короткоживущие daemon-tokens).
- `agentflow-agents/src/routes/auth-tg-callback.ts:82` — `mintSessionJwt` (Telegram widget + Mini App).

**Сервис:**
- `agentflow-agents/src/services/jwt-revision.ts` — `getCurrentJwtRevision()` (5s in-memory cache per pod), `bumpJwtRevision(reason)`, `readRevocationStatus()`.
- `agentflow-agents/src/middleware/auth.ts:256` — verify-then-rev-check, returns `401 session_revoked` when stale.
- Multi-replica: каждый под self-heal'ится в течение `CACHE_TTL_MS` (5s) от revoke-call.

**Owner curl:**
```bash
curl -X POST \
  -H "x-agentflow-secret: $INTERNAL_API_SECRET" \
  -H "content-type: application/json" \
  https://agentflow.website/_agents/internal/auth/revoke-all \
  -d '{"reason":"emergency-logout 2026-05-25"}'
# → {"ok":true,"new_revision":1}

curl -H "x-agentflow-secret: $INTERNAL_API_SECRET" \
  https://agentflow.website/_agents/internal/auth/revoke-status
# → {"ok":true,"jwt_revision":1,"last_revoked_at":"…","last_revoked_reason":"…"}
```

**Backward-compat:** cookies минтенные до этого PR не имеют `rev` claim — `requireSession` трактует missing как `rev=0`. Default `jwt_revision=0` → никто не теряет сессию пока owner не дёрнет endpoint. После первого revoke все legacy cookies приходят `< current` и тоже инвалидируются (это и есть требуемое поведение).

**Bootstrap-schema** (`src/services/bootstrap-schema.ts`) гарантирует table+seed row at pod start. Дедикейтед SQL: `migrations/2026-05-25c-auth-jwt-revision.sql`.

**Error codes (HTTP):**
- 401 `unauthenticated` — нет креденшла.
- 401 `invalid_api_key` / `jwt_invalid` / `bad_session` — auth-specific.
- 429 `too_many_auth_failures` — brute-force ban hit.
- 429 `rate_limited` — RPM exceeded.
- 500 `jwt_not_configured` — `AUTH_JWT_SECRET` отсутствует в env.
- 403 `forbidden` — ACL deny.

**Telegram callback / Mini App contract** (`POST /auth/telegram` + `/auth/telegram/callback`):

`verifyErrorStatus()` at `agentflow-agents/src/routes/auth-tg-callback.ts:110` decides the HTTP status from the verdict error. Clients distinguish "fix your payload" (400) from "fix your session" (401) from "platform broken" (503).

- **400** (malformed body / payload — client bug):
  `missing_init_data`, `invalid_body`, `invalid_init_data`, `missing_hash`,
  `missing_id`, `missing_auth_date`, `invalid_id`, `invalid_auth_date`,
  `missing_user`, `invalid_user_json`, `invalid_user_id`.
- **401** (valid shape, untrusted signature): `invalid_hash`, `auth_date_expired`.
- **503** `login_bot_not_configured` — `TELEGRAM_LOGIN_BOT_TOKEN` / `AGENTFLOW_BOT_TOKEN` unset in env.
