# Matrix Discord Bridge

> **Status: shipped 2026-05-23** — bridge pod, Dendrite registration, and `/me/chat/discord/*` routes land in agentflow-agents `feat/mautrix-discord-bridge`. UI shipped earlier (PR #424).

## TL;DR

`mautrix-discord` runs as a Matrix appservice in `franchise-factory` and bridges a user's Discord DMs + text channels into the same Dendrite homeserver as Telegram, Instagram, and WhatsApp. Same upstream bridgev2 surface — only differences are the **token-paste login** (vs cookies / QR / phone) and the `fi.mau.discord.login.token` step id. Voice channels are out of scope (separate deeplink — see `discord-voice-deeplink.mdx`).

Two paste modes:
- **User token** — pasted from a logged-in Discord web client. Violates Discord ToS; UI shows a banner before submit.
- **Bot token** — pasted from the Discord Developer Portal. Compliant, but only sees guilds the bot was invited to.

## Data flow

```
Browser /account/integrations/discord
       │  (af_session cookie)
       ▼
agentflow-agents POST /me/chat/discord/connect { token, mode }
       │
       ├── classifyDiscordToken(token, mode)  → mode | rejected
       ├── upsert chat_discord_links (status: pending)
       ▼
mautrix-discord pod  (29319)
       │  POST /_matrix/provision/v3/login/start/token?user_id=…
       │      → { login_id, step_id: 'fi.mau.discord.login.token', type:'user_input' }
       │  POST /_matrix/provision/v3/login/step/{login_id}/{step_id}/user_input
       │      body { token }
       │      → { type: 'complete', user_login_id: '<snowflake>' }
       │  GET  /_matrix/provision/v3/whoami           (best-effort, for username)
       │
       │  ▲   ▲
       │  │   │ POST /_matrix/app/v1/transactions   (Dendrite → bridge)
       │  │   │ as_token in registration.yaml
       │  ▼   │
       │  uses hs_token to call back into:
       │  POST /_matrix/client/v3/createRoom, /sendEvent, /register
       │       │
       ▼       ▼
dendrite (8008)
       │
       ▼
agentflow-postgres (DBs: dendrite + mautrix_discord + mautrix_meta + mautrix_telegram + agentflow)
```

The route collapses the upstream **start + step** wizard into a single
HTTP call so the UI contract stays `POST /me/chat/discord/connect { token }`.
Multi-step flows (2FA on a flagged user token) are not supported yet — the
route cancels the wizard and returns `409 multi_step_unsupported` so the UI
can re-prompt cleanly.

## DB / Env / API

### Postgres
- DB: `mautrix_discord` (separate from `mautrix_telegram`, `mautrix_meta`, `mautrix_whatsapp`, and `dendrite`).
- User: `mautrix_discord`, password in Secret `mautrix-discord-secrets` key `MAUTRIX_DISCORD_DB_PASSWORD`.
- AF-side table: `chat_discord_links` (mirror of `chat_whatsapp_links`).

```sql
CREATE TABLE chat_discord_links (
  af_user_id        integer PRIMARY KEY REFERENCES users(id) ON DELETE CASCADE,
  discord_user_id   text,
  discord_username  text,
  status            text        NOT NULL DEFAULT 'pending', -- pending|linked|error
  linked_at         timestamptz,
  last_error        text,
  updated_at        timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX idx_chat_discord_links_status ON chat_discord_links (status);
```

### Env / Secrets
- `mautrix-discord-secrets` (mounted via `envFrom`, then `sed`-substituted into `config.template.yaml`):
  - `MAUTRIX_DISCORD_DB_PASSWORD`
  - `MAUTRIX_DISCORD_AS_TOKEN` — appservice token, matches `as_token` in registration
  - `MAUTRIX_DISCORD_HS_TOKEN` — homeserver token, matches `hs_token` in registration
  - `MAUTRIX_DISCORD_PROVISIONING_SECRET` — guards the bridge's `/_matrix/provision/*` API
- `agentflow-secrets` (mirror, so agentflow-agents sees the secret too):
  - `MAUTRIX_DISCORD_PROVISIONING_SECRET`
- Optional overrides on `agentflow-agents`:
  - `MAUTRIX_DISCORD_INTERNAL_URL` (default `http://mautrix-discord.franchise-factory.svc.cluster.local:29319`)
  - `MAUTRIX_DISCORD_BOT_MXID` (default `@discordbot:agentflow.website`)
- `mautrix-discord-registration` Secret: key `discord.yaml` containing the appservice manifest Dendrite mounts.

### Dendrite config delta

`dendrite-config.yaml` `app_service_api.config_files` ships the line commented:

```yaml
config_files:
  - /etc/dendrite/appservices/telegram.yaml
  - /etc/dendrite/appservices/meta.yaml
  # Uncomment ONLY after `kubectl -n franchise-factory get secret
  # mautrix-discord-registration` returns the resource.
  # - /etc/dendrite/appservices/discord.yaml
```

Dendrite pod mounts the registration Secret via `projected` volume with `optional: true`, so a fresh cluster boots without the file present. Bootstrap order (mautrix-discord.yaml header) creates the Secret, then the operator uncomments the `config_files` line and rolls `deploy/dendrite`. This rule exists because Dendrite fatals on a listed but missing config file (WhatsApp 2026-05-22 incident — see `matrix-chat.mdx` failure mode row).

### Routes (AF-side)

- `GET  /me/chat/discord/status`     — `{ ok, status: 'linked'|'not_linked', discord_username, last_error? }`
- `POST /me/chat/discord/connect`    — body `{ token, mode: 'user'|'bot' }` → `{ ok, status, discord_username? }`
- `POST /me/chat/discord/disconnect` — wipes the row + revokes bridge login

Returns **501 `mautrix_discord_not_configured`** until the env var is populated — the UI hook (`useDiscordLink.ts`) treats 501 as `backendReady=false` and shows the «backend в работе» banner.

### Routes (bridge-side)

- `http://mautrix-discord.franchise-factory.svc.cluster.local:29319/_matrix/app/v1/*`
- `http://mautrix-discord:29319/_matrix/provision/*`
- `@discordbot:agentflow.website` — bridge bot user
- User regex: `@discord_<snowflake>:agentflow.website` (exclusive)

## Token-leak prevention

- The raw token never enters a `console.*` call. Route handlers log `tokenFingerprint(token)` — last 4 chars + first 12 of `sha256(token)`. Pattern: `xYz0:0123456789ab`.
- `callBridge()` in `mautrix-discord-bridge.ts` never echoes the request body.
- Token field on the cabinet UI is `type="password"` (PR #424).

## ToS-risk copy (verbatim, lives on the cabinet)

> Discord может забанить аккаунт за использование стороннего клиента (бриджа). Используй burner-аккаунт, если не хочешь рисковать основным.

## Failure modes

| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| Cabinet shows «backend в работе» permanently | route returns 501, `mautrix_discord_not_configured` | `MAUTRIX_DISCORD_PROVISIONING_SECRET` empty in `agentflow-secrets`. Run the mautrix-discord.yaml bootstrap commands. |
| Connect returns 502 | `[chat-discord] bridge call failed` with code=`mautrix_discord_unreachable` | bridge pod not Ready: `kubectl -n franchise-factory get pod -l app=mautrix-discord` |
| Connect returns 401 | `[chat-discord] token rejected by bridge` | Discord rotated the token, account locked, or 2FA-protected — user pastes a fresh one |
| Connect returns 409 | `[chat-discord] bridge call failed` with code=`multi_step_unsupported` | Discord asked for 2FA on a user token. Use a burner account or wait for the v2 PR that adds the 2FA step UI. |
| Dendrite CrashLoopBackOff after uncommenting `config_files` | `Invalid config file: open /etc/dendrite/appservices/discord.yaml: no such file or directory` | `mautrix-discord-registration` Secret not created. Re-run bootstrap step 3 in `k8s/mautrix-discord.yaml` header. |
| Bridge pod logs `pq: connection refused` | `pq: connection refused` in `mautrix-discord` logs | Postgres connectivity / `mautrix_discord` user creds. Check `kubectl -n franchise-factory exec agentflow-postgres-… -- psql -U mautrix_discord -d mautrix_discord -c '\\du'` |
| `/whoami` succeeds but `discord_username` stays null | (no log; cabinet card shows snowflake) | Best-effort fetch failed and bridge returned only `{id}` — retry by clicking «Обновить» in the cabinet, which re-hits `/status` and re-runs the reconcile path |
| User pastes a token that's &lt;50 chars | route returns 400 `discord_token_invalid_format` with `reason: too_short` | client-side validator should catch this first — check `agentflow-landing/src/lib/discordValidation.ts` |

## Operator bootstrap (one-time)

Documented inline in `k8s/mautrix-discord.yaml` header. Summary:

1. Create the `mautrix_discord` Postgres DB + user.
2. Generate `MAUTRIX_DISCORD_AS_TOKEN`, `MAUTRIX_DISCORD_HS_TOKEN`, `MAUTRIX_DISCORD_PROVISIONING_SECRET`, `MAUTRIX_DISCORD_DB_PASSWORD` (each `openssl rand -hex 32` / 24).
3. `kubectl create secret generic mautrix-discord-secrets …` and mirror the provisioning secret into `agentflow-secrets`.
4. Write the appservice registration YAML and `kubectl create secret generic mautrix-discord-registration --from-file=discord.yaml=…`.
5. Uncomment the `discord.yaml` line in `dendrite-config.yaml` and `kubectl rollout restart deploy/dendrite`.
6. `kubectl apply -f k8s/mautrix-discord-config.yaml -f k8s/mautrix-discord.yaml`.
7. Verify pod Ready, then ask the owner to paste a token in `/account/integrations/discord`.

## Hard caveat

This PR ships **manifests + backend + tests + RAG**. The bridge pod will not boot until the operator runs the bootstrap steps above — `MAUTRIX_DISCORD_*` secrets MUST exist in the cluster before `kubectl apply` is meaningful. Until then, `/me/chat/discord/*` returns 501 and the cabinet shows the «backend в работе» banner.
