# Cabinet «Функции»

## TL;DR
The «Функции» catalog (`/cabinet/functions`) is a витрина of one-click AI
functions: the user types one brief/prompt and gets ONE real artifact back
synchronously — a post, a market analysis, content ideas, an image, an MP4, or
a live landing. Each card calls a thin `POST /me/functions/*` endpoint on
agentflow-agents; «Сделать лендинг» reuses the projects pipeline instead.

## Data flow
```
CabinetFunctions.tsx card
  → agentsApi.generateFunction{Copy,Research,Ideas,Image}(brief|prompt)
    → POST /me/functions/{copy,research,ideas,image,video}  (x-api-key / session)
      → requireSession → ownerUserId = session.sub
      → text functions: services/text-function.ts
          → invokeAI(ModelType.TEXT_LARGE, {messages}, {ownerUserId, agentSlug})
          → flow alias → live provider (e.g. gpt-5.3-codex), billed to owner
      → { ok:true, text }  (or { ok:false, error, detail })
  → card renders the text inline + a «Копировать» button
```

The text functions return plain text (no JSON parse): the model reply is
trimmed; an empty trimmed reply throws `text_function_empty_llm_reply`.

## DB / Env / API
- Routes: `POST /me/functions/copy`, `/me/functions/research`,
  `/me/functions/ideas`, `/me/functions/image`, `/me/functions/video`.
- Auth: `requireSession` (cabinet session cookie OR `x-api-key: af_live_…`).
- LLM: `invokeAI(ModelType.TEXT_LARGE)` → `flow` alias. No model strings are
  hardcoded; provider resolution + priority live in the `llm_provider_configs`
  / `llm_model_aliases` PG tables. `ownerUserId` carries BYOK lookup + billing.
- No new tables. No new env vars.

## Failure modes
| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| Research card shows "try again", 502 | `research generation failed` | `me-functions.ts:106` |
| Ideas card shows "try again", 502 | `ideas generation failed` | `me-functions.ts:133` |
| Empty model reply (400, caller re-runs) | `text_function_empty_llm_reply` | `services/text-function.ts:81` |
| Blank/oversized brief rejected at edge | `invalid_body` | `me-functions.ts` (zod schemas) |
| Budget cap hit before the LLM call | `budget_cap_hit` | `ai-router/instrumented.ts` |

## Verification (live, flow router)
Owner-key smoke (lead runs post-merge):
```bash
curl -X POST https://agentflow.website/_agents/me/functions/research \
  -H "x-api-key: af_live_…" -H "Content-Type: application/json" \
  -d '{"brief":"рынок доставки кофе в Москве"}'
```
Verified 2026-06-01 in-pod via `invokeAI(TEXT_LARGE)` (model `gpt-5.3-codex`
through the `flow` alias, owner user=1): research returned 5 markdown sections
(аудитория / конкуренты / риски / отстройка); ideas returned 7 numbered post
hooks with formats (reels / сторис / рассылка). Both brief-derived, no fake
stats/links, no «бесплатно».
