# Runtime supervisor

## TL;DR

Платформенный «devops в коде»: после того как coder-агент кладёт файлы в `/workspace`, runtime-supervisor самостоятельно классифицирует проект (`static / web / api / bot / worker / mixed / unknown`), запускает build (npm/pnpm/yarn/pip/poetry), пишет Procfile + s6-services, деплоит через Caddy plan.json и проверяет health. На fail — emits `runtime_supervisor_failed` + `auto_build_failed`; pool-worker трактует это как retryable и переоткрывает task с patched bief.

## Data flow

```
plan_task done (coder finished writing /workspace)
   ↓ pool-worker post-build hook → POST /internal/runtime-supervisor/deploy
runtime-supervisor.buildPipeline (line 1146)
   ↓
snapshotWorkspace          — list /workspace, detect lockfiles, package.json
   ↓
classify → RuntimePlan      — kind ∈ {static,web,api,bot,worker,mixed,unknown}
   ↓ if kind=spa|landing|mini_app and no dist/ →
autoBuildSpaIfNeeded        — npm run build (auto-detect manager)
   ↓
detectRuntime               — node 20 / python 3.12 / bun
   ↓
processesForPlan            — Procfile lines OR package.json scripts.start
   ↓
writeS6Services             — /workspace/.runtime/s6/<name>/run
   ↓
deploy                      — write /workspace/.runtime/plan.json + Caddy reload
   ↓
postDeployHealthCheck       — probe /, /health, expected status
   ↓ fail → autoRetryCoder → emit runtime_supervisor_failed + open coder retry task
   ↓ ok   → emit runtime_supervisor_deployed → preview-gate.checkPreviewGate
```

## DB tables / env / API surface

**DB:**
- `projects` — `workspace_project_name`, `kind`, `preview_url`.
- `project_events` — append-only: `runtime_supervisor_deployed`, `runtime_supervisor_failed`, `runtime_supervisor_skipped`, `build_failed`, `auto_build_triggered`, `auto_build_succeeded`, `auto_build_failed`, `auto_build_skipped`, `backend_server_detected_no_procfile`.

**Env:**
- `PREVIEW_GATE_STRICT=true` — strict mode для preview-gate (см. caddy-preview).
- `DEP_INSTALL_AGENT=1` — LLM fallback при failed install.
- `RUNTIME_SUPERVISOR_BUILD_TIMEOUT_MS` — таймаут на build step.

**API:**
- `POST /internal/runtime-supervisor/deploy` (`agentflow-agents/src/routes/internal.ts:914`) — internal endpoint, требует `INTERNAL_API_SECRET`. Принимает `{ workspace_project_name }` → запускает buildPipeline.

## Failure modes

| Симптом | Лог-строка для grep | Где починить |
|---|---|---|
| SPA задеплоилась без `dist/` | `auto_build_skipped` | `runtime-supervisor.ts:608` (autoBuildSpaIfNeeded) |
| `npm run build` упал | `auto_build_failed` или `build_failed` | `runtime-supervisor.ts:1146` (buildPipeline) |
| Backend стартанул, но no Procfile | `backend_server_detected_no_procfile` | `runtime-supervisor.ts:1251` (processesForPlan) |
| Health-check таймаут | `runtime_supervisor_failed` + `post_deploy_health_failed` | `runtime-supervisor.ts:1725` (postDeployHealthCheck) |
| Classifier выдаёт `unknown` | `classify_unknown_kind` | `runtime-supervisor.ts:278` (classify) — добавить heuristic |
| Auto-retry chain не открыл task | `auto_retry_coder_skipped` | `runtime-supervisor.ts:1811` (autoRetryCoder) |
