# Desktop-agent kind (graph-executor)

## TL;DR

`kind=desktop_agent` — это новый тип проекта в graph-executor, который не делает coder, не пишет файлы в `/workspace`, не поднимает preview. Вместо этого он берёт уже опубликованного агента из marketplace (preset, например `desktop-assistant`), резолвит выбранное юзером устройство (`user_devices.id`), создаёт `device_sessions` row и инжектит scope + session_id в runtime-контекст Eliza-агента. Дальше агент работает в обычном цикле — но единственные доступные ему тулы это `computer.*` через [Computer MCP](/subsystems/computer-mcp).

Этим он отличается от `landing` / `tg_bot` / `spa` — там graph многоэтапный (scaffold → coder → smoke → deploy), здесь один node `attach_computer_tools` и сразу runtime.

## Data flow

```
POST /me/projects { brief, kind: 'desktop_agent', agent_id, device_id }
   │
   ▼
runProjectApprovalBackground (projects.ts:(TBD))
   │
   ├─ skip provisionWorkspaceWithRetry (no pod for desktop_agent)
   ├─ skip auto-bot, auto-scrape (none apply)
   ▼
graph-executor → kinds/desktop-agent.ts
   │
   └─ attach_computer_tools node
        │
        ├─ SELECT * FROM user_devices WHERE id=:device_id AND user_id=session.sub
        ├─ if device.status != 'online' → fail: device_offline
        ├─ INSERT device_sessions (device_id, agent_id, project_id, status='active')
        ├─ build runtime context:
        │     { scope: device.scope_json,
        │       session_id: new_session.id,
        │       tool_filter: ComputerDeviceProvider.toolsFor(scope) }
        └─ hand off to Eliza runtime → agent starts loop
   │
   ▼
Eliza agent loop (in agentflow-agents process, no pod)
   │ reads brief.goal
   │ agent.callTool('computer.screen.capture') → mcp-bridge → WS → Mac
   │ reasons about screenshot
   │ agent.callTool('computer.mouse.click', {x,y}) → forward → execute
   │ repeat until: goal achieved (task.complete) | max_actions | budget_exceeded | user revoke
   │
   ▼
session end → UPDATE device_sessions SET ended_at=now(), status=<complete|aborted>
```

## DB / Env / API

**Tables:**

- `projects.kind = 'desktop_agent'` — new value in the `ProjectKind` union.
- `projects.detail_meta` — stores `{ agent_id, device_id }` so workspace UI can resolve them.
- `device_sessions` — see [Computer MCP](/subsystems/computer-mcp).

**Env:**

- None new. Re-uses `mcp-bridge` infra.

**API:**

- `POST /me/projects` with `{ kind: 'desktop_agent', agent_id, device_id, brief }` — create.
- `POST /me/projects/:id/approve` — kicks `runProjectApprovalBackground` which dispatches to `attach_computer_tools`.
- `DELETE /me/projects/:id` — aborts active session (UPDATE `device_sessions.status='aborted'`, fires WS unregister of agent's tool subscriptions).

## How it differs from other kinds

| Kind | Provisions pod? | Coder runs? | Preview deployed? | Terminal node |
|---|---|---|---|---|

## Failure modes

| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| Project approve fails immediately | `[desktop_agent] device_offline device_id=` | User must start launchd job on their Mac; check `/cabinet/devices` |
| Project approve fails with `device_not_owned` | `[desktop_agent] device_not_owned device_id= user=` | `device_id` belongs to another user — UI bug, frontend sent wrong id |
| Session starts but agent never calls a tool | `[device] no tool calls in 5 min session=` | Agent preset has empty `allowed_tools` or LLM returned plain text — check preset config |
| Session starts, all tool calls return `scope_denied` | `[device] scope denied tool=` repeated | Preset `allowed_tools` doesn't match `device.scope_json.allowed_tools` intersection; widen scope |
| Workspace UI shows blank (no live session) | `desktop_agent project has no active session` | `device_sessions` row not created — `attach_computer_tools` failed mid-flight; check `project_events` |
| Project stuck `running` forever | `[desktop_agent] session active over 60min` | Agent in infinite loop. Hit `max_actions` (default 50) or revoke device |
