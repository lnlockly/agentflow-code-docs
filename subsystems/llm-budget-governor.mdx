# LLM budget governor

## TL;DR

Every `invokeAI()` call passes through `enforceBudget(userId, estCostUsd)` before hitting the provider. The governor reads / upserts `llm_budget_state(user_id, day)`, fires one TG notification at 80 % of the daily cap and a kill-switch at 110 %. Owner ids in `LLM_BUDGET_OWNER_BYPASS_USER_IDS` bypass enforcement. Postgres outages fail open. This is the *daily* layer between the cumulative cap (`services/llm-budget.ts`) and the hourly circuit breaker (`services/llm-circuit-breaker.ts`).

## Data flow

```
invokeAI(modelType, params, ctx)
  │
  ├─ assertHourlyCircuit(ctx.ownerUserId)   ← short-window kill
  ├─ assertUserBudget(ctx.ownerUserId)      ← cumulative agent_runs cap
  ├─ enforceBudget(ctx.ownerUserId, 0)      ← THIS — daily governor
  │    ├─ ownerIds.has(userId) → return ok  ← log `budget_owner_bypass`
  │    ├─ INSERT … ON CONFLICT (user, day) DO UPDATE → row
  │    ├─ evaluateGovernor(spent, est, cap, flags, ratios)
  │    │    ├─ projected ≥ killAt → deny + fire_110 once
  │    │    └─ projected ≥ warnAt → allow + fire_80 once
  │    ├─ if fire_80 → sendOwnerNotify + SET notified_80 = TRUE
  │    └─ if fire_110 → sendOwnerNotify + SET notified_110 = TRUE
  │
  ├─ provider call
  │
  └─ recordActualCost(userId, actualUsd)
       └─ INSERT … ON CONFLICT DO UPDATE SET total_cents += actualCents
```

## DB / Env / API

- **Tables:** `llm_budget_state(user_id INT, day DATE, total_cents INT, notified_80 BOOL, notified_110 BOOL, updated_at TIMESTAMPTZ, PK(user_id, day))`
- **Env:**
  - `LLM_BUDGET_PER_USER_USD` — daily cap per user, default `20`
  - `LLM_BUDGET_OWNER_BYPASS_USER_IDS` — CSV of user ids that bypass, default `1`
  - `ADMIN_TG_BOT_TOKEN` + `ADMIN_TG_CHAT_ID` — TG notification path (falls back to `AGENTFLOW_BOT_TOKEN` + chat `1361064246`)
- **Routes:** none new — existing `POST /admin/users/:id/budget` already manages overrides via `user_budget_overrides`.
- **MCP tools:** none.

## Failure modes

| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| Owner blocked at launch | `budget_cap_exceeded user=1` | add user id to `LLM_BUDGET_OWNER_BYPASS_USER_IDS` (env on deploy/agentflow-agents) |
| TG warning spam every minute at 80 % | `budget_80_notified` >1× same user/day | check `notified_80` UPDATE landed; if PG was unreachable the flag stays FALSE and re-fires next time `services/llm-budget-governor.ts:226` |
| Postgres outage blocks every LLM call | `budget_governor_db_failed_open` | expected behaviour — governor returns ok on DB error; investigate the DB outage, not this code |
| Killswitch never fires above $22 spend | absence of `budget_cap_exceeded` in logs | verify `LLM_BUDGET_PER_USER_USD` env is set on `deploy/agentflow-agents`; check `evaluateGovernor` killRatio (`services/llm-budget-governor.ts:122`) |
| Owner bypass with wrong id | `budget_owner_bypass user=N` for unexpected N | `readGovernorConfig` CSV parse — `services/llm-budget-governor.ts:42` |
| Drift between `llm_budget_state.total_cents` and `agent_runs.cost_cents` | `record_cost_failed_open` | DB write of `recordActualCost` dropped; safe — `llm-budget.ts` cumulative cap is the authoritative ledger |
