# Onboarding quests

## TL;DR

`/start` is the "Путь новичка" gamified onboarding page. It used to be
all mock data; 2026-05-15 wired the five sections through `useMockOrApi`
which prefers real API responses and falls back to mocks only on fetch
failure (kept for offline/dev). Quest completion awards FLOW via the
existing `referral_earnings` ledger.

## Data flow

```
/start mount
  ├─► useMockOrApi('/me/quests')         ─► quest list (defs ⊕ user completions)
  ├─► useMockOrApi('/me/earnings')       ─► claimable FLOW total
  ├─► useMockOrApi('/me/referral-link')  ─► personal ref URL
  ├─► useMockOrApi('/raffles/active')    ─► active raffles
  └─► useMockOrApi('/leaderboard')       ─► top users by FLOW

User clicks "Complete quest"
  └─► POST /me/quests/:id/complete  { proofUrl? }
      ├─► INSERT user_quests (user_id, quest_id, proof_url)
      ├─► if reward > 0: INSERT referral_earnings (type='quest', amount)
      └─► refetch ['quests']

useMockOrApi behavior:
  • initialData = mockData      → page renders instantly
  • queryFn tries apiGet(path)  → real data overwrites mock on success
  • on apiGet throw → returns mockData → page silently keeps placeholder
  • staleTime: 30s
```

## DB / Env / API

- Tables (existing, not added by this work):
  - `quest_definitions(id, title, title_ru, reward, sort_order, repeatable)`
  - `user_quests(user_id, quest_id, completed_at, proof_url)`
  - `referral_earnings(user_id, source_user_id NULL, amount, type)` — `type='quest'` for quest rewards
- Routes:
  - `GET /me/quests` — returns `{ ok, quests: [{ id, title, title_ru, reward, repeatable, completed, completed_at }] }`
  - `POST /me/quests/:questId/complete` — body `{ proofUrl? }`
  - Errors: `404 quest_not_found`, `409 already_completed` (non-repeatable + already done)
- Mock constants live in `OnboardingPage.tsx` and only render when the API throws

## Failure modes

| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| Page shows mock quests even after login | `useMockOrApi` catch returned `mockData` | `/me/quests` is failing — check session cookie + that `requireSession` is mounted on the route |
| Complete-quest 404 | `quest_not_found` | `questId` from URL does not match any `quest_definitions.id` |
| Complete-quest 409 | `already_completed` | Non-repeatable quest, user already completed. By design |
| Reward not in earnings page | n/a — only `reward > 0` writes to `referral_earnings` | Zero-reward quests track completion only; expected |
