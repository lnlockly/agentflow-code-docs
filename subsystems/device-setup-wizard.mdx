# Device setup wizard + calm manage view

## TL;DR
`/cabinet/devices/new` (alias `/cabinet/devices/setup`) is a four-step funnel
for non-technical owners: choose where the agent runs → set it up → pick a
first task → done. It replaces the old 4-card chooser (`CabinetDeviceNew`,
still reachable at `/cabinet/devices/new/cards`). The device manage view
(`CabinetDeviceDetail`) now opens on a calm status card + three actions
(Дать задачу / Пауза / Живой просмотр); everything technical (scope, app
whitelist, autonomous goals, history) collapses under ONE «Дополнительно»
disclosure — no `scope_json` editor in the user's face.

## Data flow

```
/cabinet/devices/new (CabinetDeviceSetup)
  Step 1 StepWhere → 'local' | 'cloud'
  Step 2a local:
    devicesApi.mintInstallToken()  → raw af_live_* key
    buildInstallCmd(os, key)       → one copy-paste line
    poll devicesApi.list() every 3s → first NEW online device → advance
  Step 2b cloud:
    agentsPost('/me/hosted-devices', { size, kind:'daemon', preinstall:[] })
    → { device:{ id } }  (readable готовлю → подключаю → готово states)
  Step 3 StepFirstTask:
    devicesApi.dispatchTask(deviceId, {
      task, tool:'agent_run_recipe', scope:{ recipe, params, cron? } })
    ── SEAM: identical shape to DeviceUseCasePicker (PR #543) ──
  Step 4 StepDone → link to /cabinet/devices/:id/live
```

The manage view (`CabinetDeviceDetail`) reads `GET /me/devices/:id` +
`/me/devices/:id/sessions`, derives `nowDoing` + `spentToday`, and exposes
pause/resume, dispatch (via /live), scope, app whitelist, autonomous panel,
session history, check-update and revoke — all reachable, progressively
disclosed.

## DB / Env / API
- Routes used: `POST /me/api-keys/install-token` (agentflow-api), `POST /me/hosted-devices`, `GET /me/devices`, `GET /me/devices/:id`, `GET /me/devices/:id/sessions`, `POST /me/devices/:id/dispatch_task`, `/pause`, `/resume`, `/check_update`, `DELETE /me/devices/:id`.
- Env: none new (reuses `af_session` cookie auth via `agentsApi` / `apiPost`).
- Tables: reads `user_devices`, `hosted_devices`, device sessions (unchanged).

## SEAM — full use-case picker
Step 3 ships a minimal `OUTCOMES` list inline so it does NOT depend on the
unmerged `src/data/deviceUseCases.ts` + `DeviceUseCasePicker` (PR #543). The
dispatch payload is byte-for-byte the picker's (`tool:'agent_run_recipe',
scope:{ recipe, params, cron? }`), so swapping `OUTCOMES` for the full
catalog needs no other change to the wizard.

## Failure modes
| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| Local step never advances | (no log — client poll) device never reaches `status:'online'` in `GET /me/devices` | `CabinetDeviceSetup.tsx:520` poll loop |
| Install command shows `— не удалось получить ключ —` | `mintInstallToken` rejects (401 / network) | `CabinetDeviceSetup.tsx:519`; «Обновить ключ» retry |
| Cloud provision soft-fails | `AgentsApiError` 404 from `/me/hosted-devices` | `CabinetDeviceSetup.tsx:778` (shows "сейчас недоступно") |
| First task refused | `dispatch_task` 404 (offline) / 409 (paused) | `CabinetDeviceSetup.tsx:938` |
