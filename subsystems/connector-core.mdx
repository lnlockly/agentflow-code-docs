# connector-core

## TL;DR

`connector-core` is the formal contract that turns `Platform → Account →
EntityKind → Entity → Action` into one interface (`Connector`) plus a registry.
A connector is a thin adapter over the existing MCP tools (tg-mcp, kwork-inbox)
— it never re-implements transport. The Telegram and Kwork connectors are both
registered; the approval queue and the Пульт frontend import `getConnector`
from here, so adding a platform is one `registerConnector(...)` line plus one
connector file, never an `if (platform === …)`.

## Data flow

«напиши Косте, что готово» → confirmed send:

```
Web ─POST /me/accounts/telegram:42/command {text} (SSE)─▶ me-accounts.ts
  command loop (flow model) picks intent {type:'send', payload:{to:'Костя', text}}
  connector.buildAction():
    resolveTarget('Костя') → resolveContact → get_dialogs fuzzy-match → entityId
    Action{ preview:{title,target,body}, dryRun:true }   ← NO send here
  arm() INSERT entity_approval_queue status='armed' ─emit SSE draft {approvalId}─▶ Web
Web renders the action card → Подтвердить
  ─POST /me/approvals/:id/confirm─▶ atomic claim armed→executing
    getConnector('telegram').executeAction() → mcpDirect.callTool('telegram','send_message')
    status→executed, externalId set ─▶ Web flips card to «Отправлено ✓»
```

Entity-browse (live now):

```
Web ─GET /me/accounts/telegram:42/connector/entities?kind=dialogs─▶ me-accounts.ts
  requireSession → resolveConnectorAccount (owner-scope) → browseEntities()
  getConnector('telegram').listEntities() → mcpDirect.callTool('telegram','get_dialogs')
  parseDialogs() → Entity[]   (degrades to [] + degraded:true on a connector throw)
```

## DB / Env / API

- Tables: none owned by connector-core; the approval queue owns
  `entity_approval_queue`. The Telegram connector reads accounts indirectly via
  the `list_accounts` tg-mcp tool; the Kwork connector reads `KWORK_SESSION_JSON`.
- Env: none new. Connectors inherit the MCP transport config from
  `services/mcp-direct.ts`.
- Routes:
  - `GET /me/accounts/:id/connector/entities?kind=&q=&limit=` → `{ ok, entities, degraded?, needsReauth?, reason? }`
  - `GET /me/accounts/:id/connector/entities/:eid/thread?kind=&limit=` → `{ ok, thread, degraded?, needsReauth?, reason? }`
- MCP tools wrapped: `list_accounts`, `get_dialogs`, `get_messages`,
  `send_message` (telegram); `list_dialogs`, `list_wants`, `list_my_kworks`,
  `get_dialog`, `respond_to_want` (kwork-inbox).

## Failure modes

| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| Browse/execute hits an unregistered platform | `connector_not_registered` | `src/connector-core/registry.ts:19` |
| `executeAction` called on a malformed Action | `action_missing_dry_run_flag` | `src/connector-core/connectors/telegram.ts:321` |
| Unknown / unowned account id | `account_not_found` | `src/routes/me-accounts.ts:431` |
| Browse without `kind` | `missing_kind` | `src/routes/me-accounts.ts:429` |
| MCP timeout / tg-mcp down → empty list not a 500 | `degraded: true` | `src/routes/me-accounts.ts:447` |
| Expired/missing session → typed empty instead of a fake «пока пусто» | `needsReauth: true` / `reauth_required` | `src/routes/me-accounts.ts:441` |
| Send resolved no target / empty body | `no_target` / `empty_body` | `src/connector-core/connectors/telegram.ts:325` |
