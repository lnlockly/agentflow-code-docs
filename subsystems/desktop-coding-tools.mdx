# Desktop coding tools + sub-agent spawn

## TL;DR
Adds five IDE-shaped tools (`code_read_file`, `code_write_file`, `code_edit_file`, `code_run_command`, `code_list_dir`) and a `af_spawn_subagent` / `af_get_project_events` pair to the on-Mac daemon. The model can now write code in place when scope is small, or delegate a whole sub-project to the AgentFlow platform when scope is large, with progress streaming back into the cabinet action timeline.

## Data flow

```
Model (Claude) → ToolExecutor.execute(name, args) on agentflow-desktop
   │
   ├─ name in code_read_file/list_dir
   │     └─ tools.code.read_file / list_dir
   │           └─ scope.check_path → returns content/entries
   │
   ├─ name in code_write_file/edit_file
   │     ├─ _announce("code_write_file", "path=...") → update_live → task_action frame
   │     ├─ confirm dialog (osascript) if Scope.confirm_before contains computer.fs.write
   │     └─ tools.code.write_file / edit_file → scope.check_path(write=True) + write text
   │
   ├─ name == code_run_command
   │     ├─ _announce + confirm (shell.exec gate)
   │     └─ tools.code.run_command → check_shell + asyncio subprocess → {stdout, stderr, exit_code, duration_ms}
   │
   └─ name == af_spawn_subagent
         └─ AFClient.spawn_project_task(brief, kind)
               ├─ POST /me/projects  {brief, kind_hint}
               ├─ POST /me/projects/:id/approve  (auto_approve=true)
               └─ poll GET /me/projects/:id/events ≤60s for project_ready/preview_ready
                     └─ returns {project_id, slug, preview_url, status}
   followed by af_get_project_events for ongoing progress streaming.
```

## DB / Env / API
- Tables (consumer only): `projects`, `project_events` (read via `/me/projects/:id/events`).
- Env: none new on the daemon side. AF API base = `https://agentflow.website/_agents`. Auth via `~/.agentflow/auth.json:api_key`.
- Routes consumed:
  - `POST /me/projects` — create from brief (existing).
  - `POST /me/projects/:id/approve` — start build (existing).
  - `GET /me/projects/:id/events?since_id&limit` — paged event tail (existing).
  - `GET /me/projects/:id` — final status snapshot (existing).
- MCP tools added:
  - `computer.code.read_file(path, max_lines)`
  - `computer.code.write_file(path, content, mode)` — gated by `confirm(computer.code.write_file)` reusing the `fs.write` deny-or-allow setting
  - `computer.code.edit_file(path, find, replace, count)` — same gate
  - `computer.code.run_command(command, cwd?, timeout)` — gated by `confirm(computer.code.run_command)` reusing `shell.exec` whitelist + dialog
  - `computer.code.list_dir(path, depth, ignore_globs)`
- LLM tools added: `code_read_file`, `code_write_file`, `code_edit_file`, `code_run_command`, `code_list_dir`, `af_spawn_subagent`, `af_get_project_events`.

## Failure modes
| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| `code_write_file` returns `{"ok": false, "error": "user denied code_write_file"}` | none — synchronous response | user clicked Deny on the native dialog; pass `confirm_before=()` only in test scopes |
| `code_run_command` rejected with `ScopeDenied` | `shell_whitelist is empty; shell.exec disabled` | populate `shell_whitelist` in `~/.agentflow/computer-scope.toml` |
| `code_run_command` rejected with `command not in shell_whitelist` | `command not in shell_whitelist` | add the binary name to `shell_whitelist` |
| `code_edit_file` raises `find pattern appears N times, exceeds count=1` | `exceeds count` | retry with `count='all'` or extend the find string with surrounding context |
| `code_read_file` raises `path denied by hard-coded fallback` | `path denied by hard-coded fallback` | path is under `~/.ssh`, `~/.config`, `~/Library/Keychains`, `~/.aws`, or `~/.gnupg` — never editable |
| `af_spawn_subagent` returns `{"ok": false, "error": "create_failed: 401"}` | none — synchronous response | `~/.agentflow/auth.json:api_key` missing or rotated |
| `af_spawn_subagent` returns ok but `status="pending"` after 60s | none — synchronous response | platform queue back-pressured; call `af_get_project_events` to keep streaming |
| Action frame missing from cabinet timeline for a code_* tool | check that `ToolExecutor(state=state)` was passed at construction | `desktop_cli.py:cmd_run` and `cmd_drive` both pass `state=state` since this PR |

## Screen recording

The same daemon hosts a singleton `ScreenRecorder` that pipes JPEG frames from `streamer.fast_capture_jpeg()` into ffmpeg's stdin and produces a local `.mp4`. Use case: the model finishes a UI task and saves a 30s clip as proof / kwork delivery / demo hand-off. Hard cap on duration so a forgotten `stop()` cannot fill the disk.

### Failure modes
| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| `screen_record_start` returns `{"ok": false, "error": "ffmpeg_not_found"}` | none — synchronous response | install ffmpeg via brew/apt OR install Playwright (`pip install playwright && playwright install chromium`) so the vendored bundle exists |
| Returns `{"ok": false, "error": "scope_blocked_path"}` | `scope_blocked_path` | path is outside allowed roots; pass `~/Movies/...`, `~/tmp/...`, `~/Downloads/...`, or include a `recordings/` segment |
| Returns `{"ok": false, "error": "already_recording"}` | `already_recording` | call `screen_record_stop` before starting a new clip; only one recording per process |
| Auto-stops mid-task | `[screen_record] auto_stop err` (rare) | `max_duration_s` reached — pass a larger value (recorder caps each call individually) |
| ffmpeg starts but file is empty | `[screen_record] capture err` | display backend (Quartz/mss) is failing in headless context — same path as MJPEG stream; check `streamer.fast_capture_jpeg` |
