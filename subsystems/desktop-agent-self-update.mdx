# Desktop daemon self-update

## TL;DR
The frozen `agentflow-desktop.exe` polls `github.com/lnlockly/agentflow-computer-mcp/releases/latest` every 30 minutes (`AF_UPDATE_INTERVAL_MIN`) and self-installs when a newer build appears. Since 2026-05-25 the cabinet `/cabinet/devices/<id>` also exposes a «Проверить обновление» button that triggers the same probe on demand via a `check_update` WS frame and either reports the current version or kicks off the install + restart immediately.

## Data flow

```
Cabinet button click
   │ POST /me/devices/:id/check_update
   ▼
agentflow-agents (me-devices.ts)
   │ decideCheckUpdate → randomUUID() → conn.send({type:'check_update', id})
   │ awaitCheckUpdateResult(id, 25s)
   ▼
WS bridge (devices-ws.ts) ─── ws frame ───►  Desktop daemon (ws_client.py)
                                                  │ _handle_check_update
                                                  │   → asyncio.to_thread(
                                                  │       auto_updater.check_and_apply_once)
                                                  │       → check_now → GitHub
                                                  │           ├── no newer → status='current'
                                                  │           └── newer → download + sha256
                                                  │               ├── Windows → spawn update.bat, sys.exit(0)
                                                  │               └── Unix → os.replace + os.execv (process re-execs)
                                                  ▼
                            ws frame ────────  check_update_result {id, result}
                            (or socket closes silently on Unix re-exec)
                            ──────────►  deliverCheckUpdateResult(id, result)
                                              │ resolves the pending awaiter
                                              ▼
                                        Hono returns 200 + envelope
                                        OR 504 + restarting_inferred:true
                                              ▼
                                        Cabinet toast
```

## DB / Env / API
- **Tables:** none — request is in-memory only (correlation id map in `devices-ws.ts`).
- **Env (daemon):** `AF_UPDATE_INTERVAL_MIN` (0 disables polling loop; default 30). On-demand button bypasses this entirely.
- **Routes:** `POST /me/devices/:id/check_update` → `200 { ok:true, result: CheckUpdateResult }` | `404 not_found` | `409 device_offline` | `502 send_failed` | `504 timeout (restarting_inferred:true)`.
- **WS frames:** `check_update {id}` (server → client), `check_update_result {id, result}` (client → server).
- **Reason codes (stable):** `up_to_date`, `applied`, `platform_unsupported`, `major_bump_refused`, `no_sha256`, `download_failed`, `apply_failed`, `probe_crashed`. Cabinet uses these for toast copy.

## Failure modes
| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| Probe times out at 25s on Unix even though install succeeded | `auto-update: re-executing` | Expected — `os.execv` drops the WS before ack; cabinet treats 504 + `restarting_inferred:true` as success. |
| `reason: download_failed` | `auto-update: probe crashed` or `download failed: TimeoutError` | Daemon → GitHub network blocked. Check `~/.agentflow/` reachability; retry. |
| `reason: no_sha256` | `auto-update: SHA256SUMS unavailable` | Release missing the `SHA256SUMS` asset — upload it to GitHub releases. |
| `reason: platform_unsupported` | `auto-update: running from source, polling disabled` | Daemon running from `pip install -e .`; update via `git pull` instead. |
| `reason: major_bump_refused` | `refusing major bump 0.x.x → 1.0.0` | Cross-major upgrades require a human; bump `MAX_MAJOR` in `auto_updater.py`. |
| Cabinet button greys out forever | `[device] offline … reason=heartbeat_timeout` | Daemon WS dropped; `409 device_offline` returned. Wait for reconnect or restart laptop. |
