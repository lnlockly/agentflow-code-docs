# Cabinet device-live: «Стеклянный кабинет»

## TL;DR

`/cabinet/devices/:id/live` is ONE screen for every user: a verdict line
+ lamp (StatusHero), an approval bell (ApprovalBar), the run feed in plain
language (RunTimeline), the live MJPEG screen as a framed monitor visible
to ALL by default (AgentScreen), and the terminal / files / code tools
tucked behind a collapsible «Под капотом» (UnderTheHood). Phase 1 (PR
landing #574) replaced the binary Простой⇄Профи toggle — and the
chat-only «Простой» from PR #573 — with this single screen + progressive
disclosure. The page root still owns all SSE / dispatch / stream state;
the new pieces are presentation only.

Phase 2 (PR landing #576) makes the live screen театр-grade: a cinematic
focus mode (dim vignette + fixed overlay that also works on iOS), a
click-ripple lifted from the agent's own click rows (ambient cursor when
no coordinates), an address chip + subtitle-narrator synced over the
video, a Watch⇄Drive «Взять управление» that forwards real clicks to
`POST /click` (rendered-image scaling, left + right button) while the page
pauses the agent, and a MediaRecorder session-recording → `.webm`.
Keyboard / scroll input stay Phase 3 (no backend endpoint yet).

## Data flow

```
GET /me/devices/:id            → device (status, paused, scope)
GET /me/devices/:id/tasks/stream (SSE) → action | complete | error
   │                                       │
   ▼                                       ▼
page root: tasks[] buckets (newest first), composerBusy, todayCost
   │
   ▼ deriveVerdict({isOnline, paused, composerBusy, tasks}, t)
   │   offline → error → working → idle   (waiting/🟡 = Phase 2)
   ▼
StatusHero lamp + live line  ‖  RunTimeline (humanised)  ‖  AgentScreen (MJPEG)
                                                  │
                                                  ▼ POST /me/devices/:id/stream
                                                    (pause/resume capture, unchanged)
UnderTheHood ▾ → lazy Terminal (WS /terminal) · FileTree · CodeEditor
```

## DB / Env / API

- Routes (all unchanged, presentation-only PR): `GET /me/devices/:id`,
  `GET /me/devices/:id/tasks/stream` (SSE), `GET /me/devices/:id/live_stream`
  (MJPEG), `POST /me/devices/:id/dispatch_task`, `POST /me/devices/:id/stream`,
  `POST /me/devices/:id/click`, `WS /me/devices/:id/terminal`.
- Env: none added.
- localStorage: `dlive:showFeed:<id>` (capture pause), `dlive:hood:<id>` +
  `dlive:hoodTab:<id>` (Под капотом open state + last tab).
- i18n: `live.hero.*`, `live.act.*`, `live.approve.*`, `live.screen.*`,
  `live.hood.*`, `live.results.*`, `live.idle.*`, `live.feed.title` (ru/en/zh).
- i18n (Phase 2): `live.feed.drive`, `live.feed.drive_on`, `live.feed.drive_hint`,
  `live.feed.drive_return`, `live.feed.record`, `live.feed.record_stop`,
  `live.feed.recording`, `live.feed.record_unsupported`, `live.feed.theater_exit`.

## Failure modes

| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| Live screen never shows a frame (online device) | `live.screen.offline.title` rendered | `agentflow-landing/src/components/cabinet-live/AgentScreen.tsx:56` (bustNow / first-frame timeout) |
| Approval bell never appears | `const pendingApproval` is hardcoded `null` | `agentflow-landing/src/pages/CabinetDeviceLive.tsx:938` — no draft-inbox source yet (Phase 2) |
| Feed shows raw tool names | `humanizeAction` returned de-snaked fallback | `agentflow-landing/src/components/cabinet-live/glassModel.ts:59` (add a keyword) |
| Drive click lands off-target | rendered-img scaling vs remote resolution | `AgentScreen.tsx` `handleMonitorClick` → `renderedImgRect` (letterbox math); clicks on bars are dropped |
| Record button disabled | `recordSupported` false (no MediaRecorder / `canvas.captureStream`) | `AgentScreen.tsx` `pickRecordMime()` / `recordSupported` — button shows `live.feed.record_unsupported` |
| Agent stays paused after Drive | `drivePausedRef` resume call failed | `CabinetDeviceLive.tsx` `handleDriveChange` — fallback is the detail-page Resume button |

## Phase 2 (shipped — PR landing #576)

- Театр focus mode: dim vignette + fixed overlay (CSS-driven so it expands
  on iOS where native fullscreen is a no-op), Esc / exit button to leave.
- Cursor-trail + click-ripple from the agent's own click rows
  (`deriveScreenSignal` → `parseCoords`), ambient «watching» cursor when the
  feed gives no coordinates — no faked positions.
- Address chip (app / url host) + subtitle-narrator (the live feed line)
  floating over the video, synced to the action stream.
- Watch⇄Drive «Взять управление»: clicks forward to `POST /click` with
  rendered-image → 0..1 scaling (left + right button), the page pauses /
  resumes the agent via the device idle toggle, banner «Ты за рулём».
- ⏺ Запись: MediaRecorder over a canvas painting the MJPEG frames →
  downloadable `.webm`; disabled with a hint where the browser lacks it.

## Phase 3–4 backlog

- ApprovalBar data source: an `awaiting_approval` SSE event / draft inbox so
  the bell renders with real pending actions.
- Drive keyboard / scroll / drag: needs a backend `WS /me/devices/:id/input`
  (only `POST /click` exists today), plus a true agent-hold handshake (pause
  prevents new dispatch but does not freeze a running task).
- ⌘K palette, recording DVR scrub + share-to-report, context-follows-action
  panel promotion, mobile push approvals.
