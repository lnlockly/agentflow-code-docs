# Contact Farm

## TL;DR

Per-user "contact farm" feature: a connected Telegram account auto-sends
one referral-link message per day to its contacts. Backend tables and
endpoints shipped 2026-05-15. The daily send worker shipped same day in
**stub mode** — it ticks hourly, writes audit rows to `farm_send_log`,
and bumps `farm_stats.sent_today` / `sent_total`. Real MTProto sending
is still backlog (needs per-user Telethon transport — see Backlog).

The farm's `status` column is the canonical source for the
`farm_activated` funnel stage in [Funnel analytics](/subsystems/funnel-analytics)
and the `farm_activated` state in [Reminders v2](/subsystems/reminders-v2).

## Data flow

```
                  user clicks "Запустить ферму"
                              │
                              ▼
                  POST /me/farm/start  (session auth)
                              │
                              ▼
                  upsert user_farms { user_id, status:'active' }
                  upsert farm_stats { user_id, … defaults }
                              │
                              ▼
                  GET /me/farm/stats  ─► dashboards (FarmPage, ProductsHub
                                          farm card, UserStatsStrip,
                                          ProjectsDashboard FarmBanner)

  hourly farm-send-worker tick (FF_FARM_WORKER, default ON):
    SELECT user_farms.user_id WHERE status='active'
      AND (farm_stats.last_run_at IS NULL OR < NOW() - 23h)
      LIMIT 10
    → for each: buildStubContacts(user_id) → 3..15 ids
    → INSERT farm_send_log (user_id, contact_id, status='stub')
    → UPDATE farm_stats SET sent_today += n, sent_total += n,
                            contacts_count = n, last_run_at = NOW()
  midnight UTC: UPDATE farm_stats SET sent_today = 0

  [BACKLOG]  real Telethon sending (per-user MTProto session)
    Today's worker is stub-only — every audit row has status='stub'.
```

The funnel's `farm_activated` stage in `/admin/funnel-stats` is sourced
directly from `COUNT(*) FROM user_farms WHERE status='active'` (see
`stats.ts:133`), not from the events table — activation is observable
the moment the user clicks start, before any send has fired.

## DB / Env / API

- Tables:
  - `user_farms (id, user_id UNIQUE, status, message_template, send_hour, created_at, updated_at)`
  - `farm_stats (id, user_id UNIQUE, contacts_count, sent_total, sent_today, registrations, flow_earned, last_run_at, updated_at)`
  - `farm_send_log (id, user_id FK→users ON DELETE CASCADE, contact_id, status, sent_at, error)` — audit trail; index `idx_farm_send_log_user_time(user_id, sent_at DESC)`
- Indexes: `user_farms_user_id_idx` UNIQUE, `farm_stats_user_id_idx` UNIQUE
- Status enum (string-typed): `'inactive' | 'active' | 'paused'` for farms; `'sent' | 'failed' | 'stub'` for `farm_send_log.status`
- `send_hour`: UTC hour 0-23 — currently informational; worker ticks hourly and uses 23h cooldown rather than gating on send_hour
- Env: `FF_FARM_WORKER` (set to `0` to disable, default ON), `FF_FARM_TICK_MS` (override interval for tests; default `3_600_000`)
- Routes (all `requireSession`, user_id = session.sub):
  - `GET /me/farm/stats` — returns `{ ok, farm: { status, message_template, send_hour, contacts_count, sent_total, sent_today, registrations, flow_earned, last_run_at } }`
  - `GET /me/farm/contacts` — returns `{ ok, mode: 'stub' | 'real', total, contacts: [{contact_id}], recent: [{id, contact_id, status, sent_at}] }`
  - `POST /me/farm/start`
  - `POST /me/farm/pause`
  - `POST /me/farm/toggle`

## Failure modes

| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| User without any farm record gets a response | `EMPTY_STATS` returned (status='inactive', all zeros) | By design — endpoint never 404s. Frontend renders the connect-TG CTA |
| Farm stage stuck at 0 in admin funnel | n/a | Confirm `user_farms` migration 0064 applied, then check `SELECT count(*) FROM user_farms WHERE status='active'` directly |
| `FarmPage` shows mock data | `MOCK_STATS` constant in `FarmPage.tsx:37` | Frontend still uses mock-on-fetch-failure — verify `/me/farm/stats` reachable from browser |
| `ProductsHub` farm card has no live count | `apiGet<FarmStatsLite>('/me/farm/stats')` in `ProductsHub.tsx:135` returned error | Card hides the metric silently — check auth state, agentsBaseUrl in DevTools |
| User exists but `toggle` does nothing | Toggle path explicitly only flips active↔paused | If status='inactive' (never started), call `/me/farm/start` first |
| Counters not moving despite active status | `farm-send: due farms` log absent | Verify `FF_FARM_WORKER!=0`; check the row has last_run_at older than 23h (or NULL) |
| Audit log full of `status='stub'` | `farm-send tick complete` log has `mode: 'stub'` | By design until real MTProto transport ships — see Backlog |
| `sent_today` doesn't reset at midnight | `farm-send: midnight reset failed` | Inspect DB connectivity; reset retries every tick once the new UTC day arrives |

## Backlog

- **Real MTProto send** — wire `farm-send-worker.processFarm()` to a per-user Telethon transport (today's `tg-scraper` hard-pins user 1's Jarvis pod, so reuse needs generalisation). Once live, swap `status='stub'` → `'sent'` / `'failed'` and drop the `mode: 'stub'` log tag.
- **Contact pool ingestion** — UI for the user to import their contacts list. Today the worker uses a deterministic `buildStubContacts(userId)` generator (3..15 ids per day).
- **Registration credit** — wire `farm_activated` referral signups into `farm_stats.registrations` + `flow_earned`. The funnel already observes the activation event; the credit side is still open.
