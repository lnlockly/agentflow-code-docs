# Contact Farm

## TL;DR

Per-user "contact farm" feature: a connected Telegram account auto-sends
one referral-link message per day to its contacts. Backend tables and
endpoints shipped 2026-05-15. The daily send worker shipped same day in
**stub mode** — it ticks hourly, writes audit rows to `farm_send_log`,
and bumps `farm_stats.sent_today` / `sent_total`. Real MTProto sending
is still backlog (needs per-user Telethon transport — see Backlog).
Per-user "contact farm" feature. Refactored 2026-05-15 to stop duplicating
work: `/me/farm/start` no longer flips a status row and prays a stub worker
does the sending — it now spawns a real `tg_farm` project using the
`tg-cold-mailer` boilerplate. That project drives the canonical workflow
`link_account → import_leads → personalize_template → throttled_send →
log_replies`, running on the user's connected MTProto account via tg-mcp.
The legacy stub worker (`services/farm-send-worker.ts`) is feature-flagged
off; set `FF_FARM_LEGACY_WORKER=1` to re-enable for emergency rollback only.

The farm's `status` column is the canonical source for the
`farm_activated` funnel stage in [Funnel analytics](/subsystems/funnel-analytics)
and the `farm_activated` state in [Reminders v2](/subsystems/reminders-v2).
The linked project id (`user_farms.project_id`) is the deep-link target
from the `/farm` UI into `/projects/:slug`.

## Data flow

```
                  user clicks "Запустить ферму"
                              │
                              ▼
                  POST /me/farm/start  (session auth)
                              │
                              ▼
                  upsert user_farms { user_id, status:'active' }
                  upsert farm_stats { user_id, … defaults }
                              │
                              ▼
                  GET /me/farm/stats  ─► dashboards (FarmPage, ProductsHub
                                          farm card, UserStatsStrip,
                                          ProjectsDashboard FarmBanner)

  hourly farm-send-worker tick (FF_FARM_WORKER, default ON):
    SELECT user_farms.user_id WHERE status='active'
      AND (farm_stats.last_run_at IS NULL OR < NOW() - 23h)
      LIMIT 10
    → for each: buildStubContacts(user_id) → 3..15 ids
    → INSERT farm_send_log (user_id, contact_id, status='stub')
    → UPDATE farm_stats SET sent_today += n, sent_total += n,
                            contacts_count = n, last_run_at = NOW()
  midnight UTC: UPDATE farm_stats SET sent_today = 0

  [BACKLOG]  real Telethon sending (per-user MTProto session)
    Today's worker is stub-only — every audit row has status='stub'.
```

The funnel's `farm_activated` stage in `/admin/funnel-stats` is sourced
directly from `COUNT(*) FROM user_farms WHERE status='active'` (see
`stats.ts:133`), not from the events table — activation is observable
the moment the user clicks start, before any send has fired.
                  ┌─ tg_links row exists for user? ─ no ─► 412 tg_not_connected
                  │ yes
                  ▼
                  findActiveFarmProject(userId)
                    SELECT * FROM projects
                    WHERE owner_user_id=? AND kind='tg_farm'
                      AND status IN (draft, awaiting_approval, approved, running)
                  │
                  ├─ found  ─► reused=true, skip insert
                  ▼
                  spawnFarmProject:
                    - ensurePersonalTeam(userId)
                    - INSERT projects (kind='tg_farm', brief=buildFarmBrief, …)
                    - appendProjectEvent(brief / project_created / maestro_thinking)
                    - runMaestroProposeBackground → propose_project_plan
                  │
                  ▼
                  UPSERT user_farms { user_id, status='active', project_id }
                  INSERT IGNORE farm_stats { user_id }
                  │
                  ▼
                  { ok, reused, project: { id, slug, title, status, kind, preview_url } }

  graph-executor walker on the tg_farm project (after user clicks Approve):
    workflow_schema.nodes from `tg-cold-mailer` boilerplate
    → link_account → import_leads → personalize_template
      → throttled_send → log_replies
    each → typed handler in tg-marketing.ts → coderInvoke('coder-tg-farm')
    runtime workers (Python/Telethon) write farm_send_log rows
```

`GET /me/farm/stats` joins `user_farms` + `farm_stats` + a live
`farm_send_log` aggregate (`sent_total`, `sent_today`, `last_run_at`) so
the dashboard stays accurate even when the worker's stats writes lag.
Also returns the linked project shape so the UI can render
"Открыть проект →".

## DB / Env / API

- Tables:
  - `user_farms (id, user_id UNIQUE, status, message_template, send_hour, created_at, updated_at)`
  - `farm_stats (id, user_id UNIQUE, contacts_count, sent_total, sent_today, registrations, flow_earned, last_run_at, updated_at)`
  - `farm_send_log (id, user_id FK→users ON DELETE CASCADE, contact_id, status, sent_at, error)` — audit trail; index `idx_farm_send_log_user_time(user_id, sent_at DESC)`
- Indexes: `user_farms_user_id_idx` UNIQUE, `farm_stats_user_id_idx` UNIQUE
- Status enum (string-typed): `'inactive' | 'active' | 'paused'` for farms; `'sent' | 'failed' | 'stub'` for `farm_send_log.status`
- `send_hour`: UTC hour 0-23 — currently informational; worker ticks hourly and uses 23h cooldown rather than gating on send_hour
- Env: `FF_FARM_WORKER` (set to `0` to disable, default ON), `FF_FARM_TICK_MS` (override interval for tests; default `3_600_000`)
- Routes (all `requireSession`, user_id = session.sub):
  - `GET /me/farm/stats` — returns `{ ok, farm: { status, message_template, send_hour, contacts_count, sent_total, sent_today, registrations, flow_earned, last_run_at } }`
  - `GET /me/farm/contacts` — returns `{ ok, mode: 'stub' | 'real', total, contacts: [{contact_id}], recent: [{id, contact_id, status, sent_at}] }`
  - `POST /me/farm/start`
  - `POST /me/farm/pause`
  - `POST /me/farm/toggle`
  - `user_farms (id, user_id UNIQUE, status, message_template, send_hour, project_id FK→projects(id) ON DELETE SET NULL, created_at, updated_at)`
  - `farm_stats (id, user_id UNIQUE, contacts_count, sent_total, sent_today, registrations, flow_earned, last_run_at, updated_at)`
  - `farm_send_log (id, user_id FK→users ON DELETE CASCADE, contact_id, status, sent_at, error)` — index `idx_farm_send_log_user_time(user_id, sent_at DESC)`
- Indexes: `user_farms_user_id_idx` UNIQUE, `idx_user_farms_project` (new)
- Status enum: `'inactive' | 'active' | 'paused'` for farms; `'sent' | 'failed' | 'stub'` for `farm_send_log.status`
- Env:
  - `FF_FARM_LEGACY_WORKER` — opt-in flag (`=1`) to re-enable the deprecated stub worker; default OFF
  - `FF_FARM_WORKER` — legacy gate (only checked when `FF_FARM_LEGACY_WORKER=1`)
  - `FF_FARM_TICK_MS` — override interval when running the legacy worker
- Routes (all `requireSession`, user_id = session.sub):
  - `GET /me/farm/stats` → `{ ok, farm: { …status, counters, last_run_at, project_id, project } }`
  - `GET /me/farm/contacts` → `{ ok, mode: 'stub' | 'real', total, contacts, recent }`
  - `POST /me/farm/start` → `{ ok, reused, project }` or `412 tg_not_connected` / `500 project_spawn_failed`
  - `POST /me/farm/pause` → stats payload
  - `POST /me/farm/toggle` → stats payload OR `{ ok, reused, project }` when activating

## Brief routing (kind=tg_farm)

Three boilerplates share `kind=tg_farm`. Before PR
`fix/tg-farm-broadcast-routing-2026-05-18` the picker did `LIMIT 1`
ordered by row id, so every tg_farm brief got the diploma funnel — the
broadcast/list-of-chats brief on project 996 never saw the cold-mailer's
`import_leads` / `throttled_send` nodes. See
`qa-issues/2026-05-18-tg-farm-broadcast-ui-missing.md`.

`pickTgFarmSchema` now loads every tg_farm row, runs
`classifyTgFarmBriefIntent(brief)` against the brief, and picks:

| Brief signal | Boilerplate | Reason emitted |
|---|---|---|
| `broadcast`, `рассылка`, `список чатов`, `cold-mail(ing/er)`, `mass send`, `bulk dm`, `csv import`, `lead list`, `разослать` | `tg-cold-mailer` | `tg_farm_broadcast_route` |
| `ai-shill(er)`, `keyword monitor`, `chat watcher`, `шиллинг`, `отвечать в чатах по ключевым словам`, `мониторинг чатов по ключевым` | `tg-ai-shiller` | `tg_farm_shill_route` |
| neither (bare `ферма`, generic outreach, etc.) | `diploma-outreach-build` | `tg_farm_funnel_default` |
| no recognised name in DB (drift) | first row by insertion order | `matched` |

The reasons are emitted as `log` `project_events.payload.msg` at fast-path
time (`[fast-path] kind=tg_farm skipped maestro propose — reason=…`) so
ops can grep prod logs and confirm a project ran the right schema.

## Anti-spam rails

Enforced inside the `throttled_send` handler scaffold (see
`graph-executor/handlers/tg-marketing.ts:113`):

- 30–90s uniform jitter between sends
- Daily cap (`DAILY_DM_CAP` env, default 30) — UI / FarmPage talks about 5/day,
  but the runtime ceiling is wider so warmed accounts can ramp up. The
  conservative 5/day visible in the legacy stub remains a guideline for
  first-day onboarding; the runtime worker should honour `DAILY_DM_CAP`
  from project secrets.
- 5–15 min pause after every 10 sends
- 30-day no-repeat per peer (handled in `db/leads.sqlite` by the runtime)
- Message body MUST include the disclaimer
  `(это разовое сообщение, отвечать не обязательно)` — baked into
  `buildFarmBrief` so Maestro forwards the rule to the coder.

## Failure modes

| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| User without any farm record gets a response | `EMPTY_STATS` returned (status='inactive', all zeros) | By design — endpoint never 404s. Frontend renders the connect-TG CTA |
| Farm stage stuck at 0 in admin funnel | n/a | Confirm `user_farms` migration 0064 applied, then check `SELECT count(*) FROM user_farms WHERE status='active'` directly |
| `FarmPage` shows mock data | `MOCK_STATS` constant in `FarmPage.tsx:37` | Frontend still uses mock-on-fetch-failure — verify `/me/farm/stats` reachable from browser |
| `ProductsHub` farm card has no live count | `apiGet<FarmStatsLite>('/me/farm/stats')` in `ProductsHub.tsx:135` returned error | Card hides the metric silently — check auth state, agentsBaseUrl in DevTools |
| User exists but `toggle` does nothing | Toggle path explicitly only flips active↔paused | If status='inactive' (never started), call `/me/farm/start` first |
| Counters not moving despite active status | `farm-send: due farms` log absent | Verify `FF_FARM_WORKER!=0`; check the row has last_run_at older than 23h (or NULL) |
| Audit log full of `status='stub'` | `farm-send tick complete` log has `mode: 'stub'` | By design until real MTProto transport ships — see Backlog |
| `sent_today` doesn't reset at midnight | `farm-send: midnight reset failed` | Inspect DB connectivity; reset retries every tick once the new UTC day arrives |
