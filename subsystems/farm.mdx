# Contact Farm

## TL;DR

Per-user "contact farm" feature. Refactored 2026-05-15 to stop duplicating
work: `/me/farm/start` no longer flips a status row and prays a stub worker
does the sending — it now spawns a real `tg_farm` project using the
`tg-cold-mailer` boilerplate. That project drives the canonical workflow
`link_account → import_leads → personalize_template → throttled_send →
log_replies`, running on the user's connected MTProto account via tg-mcp.
The legacy stub worker (`services/farm-send-worker.ts`) is feature-flagged
off; set `FF_FARM_LEGACY_WORKER=1` to re-enable for emergency rollback only.

The farm's `status` column is the canonical source for the
`farm_activated` funnel stage in [Funnel analytics](/subsystems/funnel-analytics)
and the `farm_activated` state in [Reminders v2](/subsystems/reminders-v2).
The linked project id (`user_farms.project_id`) is the deep-link target
from the `/farm` UI into `/projects/:slug`.

## Data flow

```
                  user clicks "Запустить ферму"
                              │
                              ▼
                  POST /me/farm/start  (session auth)
                              │
                              ▼
                  ┌─ tg_links row exists for user? ─ no ─► 412 tg_not_connected
                  │ yes
                  ▼
                  findActiveFarmProject(userId)
                    SELECT * FROM projects
                    WHERE owner_user_id=? AND kind='tg_farm'
                      AND status IN (draft, awaiting_approval, approved, running)
                  │
                  ├─ found  ─► reused=true, skip insert
                  ▼
                  spawnFarmProject:
                    - ensurePersonalTeam(userId)
                    - INSERT projects (kind='tg_farm', brief=buildFarmBrief, …)
                    - appendProjectEvent(brief / project_created / maestro_thinking)
                    - runMaestroProposeBackground → propose_project_plan
                  │
                  ▼
                  UPSERT user_farms { user_id, status='active', project_id }
                  INSERT IGNORE farm_stats { user_id }
                  │
                  ▼
                  { ok, reused, project: { id, slug, title, status, kind, preview_url } }

  graph-executor walker on the tg_farm project (after user clicks Approve):
    workflow_schema.nodes from `tg-cold-mailer` boilerplate
    → link_account → import_leads → personalize_template
      → throttled_send → log_replies
    each → typed handler in tg-marketing.ts → coderInvoke('coder-tg-farm')
    runtime workers (Python/Telethon) write farm_send_log rows
```

`GET /me/farm/stats` joins `user_farms` + `farm_stats` + a live
`farm_send_log` aggregate (`sent_total`, `sent_today`, `last_run_at`) so
the dashboard stays accurate even when the worker's stats writes lag.
Also returns the linked project shape so the UI can render
"Открыть проект →".

## DB / Env / API

- Tables:
  - `user_farms (id, user_id UNIQUE, status, message_template, send_hour, project_id FK→projects(id) ON DELETE SET NULL, created_at, updated_at)`
  - `farm_stats (id, user_id UNIQUE, contacts_count, sent_total, sent_today, registrations, flow_earned, last_run_at, updated_at)`
  - `farm_send_log (id, user_id FK→users ON DELETE CASCADE, contact_id, status, sent_at, error)` — index `idx_farm_send_log_user_time(user_id, sent_at DESC)`
- Indexes: `user_farms_user_id_idx` UNIQUE, `idx_user_farms_project` (new)
- Status enum: `'inactive' | 'active' | 'paused'` for farms; `'sent' | 'failed' | 'stub'` for `farm_send_log.status`
- Env:
  - `FF_FARM_LEGACY_WORKER` — opt-in flag (`=1`) to re-enable the deprecated stub worker; default OFF
  - `FF_FARM_WORKER` — legacy gate (only checked when `FF_FARM_LEGACY_WORKER=1`)
  - `FF_FARM_TICK_MS` — override interval when running the legacy worker
- Routes (all `requireSession`, user_id = session.sub):
  - `GET /me/farm/stats` → `{ ok, farm: { …status, counters, last_run_at, project_id, project } }`
  - `GET /me/farm/contacts` → `{ ok, mode: 'stub' | 'real', total, contacts, recent }`
  - `POST /me/farm/start` → `{ ok, reused, project }` or `412 tg_not_connected` / `500 project_spawn_failed`
  - `POST /me/farm/pause` → stats payload
  - `POST /me/farm/toggle` → stats payload OR `{ ok, reused, project }` when activating

## Anti-spam rails

Enforced inside the `throttled_send` handler scaffold (see
`graph-executor/handlers/tg-marketing.ts:113`):

- 30–90s uniform jitter between sends
- Daily cap (`DAILY_DM_CAP` env, default 30) — UI / FarmPage talks about 5/day,
  but the runtime ceiling is wider so warmed accounts can ramp up. The
  conservative 5/day visible in the legacy stub remains a guideline for
  first-day onboarding; the runtime worker should honour `DAILY_DM_CAP`
  from project secrets.
- 5–15 min pause after every 10 sends
- 30-day no-repeat per peer (handled in `db/leads.sqlite` by the runtime)
- Message body MUST include the disclaimer
  `(это разовое сообщение, отвечать не обязательно)` — baked into
  `buildFarmBrief` so Maestro forwards the rule to the coder.

## Failure modes

| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| `/me/farm/start` returns `412 tg_not_connected` | n/a (handled at handler level) | User hasn't run TG kickstart flow — show /account/settings link |
| `/me/farm/start` returns `500 project_spawn_failed` | `slug_collision` or `db_insert_failed` | Inspect Postgres connection + rerun; spawn is idempotent on the user_id side via `findActiveFarmProject` |
| Multiple tg_farm projects per user | n/a | `findActiveFarmProject` filter is by status set; failed/cancelled rows are ignored intentionally so the user can restart after a bad run |
| FarmPage stuck on mock | `MOCK_STATS` fallback in `FarmPage.tsx:37` | `/me/farm/stats` 401/500 — check auth + agentsBaseUrl |
| Counters not moving | `farm_send_log` rows never insert | Inspect the tg_farm project's plan_tasks + project_events — the runtime worker writes the rows. `coder-tg-farm` slug must be alive |
| Legacy stub still running | `farm-send: due farms` after deploy | `FF_FARM_LEGACY_WORKER` env was set to `1` somewhere — unset it |
| Worker booted in production by accident | `farm-send worker started` | Same — should print `FF_FARM_LEGACY_WORKER!=1 — legacy farm-send worker disabled` instead |
| User sees "Открыть проект" but link 404s | `user_farms.project_id` points to a deleted row | The FK is `ON DELETE SET NULL`; project deletion should null it. Next /me/farm/start spawns a new one |

## Backlog

- **Pause underlying project workflow** — `/me/farm/pause` flips
  `user_farms.status` only. Should also pause the linked project's
  scheduled workflow ticks (no canonical pause primitive on
  `projects` today; `status='paused'` isn't in the enum).
- **Promote tg_farm to first-class flag in UI** — once the workflow is
  visible inside the project workspace, drop the standalone FarmPage and
  link `/farm` directly into `/projects/:slug`.
- **Per-user daily cap override** — expose `farm.daily_cap` in
  project_secrets so the runtime reads it instead of the env default.
