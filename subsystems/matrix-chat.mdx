# Matrix Chat

> **Status: planned 2026-05-21** — spec и plan написаны, Phase 1 (Dendrite deploy) в работе. Эта страница обновляется по мере реализации.

## TL;DR

Self-hosted Dendrite homeserver на k3s + кастомный React UI поверх `matrix-js-sdk`. Юзер логинится в AgentFlow обычным способом, при заходе на `/chat` фронт получает Matrix access_token через bridge endpoint (`agentflow-agents POST /me/chat/token`), который auto-provision'ит Matrix-юзера через shared-secret registration с deterministic-password derivation. Федерация и E2EE отключены в MVP. Mobile-клиент и Telegram bridge — следующие фазы.

## Data flow

```
Browser /chat
   │
   ├──[1]──> agentflow.website POST /me/chat/token  (AF JWT cookie)
   │           │
   │           ├── verify AF session (existing middleware)
   │           ├── compute internal_password = HMAC(MATRIX_AUTH_KEY, af_id)
   │           ├── try /login → 200 (existing user) or 403 (new)
   │           ├── if 403: shared-secret register → get access_token in response
   │           └── return { homeserver, user_id, access_token, device_id }
   │
   ├──[2]──> matrix-js-sdk initialized with token
   │
   ├──[3]──> matrix.agentflow.website/_matrix/client/v3/sync (long-poll)
   │
   └──[4]──> matrix.agentflow.website/_matrix/client/v3/rooms/{id}/send/m.room.message
              │
              └── Dendrite → Postgres → fanout to other connected /sync clients
```

## DB / Env / API

### Postgres
- DB: `dendrite` (рядом с `agentflow` в `agentflow-postgres-97fb67469-69298`)
- User: `dendrite` (отдельный, чтобы limit blast radius)
- Dendrite авто-создаёт ~20 таблиц при первом старте (`account_accounts`, `roomserver_*`, `syncapi_*`, и т.д.)

### Media storage
- Local PVC `dendrite-media` 50Gi (Dendrite не имеет S3 backend; миграция на MinIO — открытый item)

### Env (agentflow-agents)
- `MATRIX_HOMESERVER_URL` — internal cluster URL, обычно `http://dendrite:8008`
- `MATRIX_PUBLIC_URL` — `https://matrix.agentflow.website` (отдаётся фронту)
- `MATRIX_AUTH_KEY` — HMAC key для deterministic-password derivation (никогда не покидает agentflow-agents)
- `MATRIX_REGISTRATION_SHARED_SECRET` — shared с Dendrite ConfigMap, для `/_synapse/admin/v1/register`
- `MATRIX_SERVER_NAME` — `agentflow.website` (не `matrix.agentflow.website` — server_name по Matrix спеке)

### Dendrite config (ConfigMap)
- `global.server_name: agentflow.website`
- `global.disable_federation: true`
- `global.database.connection_string` — postgres URL
- `client_api.registration_disabled: true` (public reg off)
- `client_api.registration_shared_secret` — same as `MATRIX_REGISTRATION_SHARED_SECRET`
- `media_api.*` — MinIO S3 backend creds

### Routes (новые на agentflow-agents)
- `POST /me/chat/token` — issue Matrix access_token (auto-provision на первом вызове)
- `POST /me/chat/rooms` *(phase 3+)* — create room with current user as admin
- `POST /me/chat/invite` *(phase 3+)* — invite by AF user_id

### Matrix endpoints (наружу)
- `https://matrix.agentflow.website/_matrix/client/v3/*` — standard Matrix Client-Server API
- `https://matrix.agentflow.website/_matrix/media/v3/upload?filename=<...>` — binary upload, `Content-Type: <mime>` + raw body, returns `{ content_uri: "mxc://agentflow.website/<id>" }`
- `https://matrix.agentflow.website/_matrix/client/v1/media/download/agentflow.website/<id>` — authenticated full-size fetch (v1.11+ requires `Authorization` header or `access_token` query)
- `https://matrix.agentflow.website/_matrix/client/v1/media/thumbnail/agentflow.website/<id>?width=&height=&method=scale` — authenticated server-rendered thumbnail
- `https://agentflow.website/.well-known/matrix/server` — server discovery
- `https://agentflow.website/.well-known/matrix/client` — client discovery

### Attachment flow (m.image / m.file)
1. Browser `POST /_matrix/media/v3/upload` with file body → `mxc://...`.
2. Browser `PUT /_matrix/client/v3/rooms/{id}/send/m.room.message/{txn}` with `{ msgtype: "m.image" | "m.file", body: <filename>, url: <mxc>, info: { mimetype, size, w?, h? } }`.
3. Other clients see the event via /sync; `agentflow-landing/src/chat/matrixApi.ts#parseSync` builds `MatrixAttachment` with `thumbnailUrl` + `downloadUrl` already auth-stamped.
4. `<img src={thumbnailUrl}>` works because `mxcToHttp` embeds `access_token` as query param (browsers can't attach Authorization to plain img tags).

## Failure modes

| Симптом | Лог-строка для grep | Где починить |
|---|---|---|
| Юзер не может залогиниться в чат | `[chat-bridge] login failed after register` | `MATRIX_AUTH_KEY` ротировался — нужен fallback через `/_dendrite/admin/resetPassword/` |
| Registration возвращает 401 invalid_mac | `[chat-bridge] register mac mismatch` | `MATRIX_REGISTRATION_SHARED_SECRET` env != `registration_shared_secret` в Dendrite ConfigMap |
| Сообщения не сохраняются | `pq: connection refused` в Dendrite logs | Postgres connectivity, проверить `dendrite` user creds + NetworkPolicy |
| Media upload 413 | `nginx 413 Request Entity Too Large` | Ingress `proxy-body-size` поднять до 50m для `matrix.agentflow.website` |
| `/sync` отрубается через 30c | `sync request closed` в browser console | Ingress timeout — поднять до 60s для `/_matrix/client/v3/sync` |
| `.well-known/matrix/server` 404 | `404 GET /.well-known/matrix/server` в landing logs | `agentflow-landing/public/.well-known/matrix/` не задеплоен или Vite plugin не копирует |
| User auto-provision 409 conflict | `M_USER_IN_USE` в bridge logs | Race condition при первом одновременном логине — добавить retry на GET после 409 |
| Voice/video не работает | `WebRTC: no ICE candidates` | Phase 2+, TURN не настроен (coturn out of scope MVP) |
| Image preview blank, dev tools показывают 401 | `401 M_MISSING_TOKEN` на `/media/thumbnail/...` | `mxcToHttp` должен добавлять `access_token` query (Authorization header нельзя на `<img>`) — Dendrite v1.11+ media auth обязателен |
| Upload падает 413 на >50 MiB | `413 Request Entity Too Large` в browser console | Composer cap = 50 MiB, совпадает с ingress `proxy-body-size`. Поднять оба, если меняем cap |

## Non-goals (MVP)

- Federation (включается флагом, но требует модерации и DDoS-защиты)
- E2EE (Olm/Megolm, device verification — отдельная фаза 4)
- Voice/video calls (требует TURN-сервера)
- Mobile apps (phase 6, отдельный repo)
- Telegram/Discord/WhatsApp bridges (phase 5, `mautrix-*`)
- Spaces hierarchies
