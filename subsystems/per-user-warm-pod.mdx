# Per-user warm pod (POC)

## TL;DR

For `owner_user_id ∈ PERUSER_POD_ENABLED_USER_IDS` (POC: `"1"`, i.e. avsee4)
the platform skips per-project StatefulSet provisioning. Projects become
subdirectories of `/workspace/<slug>` inside a single always-running
`user-workspace-1` Deployment in namespace `af-tenant-1`. Tooling
(node 22, python 3.12, git, pnpm) and the three baked boilerplates are
already on disk in the image, so `create_project` is `mkdir + cp -r` —
sub-second. The same pod's Caddy sidecar serves
`p-<slug>.proj.agentflow.website` from `/workspace/<slug>/dist/`.

## Data flow

```
user approves project (kind=landing, owner_user_id=1)
  → runProjectApprovalBackground
    → provisionWorkspaceWithRetry
      → callCodeExecTool('create_project', { name=<slug>, ownerUserId=1 })

PR-2 branch: ownerUserId ∈ PERUSER_POD_ENABLED_USER_IDS
  → skip claimWarmPod / skip kubectl apply StatefulSet
  → kubectl exec -n af-tenant-1 deploy/user-workspace-1 -c tools \
        -- sh -c 'mkdir -p /workspace/<slug> && cp -a /opt/agentflow/boilerplates/landing/. /workspace/<slug>/'
  → DB: update projects row → host_pod_name='user-workspace-1', workspace_path='/workspace/<slug>'
  → return { ok, project, pod: 'user-workspace-1', workspace: '/workspace/<slug>' }

coder writes files:
  → callCodeExecTool('write_file', { workspace_project_name=<slug>, path='src/App.tsx', content=... })
  → PR-3 routes via host_pod_name → kubectl exec user-workspace-1 -c tools -- tee /workspace/<slug>/src/App.tsx

build:
  → callCodeExecTool('exec', { workspace_project_name=<slug>, cmd='pnpm install && pnpm build' })
  → kubectl exec user-workspace-1 -- sh -c 'cd /workspace/<slug> && pnpm install && pnpm build'

preview:
  → expose_public is a no-op for per-user-pod projects — the wildcard Ingress
    user-workspace-1-preview already routes p-<slug>.proj.agentflow.website
    to user-workspace-1:8080. Caddy reads Host header, serves
    /workspace/<slug>/dist/ (or /workspace/<slug>/ if no dist).
```

## DB / Env / API

- **Tables:** `projects` gains a (logical) `host_pod_name` column in PR-2.
  Until PR-2 lands, only the manifest exists and no projects are routed
  through it.
- **Env (agentflow-agents Deployment):**
  - `PERUSER_POD_ENABLED_USER_IDS` — comma-separated user IDs that use the
    fast path. Empty / unset → everyone keeps the existing per-project STS
    pipeline. POC: `"1"`.
  - `PERUSER_POD_USE_SUDO` — set to `"1"` to wrap exec/write helpers with
    `sudo -n -u proj-<slug>`. Default is **off**: the current `tools`
    container ships no `sudo` binary and no `proj-<slug>` users (see
    failure mode below). `validateProjectPath` is the only enforced
    security boundary in the no-sudo mode, which is acceptable for the
    single-user-per-pod POC. Flip on once the manifest bumps to a
    sudo-capable tools image.
- **K8s (host k3s, after PR-1 manifest applied):**
  - Namespace `af-tenant-1` (existing vcluster for user 1).
  - PVC `user-workspace-1` (20 Gi RWO).
  - Deployment `user-workspace-1` (1 replica, recreate strategy).
  - Service `user-workspace-1` (ClusterIP, :8080).
  - Ingress `user-workspace-1-preview` in `franchise-factory` ns —
    `*.proj.agentflow.website` → `user-workspace-1:8080`, wildcard cert
    `wildcard-proj-agentflow-tls`.
- **MCP tools:** unchanged surface. `create_project` /
  `destroy_project` / `write_file` / `exec` etc. all continue to take
  `workspace_project_name`; the routing change in PR-2/PR-3 is invisible
  to callers.

## Failure modes

| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| `kubectl apply -f user-workspace.yaml` returns `Service "user-workspace-1" not found` from the Ingress | (none — apply order) | Apply PVC + Deployment + Service first, Ingress last. Or `kubectl apply` the whole file twice. |
| Caddy preview returns 404 on `p-<slug>.proj.agentflow.website` | (Caddy stdout shows `no such file or directory: /workspace/<slug>`) | `code-exec.create_project` (PR-2) didn't mkdir the slug. Check `kubectl exec deploy/user-workspace-1 -c tools -- ls /workspace`. |
| Caddy serves stale build after `pnpm build` | (none — `Cache-Control: no-cache` set, but client cache may still serve) | Force-refresh in browser. If persists: check `/workspace/<slug>/dist/index.html` mtime via `kubectl exec`. |
| User 1 PVC fills (>90%) | `df -h` on the pod | Bump PVC to 50 Gi or wire an LRU eviction job for idle project subdirs. |
| Pod restart loses in-flight project state | Pod restart event | Recreate strategy is intentional — projects re-clone from git remote on next coder turn. For long-running builds, snapshot state before any planned restart. |
| Ingress wildcard routing collides with existing per-project ingresses | nginx-ingress reload warning about duplicate host | Per-project Ingresses (`ensurePreviewIngressPlaceholder`) target the same wildcard host pattern. With ingress class `nginx` the most-specific Ingress wins; if a per-project Ingress for `p-<slug>.proj.agentflow.website` exists it'll mask the wildcard. PR-2 must skip `ensurePreviewIngressPlaceholder` for per-user-pod projects. |
| Tool returns `unknown_project` for a fresh peruser-pod project | `[code-exec] assertWorkspaceExists` miss; `test -d` exit 1 | Check `kubectl -n af-tenant-1 exec deploy/user-workspace-1 -c tools -- ls /workspace`. If slug dir missing, rerun `create_project`. |
| Tool returns `{ok:false, error:'path_outside_workspace'}` | (handler-side, never hits kubectl) | Coder passed a `cwd` / `path` outside `/workspace/<slug>/`. Fix the coder prompt — never widen the gate. Note: `exec` / `start_service` tool handlers no longer default `cwd` to `/workspace` on the peruser branch (PR #533) — they pass `undefined` so `buildSudoWrapper` resolves it to `/workspace/<slug>`. Graph handlers must also avoid hardcoded `cd /workspace` / `/workspace/src/...` paths; use cwd-relative paths. |
| Clone / pnpm install fails with `Could not resolve host: github.com` / `registry.npmjs.org` | `fatal: unable to access 'https://...': Could not resolve host` in `project_events.payload.error` | vcluster `user-workspace-1` resolv.conf points at the in-cluster CoreDNS (`10.43.8.150`), which only resolves cluster-internal names. External DNS needs forwarder rules in the vcluster's CoreDNS Corefile (forward to `1.1.1.1` / `8.8.8.8`) or pod-level `dnsPolicy: Default`. See agentflow-agents/k8s/user-workspace.yaml. |
| `landing_scaffold_finalize_failed: exit=133 ... Trace/breakpoint trap (core dumped)` | `Trace/breakpoint trap` in scaffold finalize stderr | Node process exceeded `prlimit --as=512M` virtual-memory cap from `wrapResourceLimited`. Bump the limit in `wrapResourceLimited` defaults or pass `limits.memoryMax: '1G'` from the scaffold callsite. Visible only on peruser branch where prlimit is wrapped around every exec. |
| Every peruser write/exec returns `sudo: command not found` (exit 127) | `sudo: command not found` in `project_events.payload.stderr` | The tools image (reused `agentflow-project`) ships neither `sudo` nor the `proj-<slug>` users — create_project's script skips useradd/chown when not root. Default `PERUSER_POD_USE_SUDO=0` (unset) bypasses the sudo wrap entirely; flip to `"1"` only after bumping the user-workspace manifest to a tools image with sudo + sudoers + provisioned users. `validateProjectPath` remains the enforced gate in either mode. |
| `kubectl exec` to `user-workspace-1` errors with `pods "user-workspace-1" not found` | `pods "user-workspace-1" not found` | Use the `deployment/user-workspace-1` target (already done by the wrappers). Pod name carries a ReplicaSet hash suffix; never address the bare pod name. |
| `get_logs` returns `{logs_unavailable: true}` for a peruser project | `mode: 'peruser_pod'` in tool response | Expected: shared-pod stdout is meaningless. Use `list_services` to enumerate and `exec` to tail the service log under `/workspace/<slug>/.services/<name>.log`. |

## Operational commands

```bash
# Apply the manifest (POC: from your workstation, against host k3s)
ssh ff-france "kubectl apply -f -" < agentflow-agents/k8s/user-workspace.yaml

# Verify pod up
ssh ff-france "kubectl -n af-tenant-1 get deploy user-workspace-1"

# Smoke-test caddy fallback
curl -I https://p-smoketest.proj.agentflow.website/

# Test the tools container
ssh ff-france "kubectl -n af-tenant-1 exec deploy/user-workspace-1 -c tools -- \
    sh -c 'which node python3 git pnpm && ls /opt/agentflow/boilerplates/'"

# Rollback (the per-project STS pipeline is unchanged, so this is non-destructive
# until PR-2 ships and starts routing user 1 traffic here)
ssh ff-france "kubectl delete -f -" < agentflow-agents/k8s/user-workspace.yaml
```

## Verification (real, not surface signals)

Per `feedback_real_verification_or_silence.md`, "verified" requires
rendered DOM containing brief-derived content. After PR-2 + PR-3 deploy:

1. Create a new landing project as user 1 via `POST /me/projects` (e.g. brief
   "Лендинг для онлайн-курса йоги, оранжевый, секции about/программа/цена").
2. Measure `created_at` → `status='done'`. Target < 3 min.
3. Open `https://p-<slug>.proj.agentflow.website/` via Playwright MCP,
   screenshot, grep rendered DOM for brief-derived strings ("йог" / "програм"
   / "Записаться"). DOM-presence is the gate, not 200 + bundle size.
