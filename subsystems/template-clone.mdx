# Template clone

> **Status: Backend SHIPPED in agentflow-agents PR #387 (Lanes A + B + D). MCP source staged in `mcp-tools-staging/` awaiting sibling PR in `agentflow-mcp-server`. Frontend (Lane C) and the per-route logger redaction (Lane A6) follow-up.**

## TL;DR

Every AgentFlow template (Kwork operator, TG poster, sales funnel, future verticals) ships as one `presets/<slug>.json` file with a top-level `inputs[]` schema. The landing renders a generic `<GraphInputForm>` from that schema. `POST /me/templates/:slug/clone` validates the submission against the schema, seals secret-typed values into `project_secrets`, creates the project row, and kicks the graph. The same path is exposed via MCP `clone_template`. Adding a new vertical means shipping one JSON — no new routes, no new pages, no new components.

## Data flow

```
/templates  →  /templates/:slug  →  <GraphInputForm schema={preset.inputs}>
                                          │
                                          │ submit values
                                          ▼
                        POST /me/templates/:slug/clone
                                          │
                       ┌──────────────────┼──────────────────┐
                       ▼                  ▼                  ▼
                getPreset(slug)   validate(values, inputs)   requireSession
                       │                  │
                       │       ┌──────────┴──────────┐
                       │       │ type-switch:        │
                       │       │ text/url/number/    │
                       │       │ bool/secret/        │
                       │       │ secret_json/select  │
                       │       └──────────┬──────────┘
                       │                  │
                       ▼                  ▼
              createProjectFromPreset(userId, slug, title)
                       │
                       ▼
              for each input:
                INSERT project_secrets {
                  key=name,
                  source='owner',
                  is_set=true,
                  value_encrypted = sealProjectSecretValue(stringified),
                  masked = mask(value)
                }
                       │
                       ▼
              INSERT project_events kind='cloned_from_template'
                       │
                       ▼
              project-lifecycle worker picks up the row,
              reads project_secrets, starts the graph

  MCP path: clone_template(slug, title?, inputs)
        └→ client.fetch('POST /me/templates/:slug/clone')  (same handler)
```

## DB / Env / API

- Tables:
  - `project_secrets` (`agentflow-agents/src/db/schema.ts:1226`) — one row per declared input. `value_encrypted` always populated (we seal at rest even for non-secret types, no per-key scope leakage).
  - `projects`, `project_events` (`kind='cloned_from_template'`, payload `{ template_slug, input_names_set }`).
- Routes:
  - `GET /me/templates` — list with full `inputs` schema per preset.
  - `POST /me/templates/:slug/clone` — body `{ title?, inputs: Record<string, unknown> }`, response `{ ok, project: { id, slug, status } }`.
- MCP tools (via `agentflow-mcp-server`):
  - `list_templates` — `{ slug, name, description, category, inputs }[]`.
  - `clone_template` — `{ slug, title?, inputs }` → `{ project_id, slug, status, preview_url }`.
- Env: none new. `SECRET_SEAL_KEY` (already required by `services/seal.ts`) covers `value_encrypted`.
- Limits: `secret_json` and `secret` ≤ 8 KB; `text` ≤ 1 KB; `file` (base64 fallback) ≤ 5 MB raw.

## Failure modes

| Symptom | Log / response signature for grep | Where to fix |
|---|---|---|
| Submit fails with 400, response `{ error: 'bad_input', name, detail }` | response body contains `"error":"bad_input"` | Type mismatch (e.g. `number` got a string, `url` failed `validatePublicHttpUrl`, regex unmatched). Inspect `name` + `detail` and fix the value. Code: `services/template-input-validator.ts:validateOne`. |
| Submit fails with 400, `error: 'missing_required'` | response body contains `"error":"missing_required"` | Required input absent and no `default`. Form should block this client-side — if the LLM/MCP path triggers, fill the input and retry. Code: `services/template-input-validator.ts:validateInputs` step 2a. |
| `secret_json` rejected with 400 `invalid_secret_json` | response body contains `"error":"invalid_secret_json"` | Server `JSON.parse` failed. Strip stray quotes / trailing commas from the pasted blob. Code: `services/template-input-validator.ts` `secret_json` branch. |
| 400 `error: 'unknown_input'` | response body contains `"error":"unknown_input"` | Caller sent a key not declared in `preset.inputs[]`. Common when an old form still posts a removed input. Reload `list_templates` / `/me/templates`. |
| 404 on `POST /me/templates/:slug/clone` | response body `{ error: 'unknown_template', detail: slug }` | Preset slug not seeded. Run preset re-seed or check `presets/<slug>.json` exists and `agent_presets` row was inserted. Code: `routes/me-templates.ts` `getPreset` null branch. |
| Two clones, same template, same title race | response body `{ idempotent: true, project }` | Working as intended — idempotent on `(owner, template_slug, title)` within 60 s. Code: `routes/me-templates.ts` `INTERVAL '60 seconds'` block. |
| Plaintext value visible in logs | `inputs` field present in request-log dump | Logger middleware must strip `inputs` from request bodies on `/clone` routes. **Lane A6 follow-up — not in PR #387.** |
| Owner submitted form but graph never starts | `project_secrets` row missing for declared input | Clone wrote `projects` but seal failed for one secret. Response would be `{ error: 'seal_failed', name }` — check `AGENTS_MASTER_KEY` env. Code: `routes/me-templates.ts` `sealString` try/catch. |
