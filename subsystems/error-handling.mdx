# Error handling

## TL;DR

Every backend route returns the same JSON envelope on error: `{ ok: false, error: '<code>', message: '<RU>', detail?: '<safe>', ...extras }`. The frontend `ErrorBoundary` catches render crashes, ships a fire-and-forget report to `POST /me/client-errors`, and shows a friendly retry card. A `notify` helper wraps the global toast store so call-sites stay short. 429 responses include `retry_after_sec` so the fetch wrapper can surface a countdown toast automatically.

## Data flow

```
[render crash]
  └─→ ErrorBoundary.componentDidCatch
        ├─→ console.error (DEV) | console.warn (PROD)
        ├─→ reportClientError → sendBeacon → POST /me/client-errors
        │                                       └─→ pino warn + soft-insert client_errors
        └─→ setState{error} → render fallback card

[fetch 429]
  └─→ agentsApi.request()
        ├─→ parseRetryAfter (body retry_after_sec → Retry-After header → date)
        ├─→ import('./notify') → notifyRateLimited(secs)
        │                          └─→ globalStore.addToast({warning, ...})
        └─→ throw AgentsApiError (caller still gets the rejection)

[route throws]
  └─→ Hono app.onError
        ├─→ pino log + Sentry captureException
        └─→ c.json({ ok:false, error:'internal_error', message, detail }, 500)
```

## DB / Env / API

- Tables: `client_errors` (id, ip, name, message, stack, component_stack, href, user_agent, occurred_at, created_at)
- Env: `RATE_LIMIT_CHAT_PER_MIN` (default 30), `RATE_LIMIT_CHAT_PER_HOUR` (default 600)
- Routes:
  - `POST /me/client-errors` — anon, 20 hits / 60 s per IP, returns 204
  - `app.onError` — fallback for every other route
- Frontend env: `VITE_AGENTS_URL` — base URL the ErrorBoundary posts to

## Wire shape (canonical)

```jsonc
// success
{ "ok": true, ...data }

// generic error
{ "ok": false, "error": "internal_error", "message": "Что-то сломалось у нас. Попробуй ещё раз.", "detail": "TypeError: ..." }

// 429
{ "ok": false, "error": "rate_limited", "retry_after_sec": 30, "window": "minute", "limit": 30, "message": "Слишком много запросов. Попробуй через минуту." }
// + Retry-After: 30 header

// 404 / 403 / 401 / 400 — same shape, different error code
{ "ok": false, "error": "not_found", "message": "Не найдено.", "detail": "project missing" }
```
