# Desktop platform backends

## TL;DR
The `agentflow-desktop` daemon used to be Mac-only (Quartz, AppleScript, pyobjc). It now
routes every OS-specific call through a `PlatformBackend` Protocol with three
implementations: `mac` (Quartz/CoreGraphics + AppleScript), `linux` (mss + xdotool/wmctrl
+ xclip/wl-clipboard; falls back to grim on Wayland), `windows` (mss + pywin32 + pyperclip).
Backend selection happens at import time based on `sys.platform`; nothing else in the
codebase branches on OS.

## DB / Env / API
- No DB rows specific to backends — daemon-local only.
- Env vars consumed: `XDG_SESSION_TYPE`, `WAYLAND_DISPLAY` (linux backend Wayland detection).
- New CLI: `agentflow-desktop selftest` — no API key, no network, prints OK/FAIL per backend method.
- Dependencies (`pyproject.toml`):
  - Always: `mss`, `pyautogui`, `Pillow`, `websockets`, `mcp[cli]`
  - macOS-only: `pyobjc-framework-Quartz`
  - Windows-only: `pywin32`, `pyperclip`, `psutil`
  - Linux runtime tools (apt): `wmctrl`, `xdotool`, `xclip`; on Wayland add `grim`, `wl-clipboard`

## Failure modes
| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| `selftest` reports `FAIL: no backend for this platform` | `no backend for this platform` | `platform/__init__.py:_detect` — unsupported `sys.platform` |
| Linux capture fails on Wayland with `grim failed: ...` | `grim failed:` | `platform/linux.py:_grim_capture` — install `grim` or fall back to mss |
| Linux window_list returns `[]` even with windows open | (no error) | install `wmctrl`: `apt-get install wmctrl xdotool` |
| Linux clipboard read returns `""` on Wayland | (no error) | install `wl-clipboard`: `apt-get install wl-clipboard` |
| Windows window_list `[]` despite open apps | `pywin32 not installed` | `pip install pywin32` (auto on Win via marker) |
| Pyautogui on Linux raises `Xlib.error.DisplayNameError` | `DisplayNameError` | run under a real X session or `xvfb-run -a` in CI |
