# Project IDE pod-tools

## TL;DR

When a user opens their project's browser VS Code, the in-editor coding
extension and an in-terminal `claude` both need the SAME hands as the platform
agent: the flow LLM, the AgentFlow MCP toolbox, and the project secrets.
`provisionProjectIdePodTools` mints THAT user's `af_live_*` flow key, renders an
owner-scoped MCP config, exports the project secrets as env, and writes the
bundle into the pod's `<workspaceDir>/.agentflow/` via one access-gated pod
`exec`. Per-user isolation is structural: the key, secrets, and MCP `?owner=`
all key off the pod owner, so one tenant never reaches another's data.

## Data flow

```
GET /me/projects/:id/ide
  → ensureProjectIde() brings up code-server (project-ide.ts, untouched)
  → result.ready
      → provisionProjectIdePodTools({ ownerUserId, workspaceProjectName, workspaceDir })
          → ensureCloudIdeFlowKey(ownerUserId)        # per-USER af_live_ key
          → loadProjectSecretValues({owner,ws})       # per-USER+project secrets
          → buildPodMcpConfig(ownerUserId)            # MCP URLs ?owner=<uid>
          → composePodAgentEnv({flowKey,secrets})     # flow env wins over secrets
          → callTool('exec', {project, command}, {ownerUserId})
                # resolveProjectByWorkspace gates the pod by owner
                → heredoc-writes .agentflow/{mcp.json,settings.json,flow.env}
                → appends `source .agentflow/flow.env` to ~/.bashrc, ~/.profile
```

The editor extension reads `OPENAI_BASE_URL`/`OPENAI_API_KEY` and `mcp.json`;
an in-terminal `claude` inherits `ANTHROPIC_BASE_URL`/`ANTHROPIC_AUTH_TOKEN`
from the sourced `flow.env` and reads the same `mcpServers` from
`settings.json`. Both hit the flow facade, never `api.openai.com`.

## DB / Env / API

- Tables: `api_keys` (flow key row `cloud-ide:flow`), `project_secrets`
- Env: `AGENTS_PUBLIC_BASE_URL` (flow facade base), `ANTHROPIC_LARGE_MODEL`
  (flow alias), `AGENTFLOW_AGENTS_URL` (internal MCP base), `INTERNAL_API_SECRET`
  (MCP `x-mcp-auth`), `TG_MCP_URL` / `TG_MCP_TOKEN` (Telethon MCP)
- Routes: `GET /me/projects/:id/ide`
- MCP servers exposed to the pod: `telegram`, `tasks`, `tg-bot`, `architect`,
  `kwork-inbox`, `vk-inbox`, `instagram-inbox` (owner-scoped via `?owner=`)
- Pod files: `<workspaceDir>/.agentflow/mcp.json`, `…/settings.json`,
  `…/flow.env` (chmod 600)

## Failure modes

| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| Pod toolbox missing after open | `pod_tools_write_failed` | `services/project-ide-pod-tools.ts:349` |
| Flow key absent in pod | `flow_key_mint_failed` | `services/project-ide-pod-tools.ts:349` |
| Editor reaches openai.com | check `OPENAI_BASE_URL` ends `/llm/v1` | `services/project-ide-pod-tools.ts:207` |
| MCP server unreachable from pod | server skipped when `INTERNAL_API_SECRET` unset | `services/project-ide-pod-tools.ts:150` |
