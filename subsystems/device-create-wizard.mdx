# Device create wizard + calm manage view

## TL;DR

Adding a device is a 4-step funnel (`CabinetDeviceSetup.tsx`): pick where (local
desktop vs cloud pod) → connect/provision → optional first task → done. The device
detail page (`CabinetDeviceDetail.tsx`) was rebuilt as a "calm" manage view: primary
actions (Дать задачу / Пауза / Стоп) up top, everything technical folded into
collapsed `<Disclosure>` panels. The **Сценарии** use-case recipe picker (PR #543)
lives as the first disclosure and dispatches `agent_run_recipe`.

## Data flow

```
/cabinet/devices/new
   └─ CabinetDeviceSetup
        StepWhere ──local──> StepLocalInstall ──connected(device)──┐
                 └─cloud──> StepCloudProvision ──provisioned(id)───┤
                                                                   ▼
                                                  StepFirstTask (skip ok)
                                                                   ▼
                                                              StepDone
                                                                   │
                                            navigate → /cabinet/devices/:id
                                                                   ▼
                                              CabinetDeviceDetail (manage)
   primary: Дать задачу · Пауза · Стоп
   Дополнительно (collapsed Disclosures):
     ├─ Сценарии   → DeviceUseCasePicker → dispatch agent_run_recipe
     ├─ Доступы    → scope (apps / paths / shell / confirm / budget) + DeviceAppWhitelist
     ├─ Автономно  → DeviceAutonomousPanel
     └─ История    → sessions table → DeviceLiveSession
```

## DB / Env / API

- Routes: `/cabinet/devices/new`, `/cabinet/devices/setup` (wizard);
  `/cabinet/devices/new/cards` (legacy fallback); `/cabinet/devices/:id` (manage).
- Dispatch tool (use-case picker): `agent_run_recipe` with `scope: { recipe, params, cron? }`.
- Generic + manifest-driven — no per-slug code. Local devices surface `L*` use-cases,
  hosted pods `C*`, keyed off `device.kind === 'hosted' || device.hosted`.

## Rebase note (2026-05-30)

PR #544 (wizard + manage rewrite) was rebased onto main after PR #543 (use-case picker)
merged. #544 replaced the old tab nav with disclosures, so #543's `tab==='usecases'`
"Сценарии" tab was re-grafted as the first `<Disclosure>` (`advanced==='usecases'`).
Both survive: the picker still renders and dispatches `agent_run_recipe`. The old
`tab`/`setTab` state was dropped (disclosures use `advanced`).

## Failure modes

| Symptom | Log / grep signature | Where to fix |
|---|---|---|
| Сценарии disclosure empty for a hosted pod | `useCaseHome` resolves to `local` for a `kind==='hosted'` device | `CabinetDeviceDetail.tsx:165` — `isHosted` check |
| Recipe never dispatched on outcome select | no `agent_run_recipe` in events | `DeviceUseCasePicker.tsx:86` — dispatch payload |
| `/cabinet/devices/new` shows old card picker not wizard | route points at `CabinetDeviceNew` | `main.tsx:720` — must be `CabinetDeviceSetup` |
