# Research citation pills

## TL;DR

The chat-tooluse loop now harvests citation URLs (`source_url` / `url`) from every tool result in a turn, dedupes them per user message, streams them on a new `sources` SSE event, and persists the final list onto `chat_messages.meta.sources`. The frontend already reads `meta.sources` on history load (`AgentChatPanel.tsx`), so pills survive a page reload — the bug fixed here was the backend never writing them.

## Data flow

```
user message
   │
   ▼
runChatTurnNative (chat-tooluse.ts)
   │
   ├── tool dispatch loop ──┐
   │                        │
   │   for each tool_use:   │
   │     mcpRes = callTool  │
   │     ┌──────────────────▼──────────────────┐
   │     │ extractSourcesFromToolResult        │
   │     │   knowledge.search → items[].source_url │
   │     │   tavily.{search,extract,news}      │
   │     │     → results[].url                 │
   │     │   generic → {items|results}[].url   │
   │     └──────────────────┬──────────────────┘
   │                        │
   │     mergeSources(acc, new) ── dedupe by URL
   │                        │
   │     if grew → onSourcesUpdate(snapshot)
   │                        │
   ▼                        ▼
ChatTurnResult.sources    SSE: event:sources
   │                        │
   ▼                        ▼
routes/agents.ts          (frontend live update)
   │
   ├── enqueueEvent('done', { text, sources })
   └── db.insert(chatMessages).values({
         role: 'agent',
         content: replyText,
         meta: { sources }   ← persisted here
       })
                         │
                         ▼
              page reload → GET /agents/:slug/messages
                         │
                         ▼
        storedToTurn() reads m.meta.sources
                         │
                         ▼
            AgentChatPanel renders citation pills
```

## DB / Env / API

- Tables: `chat_messages.meta` (JSONB, nullable — no migration needed).
- Persisted shape: `meta = { sources: [{ source_url, title, score }, ...] }` only when at least one URL was harvested. Otherwise `meta = null`.
- SSE events emitted by `POST /agents/:slug/chat`:
  - `event: sources` — `{ sources: [{ source_url, title, score }, ...] }` — fires whenever the accumulator grows. Optional for the UI; live pills render from `ui_blocks` today, persistence is the actual fix.
  - `event: done` — now `{ text, sources? }` (sources omitted when empty).
- No env vars added.
- API routes: no shape change to existing `GET /agents/:slug/messages` — `meta.sources` flows through the existing `StoredMessage.meta: Record<string, unknown> | null` field.

## What counts as a source

`extractSourcesFromToolResult(server, tool, mcpResult)` is generic and accepts ANY tool whose payload has:
- `items[]` (knowledge.search shape) or `results[]` (tavily.* shape), with each entry exposing one of `source_url` / `url` / `source`, OR
- A flat top-level object with one of those URL fields (single-result tools).

Hard filter: only `http(s)://` URLs are kept. `file://`, `javascript:`, and bare strings are rejected so the pill list can't be poisoned by tool authors.

First-write-wins on dedupe: identical `source_url` from two tools keeps the title/score from the first occurrence. Deterministic, predictable for the UI.

## Failure modes

| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| Pills appear during stream then vanish on reload | `db.insert(chatMessages).values(` agent row without `meta` field | `agentflow-agents/src/routes/agents.ts:805` |
| Pills never appear at all (knowledge tool returns empty) | `[chat-tooluse] start agent=` followed by `tool=knowledge.search` and zero items | Owner has no docs ingested — see `knowledge-mcp.mdx` |
| Wrong title on shared URL | first-write-wins by design — change order of tool calls in prompt | `chat-tooluse.ts:mergeSources` (intentional) |
| `meta=null` on persisted row despite tool returning URLs | tool result envelope `isError:true` → harvester skips | check MCP server logs for the offending tool |
