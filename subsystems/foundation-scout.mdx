# Foundation Scout

:::caution[Deprecated — старая архитектура]
Этот раздел про старую архитектуру с vertical → curated GitHub repo подбором по `kind=landing/spa/tg_bot/...`. Новый flow (AI-ранжированный GitHub Code Search прямо по словам брифа, без vertical-таблицы) описан в [`subsystems/projects`](/subsystems/projects/) (approved 2026-05-25).
:::

## TL;DR

When a user submits a brief, the platform picks a GitHub repo as the project's
foundation BEFORE the coder runs. The owner directive (T6 — 2026-05-23): pick a
repo that's already ~90% the brief, then rebrand it. The coder shouldn't
scaffold from scratch on top of a generic landing template.

The scout runs three layers in order:
1. **Curated bypass** for marketing-intent briefs — direct vertical lookup
   (ecom → Medusa, dashboard → kiranism, blog → timlrx, portfolio → BartoszJarocki/cv,
   landing → cruip).
2. **LLM scorer** — TEXT_SMALL ranks every curated entry 0-10 against the brief
   for non-marketing briefs.
3. **LLM proposer + substring matcher** — fallback when curated bypass + scorer
   both come back empty.

## Data flow

```
POST /me/projects {brief, title, kind?}
  → row inserted with status='preparing', placeholder foundation
  → response returns < 2s
  → setImmediate(runBackgroundProjectPrep)
      ├── classifyUserFacingProjectKind (when kind=auto)
      ├── recommendProjectFoundations
      │     ├── shouldUseMarketingCuratedBypass(brief, kind)?
      │     │     └── true → detectVertical → pickCuratedBypassList → bucket
      │     │                 ├── ecom_marketplace → ECOM_CURATED_LIST
      │     │                 ├── dashboard_saas   → DASHBOARD_CURATED_LIST
      │     │                 ├── blog_content     → BLOG_CURATED_LIST
      │     │                 ├── portfolio_cv     → PORTFOLIO_CURATED_LIST
      │     │                 ├── mlm              → MLM_CURATED_LIST
      │     │                 └── *                → MARKETING_CURATED_LIST
      │     ├── false → scoreCuratedFoundations (LLM TEXT_SMALL, 0-10)
      │     │           + proposeWithLlm (LLM TEXT_LARGE proposes 5 repos)
      │     ├── enrich via GitHub REST (stars, license, package.json, root contents)
      │     ├── deriveStructuralSignals → decideHardReject (drop monorepos / framework source)
      │     └── score → top 15
      ├── update projects.foundationRepoFullName + foundationSnapshot, status='draft'
      ├── emit foundation_picked event
      ├── ensureProjectFoundationScout (permanent scout agent)
      └── runFastPathProposal → plan_proposed → status='awaiting_approval'
```

## DB / Env / API

- Tables: `projects.foundation_mode`, `projects.foundation_repo_url`,
  `projects.foundation_repo_full_name`, `projects.foundation_ref`,
  `projects.foundation_snapshot` (JSONB), `projects.scout_agent_id`.
- Events: `kind_resolved`, `foundation_selected`, `foundation_picked`,
  `foundation_scout_attached`, `project_ready`.
- Env: `GITHUB_TOKEN` (REST enrichment, optional but recommended).
- Routes: `POST /me/projects` (route handler at `agentflow-agents/src/routes/projects.ts:920+`),
  `POST /me/project-foundations/recommend` (preview during the wizard).
- LLMs: `ModelType.TEXT_SMALL` (scorer), `ModelType.TEXT_LARGE` (proposer).
  Routed through `ai-router/instrumented.ts:invokeAI`.

## Failure modes

| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| Tea shop / ceramic shop brief lands on `cruip/open-react-template` instead of an ecom template | `[foundation-scorer] marketing_bypass vertical=landing_generic` for a brief containing «магазин» / «marketplace» | Extend `VERTICAL_RX.ecom_marketplace` in `foundation-structural-filter.ts:370` |
| Dashboard brief picks generic landing | `[foundation-scorer] marketing_bypass vertical=landing_generic` for a brief containing «dashboard» | Extend `VERTICAL_RX.dashboard_saas` |
| Brief contains «магазин» but is actually MLM → still picks ecom bucket | `[foundation-scorer] marketing_bypass vertical=ecom_marketplace` for a Monar / MLM brief | `detectVertical` runs `isMlmBrief` first; widen `MLM_KEYWORDS_RX` in `foundation-structural-filter.ts:344` |
| All bypass paths return empty list | `[foundations] llm returned zero suggestions for brief` | Curated bucket entry validation failed enrichment — check `fetchRepoMeta` for 404s |
| scaffold_vite node runs coder-spa unnecessarily for kind=spa | `coder_did_nothing` in `scaffold_vite` for a spa project | `mini-app.ts:scaffoldViteCoder` — kind=spa now noops here, foundation-bridge in `admin_panel` owns the work (T6 2026-05-23) |
| Scout agent never attaches | `foundation_scout_provision_failed` | `project-foundation-scout.ts:262` — check Eliza is up, preset file is readable |
