# JSON App Manifests

## TL;DR
A feature on AgentFlow is declared as a JSON `AppManifest` (modes, panels,
composer, pricing, CLI commands, MCP/engine `uses`) rather than bespoke code.
`app-manifests/*.json` ship in the image; `src/app-manifests/registry.ts` loads
them into a slug→manifest map; `GET /me/apps` + `GET /me/apps/:slug` expose them
read-only; the `agentflow-apps` CLI renders the SAME registry. The frontend draws
any manifest generically (see [Generic App Renderer](/subsystems/generic-app-renderer)).
Examples: `accounts-pult.json` (Пульт) and `cloud-ide.json`
([Cloud IDE](/subsystems/cloud-ide)).

## Data flow
```
app-manifests/*.json (in image)
   │  readdirSync + validateManifest (zod)
   ▼
registry.ts  slug→AppManifest (cached)
   ├─ HTTP: GET /me/apps        → listManifests()
   ├─ HTTP: GET /me/apps/:slug  → getManifest(slug)   (404 if absent)
   ├─ HTTP: POST /me/apps/route → routeComposerMessage(msg)
   │           liveCatalogSource → compact catalog
   │           useModel(TEXT_LARGE) → strict-JSON pick
   │           slugValidator coerces a hallucinated slug → null
   │           confidence < 0.45 → {appSlug:null, reason}
   └─ CLI:  agentflow-apps list|show|run → same registry
   ▼
FE: /apps grid + /apps/:slug renderer (generic panel map);
    composer box POSTs /me/apps/route → opens the chosen app+mode prefilled
```

## DB / Env / API
- Tables: none — manifests are on-disk JSON (DB-backed/user-authored apps are a later phase, see `routes/me-apps.ts:8`).
- Env: none required; disk resolution mirrors `services/preset-store.ts` candidate-dir list (`registry.ts:7`).
- Routes: `GET /me/apps`, `GET /me/apps/:slug`, `POST /me/apps/route` (all `requireSession`).
  - `POST /me/apps/route` body `{ message: string }` → `{ appSlug, mode, prefill, confidence, reason }`. `message` must be a string (else `400 message_required`); a non-JSON body returns `400 invalid_json_body`. The handler never 500s on a bad LLM reply — it returns `appSlug:null` with a reason.
- CLI: `agentflow-apps list | show <slug> | run <slug> <cmd>`.
- LLM: `POST /me/apps/route` calls `useModel(ModelType.TEXT_LARGE)` with `ownerUserId` from the session for billing attribution; no model name is hardcoded.
- Manifest `uses`: free-string `engine` + `mcp_tools` (engine selection still routes through `useModel`, never a hardcoded model).

## Failure modes
| Symptom | Log signature / response for grep | Where to fix |
|---|---|---|
| Manifest absent → 404 on app page | response `{ ok:false, error:'app_not_found' }` (FE: «Апп … не найден») | `agentflow-agents/src/routes/me-apps.ts:33` |
| A bad `.json` silently skipped from registry | `loadManifestsFromDir` collects `errors[]` (file kept out of map) | `agentflow-agents/src/app-manifests/registry.ts:58` |
| No candidate dir found at boot | `findManifestsDir()` returns `null` → empty registry | `agentflow-agents/src/app-manifests/registry.ts:40` |
| CLI unknown verb | prints `unknown command: <verb>` + USAGE | `agentflow-agents/src/cli/agentflow-apps.ts:121` |
| Composer route returns null app on a garbled LLM reply | `[composer-router] parse_failed` | `agentflow-agents/src/services/app-composer-router.ts:233` |
| Composer route drops an invented app slug | `[composer-router] hallucinated_slug` | `agentflow-agents/src/services/app-composer-router.ts:239` |
| Composer route degrades when all providers are down | `[composer-router] llm_call_failed` | `agentflow-agents/src/services/app-composer-router.ts:227` |
