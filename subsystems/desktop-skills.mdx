# Desktop Skills

## TL;DR

`device_intent_skills` is a per-user table of "when I say X, do Y" rules. The
desktop daemon (`agentflow-computer-mcp`) pulls a pre-rendered prompt block via
`GET /me/devices/skills/prompt-block` on each task and prepends it to its system
prompt, so users replace hardcoded phrase → tool mappings inside the daemon
loop with their own rules. Managed at `/cabinet/devices/skills`.

## Data flow

```
cabinet board
   │ POST /me/devices/skills          → INSERT device_intent_skills
   │ PUT  /me/devices/skills/:id      → UPDATE row by (id, user_id)
   │ POST /me/devices/skills/reorder  → sql.begin() UNNEST UPDATE
   ▼
device_intent_skills (Postgres)
   ▲
   │ GET  /me/devices/skills/prompt-block?device_id=…
   │      WHERE user_id = $sub AND enabled = TRUE
   │      AND (device_id = $deviceId OR device_id IS NULL)
   ▼
desktop daemon system prompt
   ↳ "• Когда юзер говорит «…» → instruction…"
```

The daemon caches the block per task. A skill `device_id = NULL` applies to
every device the user owns; a non-null value scopes it to one Mac. When the
cabinet creates a skill it verifies the caller owns the referenced device
before insert.

## DB / Env / API

- **Table:** `device_intent_skills` (`agentflow-agents/migrations/2026-05-22b-device-intent-skills.sql`).
  - PK `id BIGSERIAL`, FK `user_id → users(id) ON DELETE CASCADE`.
  - `device_id` nullable, FK to `user_devices(id) ON DELETE CASCADE`.
  - `when_phrases TEXT[]` (1+ phrases, each ≤ 200 chars).
  - `then_instruction TEXT` (1–2000 chars).
  - `category TEXT` CHECK in (`'custom' | 'comm' | 'system' | 'research' | 'developer'`).
  - `enabled BOOLEAN`, `position INTEGER`.
  - Indexes: `(user_id, device_id)`, `(user_id, category, position)`.
- **Env:** none new. Auth flows through the existing `af_session` cookie / `x-api-key` header (`requireSession`).
- **Routes:**
  - `GET    /me/devices/skills?device_id=…`
  - `POST   /me/devices/skills`
  - `PUT    /me/devices/skills/:id`
  - `DELETE /me/devices/skills/:id`
  - `POST   /me/devices/skills/reorder`
  - `GET    /me/devices/skills/prompt-block?device_id=…`

### Prompt-block format

One enabled row per line:

```
• Когда юзер говорит «напиши в TG» / «send tg» → use af_send_telegram_message with chat_id=me
• Когда юзер говорит «прочитай почту» → Открой Mail.app, читай 5 последних…
```

Multi-phrase skills join with ` / ` between quoted phrases. Disabled rows are
omitted. Empty user list returns `{ block: "" }`.

## Failure modes

| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| Daemon ignores a new skill | `prompt-block` returns empty `block` despite cabinet showing rows — usually `enabled=false` | toggle the card on, or `UPDATE device_intent_skills SET enabled = TRUE WHERE id = $id` |
| Cabinet 404 on `/me/devices/skills` | route order regression — `/me/devices/:id` swallows `/me/devices/skills` | re-check `src/server.ts:783` mounts `meDevicesSkillsApp` before `meDevicesApp` |
| `POST /reorder` updates only some rows | rows belong to a different `user_id` — the `WHERE s.user_id = ${userId}` clause filters silently | confirm the cabinet only sends ids it owns; check `device_intent_skills_user_cat_pos` index covers the lookup |
| `invalid_body` from POST | zod rejected the input — usually empty `when_phrases` or `then_instruction > 2000 chars` | inspect `.detail` array in response; mirror CHECK constraints in the form |
| Skill survives device deletion | `device_id` is nullable so device-scoped rows are GC'd via `ON DELETE CASCADE`; global (`device_id IS NULL`) rows stay alive — intentional | no fix needed; document this UX expectation in the cabinet copy |
| Cloud device loops on `screen_capture` for project chat | `ScreenShotError: Library libxcb.so not found` in daemon logs, task text starts with `[PROJECT CONTEXT]` | `agentflow-computer-mcp/src/agentflow_computer_mcp/driver/loop.py:1005-1046` — `run_task` now strips `screen_capture / screen_region / list_windows / activate_app / chrome_* / browser_* / keyboard_* / mouse_*` from the descriptor list AND skips the initial `jpeg_b64_full()` frame when the task body contains `[PROJECT CONTEXT]` or `project_id:` / `project_dir:`. Soft prompt directives don't bind tool choice; the LLM can't call what it can't see. Shipped in computer-mcp PR #121 (2026-05-28). |
