# AgentFlow Desktop (forked Goose Desktop)

## TL;DR
AgentFlow Desktop is a rebranded fork of Block's Goose Desktop (Electron Forge app)
living in `lnlockly/agentflow-goose` at `ui/desktop/`. It ships the local `goosed`
binary (Rust, `crates/goose-server`) and runs in two modes: standalone (user chats,
goose codes + controls the machine) and platform-driven (device-bridge enrolls with
AgentFlow and runs the same `goosed` from `task_dispatch`). Phase 1 (this page's
current scope) rebrands the brand surface only — name, bundle id, icons, theme accent,
installer metadata, updater target, docs links. Internal identifiers (`goosed`,
`GOOSE_*` env, `goose://` deep-link scheme, `@aaif/goose-sdk` workspace pkg) are kept
unchanged on purpose.

## DB / Env / API
- Env (build/runtime, unchanged identifiers): `GOOSE_PROVIDER`, `GOOSE_MODEL`,
  `OPENAI_HOST`, `GOOSE_BUNDLE_NAME`, `GITHUB_OWNER`, `GITHUB_REPO`, `APPLE_TEAM_ID`,
  `APPLE_ID`, `WINDOWS_CERTIFICATE_FILE`.
- Bundle id: `com.agentflow.desktop` (macOS). Deep-link scheme: `goose://` (kept —
  recipe/resume deep-links + server-emitted URLs depend on it).
- Updater target default: `github.com/lnlockly/agentflow-goose/releases/latest`.
- Device-bridge enrolment: `~/.agentflow/auth.json` (`api_key`, `device_id`,
  `device_secret`/`enrollment_token`, `ws_url`) — same file the old daemon used.
- Device-bridge env: `FF_DEVICE_BRIDGE=1` (opt-in until packaged-verified),
  `AGENTFLOW_DIR` (auth dir override), `AF_API_URL` (REST base, default
  `https://agentflow.website` → `/_agents`).
- Engine LLM env (P3, gated `FF_FLOW_LLM=1`): `GOOSE_PROVIDER=openai`,
  `GOOSE_MODEL=flow` (alias only — gateway's `pickFlowUpstream` resolves it),
  `OPENAI_HOST=https://agentflow.website`,
  `OPENAI_BASE_PATH=_agents/llm/v1/chat/completions`, `OPENAI_API_KEY=<af key
  from auth.json>`, `GOOSE_DISABLE_KEYRING=true`. `GOOSE_MODE` is NOT set so
  interactive Mode A keeps its tool-approval UX. The gateway requires an
  `af_live_*` key, so a keyless standalone launch keeps the user's own provider.
- WS frames (device→server): `hello`, `heartbeat`, `task_progress`,
  `task_complete`, `task_error`; (server→device): `hello_ack` (rotates
  `device_secret`), `task_dispatch`, `task_cancel`, `subscribe_stream`/`unsubscribe_stream`.
- goosed headless dispatch: `POST /agent/start` (→ `Session.id`) then `POST /reply`
  (SSE, header `X-Secret-Key`), events `Message`/`Finish`/`Error` — `crates/goose-server`.
- Docs links repointed: `goose-docs.ai` → `docs.agentflow.website`; issues →
  `github.com/lnlockly/agentflow-goose/issues`.

| Bridge connects then drops repeatedly | `[device-bridge] heartbeat timeout — closing` | network / server WS keepalive |
| Dispatched task fails | `[device-bridge] task … cancelled` or `task_error: task_failed:` frame | `ui/desktop/src/device-bridge/goosedDispatch.ts` |
| Queued tasks not replayed | `queued-task drain failed` | `ui/desktop/src/device-bridge/queuedTasks.ts` |

## Device-bridge verification status
The bridge module is unit-verified — 29 vitest tests (auth round-trip + header
build, SSE framing + `/reply` answer/usage accumulation, WS handshake +
secret-rotation + task dispatch/cancel/progress, queued-task normalization) pass,
and the whole module typechecks clean under the repo's strict + `noUnusedLocals`/
`noUnusedParameters`/`noImplicitReturns` flags. The live wiring (`main.ts`
`ensureDeviceBridge`) is gated `FF_DEVICE_BRIDGE=1`. End-to-end Mode B against a
real cabinet dispatch needs a packaged build (matrix b3/b4/b6) — that is the next
verification step once P1 lands and a signed/packaged artifact exists.

## Not yet done (tracked follow-ups)
- **Extension enablement (P3.5):** `engineConfig.buildExtensionsConfig()` is the
  canonical builder for the `developer` + `computercontroller` builtins + af_*
  MCP, but it is not yet applied to the desktop's goose config (developer is on
  by default; computercontroller + af_* need a config merge through the desktop's
  extension system — held back to avoid clobbering a user's `config.yaml`).
- **Live-screen stream (b6 "watch live"):** `subscribe_stream`/`unsubscribe_stream`
  are routed to an `onStreamSubscribe` hook, but the screen-capture publisher
  (port of computer-mcp `CaptureLoop`) is not yet wired — flag for P3/P4.
- **Renderer/i18n copy scrub:** ~65 `src/components/*` files + `src/i18n/messages/en.json`
  still say "goose" in user-facing copy (e.g. "Welcome to goose", "goose is thinking…").
  Deferred from Phase 1 to avoid breaking `i18n:check` (compiled-message parity). Needs a
  dedicated extract+recompile pass across all locale files.
- **Splash frames** `src/images/loading-goose/*.svg` still the goose animation — replace
  with AgentFlow mark.
- **Code-signing / notarization** certs (Apple + Windows EV) — infra/owner.
- **Packaged Mode-B e2e:** flip `FF_DEVICE_BRIDGE=1` in a packaged build, enrol via
  cabinet, dispatch a task, confirm `task_complete` with a real answer artifact.
