# Account automations

## TL;DR

An `account_automations` row pairs a `recipe` (a connector `ActionIntent`
template) with a `trigger` (`{kind:'cron'|'event', value}`) for one owner +
account. A 60s worker tick selects active cron rows whose schedule has elapsed,
routes each to the right connector by the `${platform}:${ref}` prefix, drafts
the action via `connector.buildAction(...)` (dry-run, NEVER sends), and `arm()`s
it into `entity_approval_queue`. The owner confirms in the Пульт — automations
schedule drafts, the [approval queue](/subsystems/approval-queue) is the only
send gate. Mounted at `/me/account-automations` because `/me/automations` is
already the Activepieces marketplace surface.

## Data flow

```
every 60s (AUTOMATIONS_TICK_MS) → runAutomationsTick():
  selectActiveCron({limit})                       (status='active', cron only)
    for each row:
      isDue(trigger, last_run_at, now) ? continue : skip
      platformOf(account_ref) → getConnector(platform)
      connector.buildAction(account, recipe-as-intent, ctx)   ← dry-run, NO send
      arm(user_id, {action}) → INSERT entity_approval_queue status='armed'
      recordRun(id, result)  → stamp last_run_at + last_result
                                    │
owner Пульт: GET /me/approvals?status=armed ──▶ confirm ──▶ executeAction once
```

The PATCH body recognises only `status` (`active`|`paused`); any other value →
`400 invalid_body`. The worker only ever drafts — there is no auto-send path.

## DB / Env / API

- Tables: `account_automations (id, user_id, account_ref, name, recipe jsonb,
  trigger jsonb, status, last_run_at, last_result, created_at, updated_at)`;
  indexes `idx_account_automations_status (status, last_run_at)` +
  `idx_account_automations_user`.
- Env: none new. Worker cadence is the `AUTOMATIONS_TICK_MS` constant (60s).
- Routes (all `requireSession`, owner = `session.sub`):
  - `GET    /me/account-automations` → `{ ok, count, items }`
  - `POST   /me/account-automations { accountRef, name, recipe, trigger }` → `{ ok, item }`
  - `PATCH  /me/account-automations/:id { status }` → `{ ok }`
  - `DELETE /me/account-automations/:id` → `{ ok }`
- MCP tools: none directly — the connector each automation routes to wraps them.

## Failure modes

| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| Create rejected, malformed recipe | `recipe_bad_type` | `src/services/automations/engine.ts:93` |
| Create rejected, bad cron string | `trigger_bad_cron` | `src/services/automations/engine.ts:109` |
| Create rejected, empty name | `name_required` | `src/services/automations/engine.ts:160` |
| PATCH status to a non-`active\|paused` value | `invalid_body` (`status must be active\|paused`) | `src/routes/me-account-automations.ts:114` |
| Automation fires but the platform has no connector | `runAutomationsTick` skips on `getConnector` miss / `recordRun` error | `src/services/automations/engine-worker.ts:116` |
