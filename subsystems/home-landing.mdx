# Home landing (HomeV3)

## TL;DR

`HomeV3.tsx` is the main marketing landing for `/`. As of 2026-05-15 it
ships an Apple-keynote tier visual treatment: oversized hero type
(`clamp(44px, 8.4vw, 112px)`), soft gradient mesh background, single
primary CTA, and six sections that each earn their row (hero → 3-step
explainer → showcase tiles → numbers → pull quote → final CTA → footer).
Styling lives under `.v3.home-apple` in `home-apple.css`, layered on top
of the existing `.v3-*` token system from `landing-v3.css` so V3Header
keeps working without changes.

## Data flow

```
Browser → /  → React Router → lazy(HomeV3)
   ↓
HomeV3 mounts under <div class="v3 home-apple">
   ↓
useEffect adds .has-reveal to root
   ↓
IntersectionObserver toggles .is-in on each .apple-reveal
   ↓
CSS fade + slide-up via cubic-bezier(0.22, 1, 0.36, 1) @ 700ms
```

## Reveal motion

The reveal animation is **opt-in**, not opt-out. By default `.apple-reveal`
elements are fully opaque. Only after JS adds `.has-reveal` to the page
root does CSS switch them to `opacity:0; translateY(28px)`. The
`IntersectionObserver` then adds `.is-in` per element when it enters
viewport. This means:

- SSR / no-JS / pre-hydration render = content visible
- Headless `fullPage: true` screenshots = content visible (no scroll race)
- `prefers-reduced-motion: reduce` = no `.has-reveal` ever applied, content visible

## Failure modes

| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| Sections below fold stay invisible | (visual only — no log) | `HomeV3.tsx:38` reveal logic; verify `.has-reveal` opt-in is in place so non-JS renders stay visible. |
| Headline wraps awkwardly on iPhone SE (375px) | (visual only) | `home-apple.css` `.apple-hero h1 { font-size: clamp(40px, 11vw, 56px) }` in `@media (max-width: 640px)` block. |
| Lime gradient blob clips into header | (visual only) | `.apple-hero { overflow: hidden; isolation: isolate }` already prevents this; verify if header gets `position: sticky` removed. |
| `/` shows old AGENTFLOW launchpad page | route falls back to `<App />` | `agentflow-landing/src/main.tsx:282` — route for `/` must point at `HomeV3`, not `App`. |
| Build fails with TonCenter error | `VITE_TONCENTER_API_KEY ... is required for production builds` | Set `VITE_ALLOW_NO_TONCENTER_KEY=1` (already in prod Dockerfile). |
