# Cloud IDE — Extension Packs + Codex-via-flow

## TL;DR
The Cloud IDE (`code-server` at `ide.agentflow.website`) gains named, installable
**extension packs** the user picks in the cabinet, and the OpenAI-compatible AI
coding extension (`continue.continue`) is repointed at the platform **flow**
facade (`<origin>/_agents/llm/v1`) instead of `api.openai.com`. The model is the
`flow` alias (resolved server-side); the API key is a per-user `af_live_*` flow
key minted server-side, never a real OpenAI key and never minted in the FE.

## Data flow
```
cabinet picker → POST /me/cloud-ide/extensions { pack }   (requireSession: cookie OR x-api-key)
  → getExtensionPack(pack)            (unknown → 400 unknown_pack, no exec)
  → for each id: kubectl exec deployment/cloud-ide -c code-server --
        code-server --install-extension <id> --force   (one exec per id; a single failure never aborts)
  → ensureCloudIdeFlowKey(userId)     (mint af_live_* flow key, server-side)
  → write settings.json (merge):
        continue.models[0] = { provider:"openai", model:"flow",
                               apiBase:"<origin>/_agents/llm/v1", apiKey:<af_live_*> }
  → 200 { installed[], failed[], flowSettingsWritten }   (never 500 on a single failure)

k8s boot: initContainer bootstrap-extensions → bootstrap.sh
  → installs DEFAULT pack (basic) + (when CLOUD_IDE_FLOW_KEY set) AI pack + flow settings
```

The coding extension then sends OpenAI `/chat/completions` to
`<origin>/_agents/llm/v1/chat/completions` with `Authorization: Bearer af_live_*`.
`pickFlowUpstream` (`public-llm-upstream.ts`) resolves the `flow` alias to the
live concrete model per request — no model id is hardcoded.

## DB / Env / API
- Tables: `api_keys` (per-user `cloud-ide:flow` row holds the flow key hash).
- Env (pod): `AF_API_URL` (origin for the flow baseURL), `CLOUD_IDE_FLOW_KEY`
  (optional boot-time flow key from Secret `cloud-ide-auth.flow_key`).
- Routes: `POST /me/cloud-ide/extensions`, `GET /me/cloud-ide/extensions/packs`.
- Flow OpenAI baseURL: `https://agentflow.website/_agents/llm/v1` (the extension
  appends `/chat/completions`). Model: the `flow` alias. NEVER `api.openai.com`.
- Codex/OpenAI extension id: `continue.continue` (Open VSX). Claude companion:
  `anthropic.claude-code`.

## Failure modes
| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| Pack not applied, 400 | response `unknown_pack` | client sent an unknown slug — list via `GET /me/cloud-ide/extensions/packs`, `me-cloud-ide-extensions.ts:79` (`getExtensionPack` miss) |
| One extension missing, others OK | `failed:[{id,detail}]` in the 200 body | bad Open VSX id or registry hiccup; re-run is a no-op (`--force`), `ide-extension-packs.ts:120` |
| AI assistant talks to OpenAI, not flow | `apiBase` is `api.openai.com` in settings.json | `renderFlowSettings` must set `apiBase` to `flowOpenAiBaseUrl` — `ide-extension-packs.ts:159` |
| Boot AI pack skipped | `[cloud-ide-bootstrap] CLOUD_IDE_FLOW_KEY unset` | create Secret key `cloud-ide-auth.flow_key`; otherwise per-user mint at runtime, `15-bootstrap.yaml` |
| Flow call 403 | upstream WAF blocks default `OpenAI/JS` UA | the editor extension UA differs; if blocked, mirror `FLOW_USER_AGENT`, `openclaw-shim/config.ts:45` |
