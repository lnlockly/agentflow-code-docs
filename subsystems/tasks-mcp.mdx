# Tasks MCP

## TL;DR
`src/mcp-servers/tasks.ts` is an internal MCP server that lets agents read and
write Plane projects/issues (the [Plane Task Manager](/subsystems/plane-task-manager)).
It is registered at `/internal/mcp/tasks` in `routes/internal-mcp.ts`. Every tool
returns errors **as data**: when `PLANE_API_BASE` / `PLANE_API_TOKEN` /
`PLANE_WORKSPACE` are unset it answers `{ok:false, error:'tasks_not_configured'}`
instead of throwing, so the server is a safe no-op until a workspace token is
configured.

## Data flow
```
Eliza agent → POST /internal/mcp/tasks  (MCP JSON-RPC)
   → handleTasksMcp → resolvePlaneConfig(process.env)
       │ unset → {ok:false, error:'tasks_not_configured'}  (no throw)
       └ set   → buildPlaneRequest → planeFetch → Plane api (X-API-Key)
                    └ planeErrorEnvelope on non-2xx (errors as data)
```

## DB / Env / API
- Tables: none (delegates state to Plane).
- Env: `PLANE_API_BASE`, `PLANE_API_TOKEN`, `PLANE_WORKSPACE` (agents secret).
- Route: `POST /internal/mcp/tasks` (internal MCP surface).
- Tools: `list_projects`, list/create/update issues, add comment (`tasksTools`, `tasks.ts:286`). Each returns `{ok:true,…}` or a typed `{ok:false,error}`.
- Scope: owner-pinned via `ownerUserId`, but the single workspace is addressed by the env token so owner-scope is advisory (`internal-mcp.ts:419`).

## Failure modes
| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| All tools no-op | `tasks_not_configured` | set `PLANE_*` env; `agentflow-agents/src/mcp-servers/tasks.ts:80` |
| 401 from Plane | `error:'auth_error'` | bad/expired token → re-run plane-bootstrap |
| 429 from Plane | `error:'rate_limited'` | `agentflow-agents/src/mcp-servers/tasks.ts:191` |
| other Plane non-2xx | `error:'http_error'` | `agentflow-agents/src/mcp-servers/tasks.ts:191` |
