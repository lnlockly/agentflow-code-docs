# CryptoBot billing

## TL;DR

Buyer clicks Start/Pro/Business on `/pricing` → backend mints a server-side payload `sub:u<id>:t<tier>:p<period>:c<credits>:v1`, calls `pay.crypt.bot/createInvoice` with token in `Crypto-Pay-API-Token` header, returns `pay_url`. User pays inside @CryptoBot, CryptoBot fires `invoice_paid` webhook signed with `HMAC-SHA256(rawBody, secret=SHA256(token))`. We verify hex header in constant time, parse the payload we minted, then in a single TX with `pg_advisory_xact_lock(hashtextextended('cryptobot:<invoice_id>'))`: flip `cryptobot_payments.status='completed'`, bump `user_credits.balance_cents`, and upsert `cryptobot_subscriptions` with `expires_at = GREATEST(existing, now()) + period_days × INTERVAL '1 day'` so renewals stack. Idempotency is enforced by UNIQUE `invoice_id` — webhook redelivery is a no-op.

## Heads-up — duplication with agentflow-api

There is an older parallel CryptoBot integration in `agentflow-api/src/routes/subscriptions.ts` + `agentflow-api/src/services/cryptobot.ts` that writes to the canonical `public.subscriptions` + `public.flow_payments` tables with a **different tier vocabulary** (`plus`/`pro`/`max` at $20/$100/$200/mo via `agentflow-api/src/services/flow-credits.ts:138`) and a **different surface** (`POST /subscriptions/checkout`, `POST /payments/cryptobot/webhook`). The current landing (PricingPageV2.tsx) advertises `start/pro/business` at $30/$90/$300 and hits `agents.agentflow.website` — i.e. this new service. Until a workspace-wide decision picks one as canonical, the new agents-side rail uses its own `cryptobot_payments` + `cryptobot_subscriptions` tables to avoid cross-crediting. Follow-up: pick a winner + retire the loser.

## Data flow

```
┌──────────────────────────────────────────────────────────────────────────┐
│  Buy flow (online, user-driven)                                           │
└──────────────────────────────────────────────────────────────────────────┘

  Browser                Hono (agents)              CryptoBot API
  /pricing                                          pay.crypt.bot
     │                                                    │
     │ click "Start/Pro/Business"                         │
     ├──► POST /me/billing/cryptobot/create-invoice ──────┤
     │   {tier, period_months}                            │
     │                  │                                 │
     │                  │ computeUsdPrice                 │
     │                  │ encodeSubscriptionPayload       │
     │                  │   ⇒ "sub:u42:tpro:p3:c60000:v1" │
     │                  │                                 │
     │                  ├─► POST /createInvoice ──────────►
     │                  │  hdr Crypto-Pay-API-Token       │
     │                  │  body {amount, payload, …}      │
     │                  │                                 │
     │                  │◄─── {invoice_id, bot_invoice_url}
     │                  │                                 │
     │                  │ INSERT cryptobot_payments       │
     │                  │   status='pending'              │
     │                  │                                 │
     │◄─── {pay_url, invoice_id, amount_usd}              │
     │                                                    │
     │ window.open(pay_url) ────────────────────────────► @CryptoBot dialog
     │                                                    │ user pays USDT
     │                                                    │
┌─────────────────────────────────────────────────────────┴─────────────────┐
│  Webhook flow (CryptoBot-driven, idempotent)                              │
└───────────────────────────────────────────────────────────────────────────┘
                                                          │
  Hono (agents)                                           │
     ◄── POST /webhooks/cryptobot ─────────────────────────
     │  hdr crypto-pay-api-signature: <hex>
     │  body { update_type:'invoice_paid', payload:{ invoice_id, payload, … } }
     │
     │  rawBody = c.req.text()        ← BEFORE JSON.parse
     │  verifyCryptoBotSignature(rawBody, sigHeader)
     │   ├─ secret = SHA256(CRYPTO_BOT_TOKEN)
     │   ├─ expect = HMAC-SHA256(rawBody, secret).hex
     │   └─ timingSafeEqual(actual, expect)  → fail-closed
     │  applyInvoicePaid(update)
     │   ├─ TX BEGIN
     │   ├─ SELECT pg_advisory_xact_lock(hashtextextended('cryptobot:'||id, 0))
     │   ├─ SELECT row FROM cryptobot_payments WHERE invoice_id = …
     │   ├─ if row.status='completed' ⇒ return {credited:false}    ← idempotent no-op
     │   ├─ if row.user_id ≠ payload.userId ⇒ throw                ← attribution guard
     │   ├─ UPDATE cryptobot_payments SET status='completed', paid_at=now()
     │   ├─ UPDATE user_credits SET balance_cents += creditsCents  ← atomic bump
     │   └─ INSERT INTO cryptobot_subscriptions (user_id, tier, expires_at)
     │      ON CONFLICT (user_id) DO UPDATE SET
     │        expires_at = GREATEST(cryptobot_subscriptions.expires_at, now())
     │                       + period_months × INTERVAL '30 days'    ← stack on renewal
     │
     ├──► 200 {credited:true, tier, expires_at}
```

## DB / Env / API

### Tables (migration `2026-05-14p-cryptobot-payments.sql`)

- **`cryptobot_payments`** — invoice journal
  - `id bigserial PRIMARY KEY`
  - `user_id integer NOT NULL`
  - `invoice_id bigint NOT NULL UNIQUE` — idempotency key
  - `currency_type text NOT NULL` — `crypto`
  - `asset text NOT NULL` — USDT/TON/BTC/ETH
  - `amount numeric(38,18) NOT NULL`
  - `usd_cents bigint NOT NULL`
  - `status text NOT NULL CHECK (status IN ('pending','completed','refunded'))`
  - `kind text NOT NULL CHECK (kind IN ('topup','subscription'))`
  - `tier text NULL` — start/pro/business when kind='subscription'
  - `period_months smallint NULL`
  - `metadata jsonb NOT NULL DEFAULT '{}'::jsonb`
  - `created_at timestamptz NOT NULL DEFAULT now()`
  - `paid_at timestamptz NULL`

- **`cryptobot_subscriptions`** — one row per user (NOT `public.subscriptions` — see "Heads-up" above)
  - `id bigserial PRIMARY KEY`
  - `user_id integer NOT NULL UNIQUE`
  - `tier text NOT NULL CHECK (tier IN ('start','pro','business'))`
  - `status text NOT NULL CHECK (status IN ('active','cancelled','expired'))`
  - `started_at timestamptz NOT NULL DEFAULT now()`
  - `expires_at timestamptz NOT NULL` — set via `GREATEST(existing, now()) + period_days`
  - `last_invoice_id bigint NULL`
  - `updated_at timestamptz NOT NULL DEFAULT now()`

### Env

- `CRYPTO_BOT_TOKEN` — Crypto Pay API token from @CryptoBot dashboard. **Required for create-invoice + webhook verify.** Missing ⇒ `cryptobot_not_configured` 503 + fail-closed signature reject.
- `CRYPTO_BOT_API_BASE` — optional, defaults `https://pay.crypt.bot/api`. Testnet: `https://testnet-pay.crypt.bot/api`.
- `CRYPTO_BOT_PRESTART_DISCOUNT` — optional, default `1.0` (no extra discount). Set to e.g. `0.5` for the −50% academy pre-start window. Applied **after** the period discount: `round(round(base × (1 − period_discount)) × months × prestart_factor)`. Validated `0 < n ≤ 1`; anything else falls back to 1.0. See `services/cryptobot-billing.ts:getPrestartFactor` (PR #249).

## Failure modes

| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| Frontend gets 503 on tier click | `cryptobot_not_configured` | Set `CRYPTO_BOT_TOKEN` on `deploy/agentflow-agents` (see `routes/billing-cryptobot.ts:144`) |
| Frontend gets 502 on tier click | `cryptobot_upstream` | CryptoBot API down or rate-limited; check `pay.crypt.bot` status (`routes/billing-cryptobot.ts:144`) |
| Webhook 401 spam in logs | `[cryptobot] webhook signature rejected` | Token mismatch between dashboard + pod env, or CryptoBot probing wrong endpoint (`routes/billing-cryptobot.ts:214`) |
| User paid but no credits | `applyInvoicePaid: unrecognised payload format` | Forged or legacy webhook with our prefix; ignored, return 200; check `cryptobot_payments` row (`services/cryptobot-billing.ts:384`) |
| User paid but wrong account credited | `applyInvoicePaid: user mismatch` | Pending row vs payload userId disagree — payload was tampered or pending row crossed wires. Block + investigate (`services/cryptobot-billing.ts:436`) |
| Invoice paid but status still pending | `applyInvoicePaid: invoice not paid` | CryptoBot sent update with status≠paid; check `update.payload.status` (`services/cryptobot-billing.ts:378`) |
| Subscription expires_at drift | (silent — verify against `cryptobot_subscriptions.expires_at`) | `GREATEST(existing, now())` clause at `services/cryptobot-billing.ts:495` — stacks on top of remaining time |
| Pending row missing on webhook | (defensive INSERT — no error) | Covered by `INSERT INTO cryptobot_payments` at `services/cryptobot-billing.ts:458` when SELECT returns 0 rows |

## Pricing matrix (single source of truth)

| Tier   | Base $/mo | 1mo  | 3mo (-15%) | 6mo (-25%) | 12mo (-35%) | Monthly USDF credits |
|--------|-----------|------|------------|------------|-------------|----------------------|
| Start  | $30       | $30  | $78        | $135       | $234        | 50 USDF              |
| Pro    | $90       | $90  | $231       | $405       | $702        | 200 USDF             |
| Business| $300     | $300 | $765       | $1350      | $2340       | 700 USDF             |

Per-month price is `Math.round(base × (1 - discount))` then `× months`. The same constants live in landing `PricingPageV2.tsx` — `tests/unit/cryptobot-billing.test.ts:53` guards drift.

### Pre-start factor (PR #249)

`GET /me/billing/cryptobot/pricing` now returns each tier with a `prices: [{months, amount_usd, regular_usd}, ...]` array plus a top-level `prestart: {active, factor, discount_percent}` block. `regular_usd` is the would-be price ignoring the prestart factor — frontend renders it strike-through next to `amount_usd` so users see what they save. When `CRYPTO_BOT_PRESTART_DISCOUNT` is unset (or 1.0), `active=false` and the two prices are equal.

Frontend consumers:
- `agentflow-landing/src/pages/AccountBilling.tsx` — tier cards on `/account/billing` (PR #178)
- `agentflow-landing/src/pages/PricingPageV2.tsx` — public pricing page

## Runbook — apply migration

CI does not run drizzle migrations (see `feedback_agentflow_migrations.md`). Apply by hand:

```bash
kubectl -n franchise-factory exec -i deploy/postgres -- \
  psql -U postgres -d agentflow \
  < agentflow-agents/migrations/2026-05-14p-cryptobot-payments.sql

# Verify
kubectl -n franchise-factory exec deploy/postgres -- \
  psql -U postgres -d agentflow -c '\d cryptobot_payments' -c '\d cryptobot_subscriptions'
```

The migration is wrapped in a top-level `pg_advisory_xact_lock(2026051401)` so concurrent cold-start applies serialise.
