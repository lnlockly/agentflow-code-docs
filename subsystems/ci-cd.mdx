# CI/CD

## TL;DR
GitHub Actions runs build+deploy on push to `main` for both `agentflow-agents`
and `agentflow-landing`. On `pull_request`, `agentflow-landing` runs a
Playwright E2E smoke against prod `agentflow.website` to catch P0
regressions (auth, autonomous-goal POST, NaN cards) before merge.
`agentflow-agents` PRs run `typecheck` + `build` (blocking) and a
`node --test` job over `tests/` (non-blocking, `continue-on-error: true`).

## agentflow-agents test glob (the `**` quirk)

`npm test` runs via `sh -c`, where `sh` has no `globstar`, so an unquoted
`tests/**/*.test.ts` collapses `**` to a single `*` — it matches nested
`tests/<dir>/*.test.ts` but silently DROPS top-level `tests/*.test.ts`. For a
long time ~109 top-level suites never ran in CI (and the `test` job is
`continue-on-error: true`, so nobody noticed). Real totals jumped 3042 → 4434
tests once fixed.

Fix: quote BOTH patterns so the shell passes them literally to node, whose
`--test` glob handles `**` correctly and de-dupes overlapping file args:

```
"test": "node --import tsx --test \"tests/*.test.ts\" \"tests/**/*.test.ts\""
```

`pr-check.yml` `detect_tests` counts with `find tests -name '*.test.ts'` for the
same reason. ~53 real failures are now visible (DB-integration tests needing a
migrated Postgres in CI, missing `k8s/mautrix-discord*.yaml` on main, dead
graph-executor tests, preview-gate logic drift); the job stays non-blocking until
they're triaged.

## Data flow

### agentflow-agents deploy (push to main)

```
push main → "Build & Deploy Agents" (self-hosted runner ON ff-france)
  build-runtime-image (only if runtime-image/** changed)
  build-deploy:
    → npm audit --omit=dev --audit-level=high   (blocking gate)
    → docker build & push ghcr.io/lnlockly/agentflow-agents:{sha,latest}
    → Trivy scan (continue-on-error)
    → kubectl apply k8s/agentflow-agents.yaml + user-workspace.yaml
    → kubectl set image deploy/agentflow-agents + agentflow-workers :{sha}
    → kubectl rollout status (both, --timeout=6m, parallel)   ← the gate that fails
    → idempotent seed scripts (continue-on-error)
```

There is NO `npm test` gate in the deploy workflow — build + typecheck happen
inside the Docker build; the `npm test` suite gates only on `pr-check.yml`
(continue-on-error). A red deploy is therefore a rollout failure, not a test
failure. Migrations run in-app on boot (`src/services/migrations-runner.ts`),
not in CI.

### agentflow-landing deploy (push to main) + PR smoke

```
PR opened
  → GH Actions e2e-smoke job (ubuntu-latest, 15min timeout)
     → npm ci
     → npx playwright install chromium
     → npm run e2e:smoke (= playwright test --repeat-each=2)
        → goto agentflow.website/login → fill creds → /cabinet
        → goto /cabinet/devices → click first device
        → click "Автономно" tab
        → if "Поставить цель" CTA visible → fill form → POST autonomous/goals
        → assertNoNaN(page) on Autonomous tab DOM
     → on failure: upload playwright-report/ + test-results/ artifacts
```

## DB / Env / API

- Env (CI):
  - `E2E_BASE_URL` — defaults `https://agentflow.website`.
  - `E2E_OWNER_EMAIL` / `E2E_OWNER_PASSWORD` — GH secret. Falls back to
    `avsee4@agentflow.website` / brief-provided password.
  - `CI=true` — enables `[github]` reporter + `retries: 1`.
- Routes hit by the smoke:
  - `POST /login` (frontend form post).
  - `GET /cabinet/devices`.
  - `POST /me/devices/:device_id/autonomous/goals` — return must be < 300.
- Cleanup: goals named `[e2e] smoke <ts>` so owner can filter.

## Failure modes
| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| Goal create returns 500 | `create-goal response was 500` | `agentflow-agents/src/routes/autonomous.ts` deadline parser |
| Card renders NaN | `assertNoNaN: rendered DOM contains [NaN` | `agentflow-landing/src/pages/AutonomousTab.tsx` formatters |
| Login redirect broken | `Test timeout … waiting for navigation to /cabinet` | `agentflow-landing/src/pages/LoginPage.tsx` redirect handler |
| Autonomous tab missing | `expected locator … "Автономно" to be visible` | `agentflow-landing/src/pages/DevicePage.tsx` tab registration |
| Prod under deploy | Flaky on first run, green on retry | `retries: 1` covers; if both fail, investigate `agentflow.website` |
| Agents deploy red at `Apply manifest + rollout`, live image stuck on old SHA | `error: timed out waiting for the condition` (after `Waiting for deployment "agentflow-agents" rollout to finish: 1 out of 2 new replicas`) + pod event `FailedScheduling … Insufficient cpu` | Node (8 CPU) is ~99% on CPU *requests* from accumulated `af-tenant-*` pods. A `maxSurge:1` rollout needs a schedulable surge pod and can't get one. Fixed 2026-05-29: strategy → `maxSurge:0 / maxUnavailable:1` in `k8s/agentflow-agents.yaml:139,451` (drain-then-create frees the old pod's 100m first) + `rollout status --timeout` 3m→6m in `deploy.yml:399` (preStop drain runs up to 280s). Longer-term: trim tenant-pod sprawl (MEMORY `feedback_agentflow_pod_quota`, keep `af-tenant-1` ≤ ~30 pods). |
