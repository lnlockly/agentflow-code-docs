# OpenCode installer + LLM gateway integration

## TL;DR

Two MCP tools land on the desktop daemon: `computer.opencode.install` (downloads
the `sst/opencode` release archive matching the host OS+arch into
`~/.agentflow/bin/opencode`) and `computer.opencode.patch_config` (writes/merges
`~/.config/opencode/opencode.json` so OpenCode talks to AgentFlow's public LLM
facade at `https://agentflow.website/_agents/llm/v1`). Users get a third-party
coding assistant they already know, but billed through their AgentFlow balance
via the existing `public-llm-billing` pipeline.

The patched config registers two providers — `agentflow` (Anthropic-format,
backs Claude models) and `agentflow-openai` (OpenAI-compatible, backs GPT
models) — so `opencode` can pick either family while routing through the same
facade. Existing user providers (openrouter, anthropic upstream, MCP servers
like Pencil) are preserved verbatim.

## Data flow

```
LLM / cabinet
    │ "install OpenCode and wire it to AgentFlow"
    ▼
ToolExecutor.execute("opencode_install", {})
    │ urllib.urlopen(api.github.com/repos/sst/opencode/releases/latest)
    │ pick asset by (os_slug, arch_slug)
    │ urllib.urlopen(asset.browser_download_url) → tempfile
    │ zipfile.extractall | tarfile.extractall(filter="data") → tempdir
    │ shutil.move(extracted/opencode → ~/.agentflow/bin/opencode)
    │ chmod +x  (Unix)
    ▼ {ok, version, binary_path, bytes, asset}

ToolExecutor.execute("opencode_patch_config", {api_key?})
    │ api_key := args.api_key OR AFClient._key OR auth.json
    │ read existing ~/.config/opencode/opencode.json (or empty)
    │ provider["agentflow"] = {npm:@ai-sdk/anthropic, baseURL:.../llm/v1, apiKey}
    │ provider["agentflow-openai"] = {npm:@ai-sdk/openai-compatible, baseURL:.../llm/v1, apiKey}
    │ model := "agentflow/claude-opus-4-7" (only if empty or already agentflow*)
    │ atomic write via .json.tmp + replace
    ▼ {ok, config_path, provider, model, base_url}

opencode run "hello" --model agentflow/claude-haiku-4-5
    │ @ai-sdk/anthropic builds POST https://agentflow.website/_agents/llm/v1/messages
    │   headers: x-api-key: af_live_...
    ▼
public-llm.ts authGate → validateApiKey → exceededSpendCap check
    │ pickUpstreamForAnthropicRequest("claude-haiku-4-5")
    ▼
east-api-3 proxy (anthropic-compat) → real Claude
    │ stream tokens back through teeSseWithObserver
    │ recordUsage({key, endpoint, model, tokensIn, tokensOut})
    ▼
SSE stream to opencode TUI
```

## DB / Env / API

**Daemon:**
- No new env vars.
- New paths: `~/.agentflow/bin/opencode[.exe]` (binary), `~/.config/opencode/opencode.json` (Unix config), `%APPDATA%\opencode\opencode.json` (Windows config).
- API key read order: explicit `api_key` arg → `AFClient._key` → `auth.json:api_key`.

**Backend:** no changes. Existing `/llm/v1/chat/completions` + `/llm/v1/messages` carry all traffic — facade was shipped before this PR (see `routes/public-llm.ts`).

**MCP tools:**
- `computer.opencode.install({version?: str = "latest"})` → `{ok, version, binary_path, bytes, asset, os, arch}`
- `computer.opencode.patch_config({api_key?: str, base_url?: str, model?: str})` → `{ok, config_path, provider, model, base_url}`
- `computer.opencode.status({})` → `{binary_path, binary_present, config_path, config_present}`

**LLM-visible tool names** (driver/desktop_tools.py): `opencode_install`, `opencode_patch_config`, `opencode_status`.

## Failure modes

| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| Install fails with `unsupported_os:` or `unsupported_arch:` | `unsupported_os` / `unsupported_arch` | host runs FreeBSD / 32-bit / exotic CPU — not supported by upstream releases. |
| Install fails with `no_matching_asset` | `no_matching_asset for darwin/arm64` | sst/opencode dropped a target in the new release — patch `ASSET_PREFERENCE` in `tools/opencode_installer.py:51` with the new filename. |
| Install hangs > 2 min | none — synchronous `urlopen(timeout=120)` | network egress blocked or GitHub LFS slow; tool returns `download_failed` after 120s. |
| `binary_not_found_in_archive` | `binary_not_found_in_archive: opencode-*.zip` | sst/opencode changed archive layout (e.g. nested `bin/`) — extend the `rglob("*")` walk in `_extract`. |
| `opencode run` returns 401 from the gateway | `recordUsage` skipped, response body `{"error":{"type":"authentication_error"}}` | rotate `af_live_*` key in `~/.config/opencode/opencode.json` (run `opencode_patch_config` again with fresh key). |
| `opencode run` returns 402 spend cap | `Spend cap reached: $X.XX of $Y.YY` | top up balance in cabinet OR raise cap in `users.budget_cents_remaining`. |
| Claude model errors `uses the Anthropic wire format. Call POST /v1/messages instead.` | `invalid_request_error` | user has `model: "agentflow/claude-*"` but provider entry uses `@ai-sdk/openai-compatible` — re-run `patch_opencode_config` to restore the dual-provider setup. |
| GPT-5.4 returns `insufficient_user_quota` | `预扣费额度失败` from upstream (designapi) | account balance below per-request reserve; top up or pick a cheaper model. |
| Patch destroys an existing user provider | none — overwrite | patcher only writes `agentflow` and `agentflow-openai` keys; other providers are preserved. If you see loss, check that `_read_existing_config` returned `{}` due to corrupt JSON — the corrupt file is saved as `opencode.json.broken` next to the new one. |
