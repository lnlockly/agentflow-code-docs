# Kwork freelance conveyor (last mile)

## TL;DR

Three existing pieces — the [kwork-connector](/subsystems/kwork-connector), the
[proxied browser-login](/subsystems/proxied-browser-login), and the freelance
conveyor (order → task → launch) — are wired into one loop. (1) `POST
/me/integrations/kwork/relogin` mints a fresh kwork session inside an in-pod
chromium behind the owner's sticky NodeMaven residential exit IP, and `…/relogin/
verify` proves the inbox reads back non-empty entities on that IP. (2) A kwork
order becomes a Plane task and `launchAgentOnTask` spawns a coder run on the
order brief in a project pod (the existing conveyor). (3) The finished run's reply
to the CLIENT is `arm()`-ed into the generic approval queue — the owner confirms
it before any message leaves to the client. Nothing client-facing auto-sends.

## Data flow

```
RE-LOGIN (mint on the residential exit IP)
  POST /me/integrations/kwork/relogin
    → startRelogin → ProxiedBrowserLoginService.startLogin(owner,'kwork')
        (in-pod chromium behind sticky NodeMaven residential proxy → kwork login)
    → { session_id, login_url, proxied, stream }
        FE drives the EXISTING browser-login screenshot/input/confirm endpoints
        → on logged-in signal the browser-login service captures cookies into the
          user_credentials vault ON the residential IP (proxy_ref in meta)
  POST /me/integrations/kwork/relogin/verify
    → verifyRelogin → getConnector('kwork').listEntities('dialogs')  ← same IP
        entityCount > 0  → { verified:true }   (the session is valid on this IP)
        entityCount == 0 → { verified:false }  (still logged out / wrong IP / CAPTCHA)

ORDER → AGENT → APPROVAL-GATED DELIVERY
  kwork order  ─POST /me/freelance/tasks─▶ orderToTask → Plane issue + linkage row
               ─POST /me/freelance/tasks/:id/launch─▶ launchAgentOnTask
                   → spawnRun (POST /me/projects + /approve) → coder run in a pod
                   → run_status='running'
  run finishes ─POST /me/freelance/tasks/:id/deliver { reply }─▶ queueDelivery
                   → connector.buildAction({type:'send', entityId:<dialog>}) (dryRun)
                   → arm(owner, {action})  → entity_approval_queue (status='armed')
                   → 202 { approval_id }            ← NOTHING sent to the client yet
  owner        ─POST /me/approvals/:id/confirm─▶ confirm (atomic single-use claim)
                   → getConnector('kwork').executeAction('send') ONCE → send_message
```

## DB / Env / API

- **Tables:** `fl_conveyor_tasks` (the conveyor linkage, UNIQUE `(connector, external_id)`); `user_credentials` (vault the relogin captures into, sticky proxy ref in `meta.proxy_ref`); `entity_approval_queue` (the armed reply awaiting owner confirm).
- **Env:** `NODEMAVEN_PROXY_USER` / `NODEMAVEN_PROXY_PASS` / `NODEMAVEN_PROXY_GATEWAY` (residential proxy; unset ⇒ `proxied:false` + `warning:'no_residential_proxy'`); `FF_FREELANCE=1` (conveyor surface); `INTERNAL_API_SECRET`; `DATABASE_URL`.
- **Routes (owner-auth via `requireSession`):**
  - `POST /me/integrations/kwork/relogin` → `{ session_id, login_url, proxied, stream, warning? }`
  - `POST /me/integrations/kwork/relogin/verify` → `{ verified, entity_count, sample }`
  - `POST /me/freelance/tasks` → order → task (idempotent)
  - `POST /me/freelance/tasks/:taskId/launch` → spawn a coder run
  - `POST /me/freelance/tasks/:taskId/deliver { reply }` → `202 { approval_id }` (gated)
  - `POST /me/approvals/:id/confirm` → ships the reply once (existing approval queue)
- **Connector contract:** the relogin verify and the delivery both resolve through the connector registry (`getConnector('kwork')`). Adding a second freelance source (vk, avito) is a connector row, never an `if (connector === …)` branch in the conveyor.

## Failure modes

| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| relogin starts but mints on the pod IP | `no_residential_proxy` (warning in the start response) / `proxy_unconfigured` | NodeMaven env unset — `services/proxied-browser-login.ts:476`; set the proxy creds |
| relogin verify always `verified:false` despite login | `reauth_required` from `listEntities` | cookies minted on the wrong IP / behind CAPTCHA — re-drive the browser-login on the residential proxy (`kwork-relogin.ts:88`) |
| relogin start 503 | `browser_runtime_unavailable` | the in-pod chromium runtime is down — `proxied-browser-login.ts` driver / `BROWSER_RUNTIME_WS` |
| relogin start 502 | `proxy_auth_failed` | the residential proxy refused the tunnel — check NodeMaven creds / sticky sid |
| deliver 409 `connector_not_registered` | `connector_not_registered` | the order's connector has no registry row — `connector-core/bootstrap.ts` |
| deliver 400 `empty_reply` / `missing_target` | `empty_reply` / `missing_target` | the run produced no reply text, or the conveyor row has no dialog id (the kwork order's `external_id`) |
| deliver 400 `draft_not_dry_run` | `draft_not_dry_run` | a connector returned a live action from `buildAction` — drafts MUST be `dryRun:true` (`conveyor-delivery.ts`) |
| reply sent without owner confirm | (must not happen — guarded) the deliver path only `arm()`s | `conveyor-delivery.ts:94` never calls `executeAction`; only `confirm` does |
