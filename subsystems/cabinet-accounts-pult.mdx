# Cabinet «Пульт аккаунтов»

## TL;DR
`/cabinet/accounts` is a three-zone command center (288 / 1fr / 360) for the
owner's connected social accounts, sibling to `/projects` and `/cabinet/agents`.
LEFT lists accounts (grouped by platform) with a group-pill switcher, CENTER is
a **Просмотр / Команда** toggle (Просмотр = entity browser: data-driven kind nav
→ entity list → real message thread; Команда = the SSE command composer), and
RIGHT defaults to **«Очередь»** — the generic approval feed where every armed
action is confirmed/edited/rejected before it fires (plus Лог / Автоматизации /
Интеграции tabs). The cross-account **«Общий пульт»** at `/cabinet/accounts/all`
aggregates that queue across every account with one command bar. The page is
MCP-first/generic — it never branches on a platform string — and every backend
read degrades to empty / «скоро» so it renders before the agents-service v2
endpoints ship. Wave-1 T1.7/T1.8 (PR `feat/pult-v2-wired`).

## Data flow
```
LEFT   GET /me/accounts -> Account[] grouped by platform (PLATFORM_META map)
         GroupsPills (deriveGroups) -> narrow list by status (Wave-2: account_groups)
         + «+ Подключить» -> in-pult ConnectDrawer

CENTER tab=Просмотр -> EntityBrowser
           EntityKindNav (account.entityKinds | registry) -> select kind
           GET /me/accounts/:id/entities?kind= (getEntities) -> EntityList
           open dialog -> getThread (GET …/entities/:eid/messages) -> bubbles
           reply -> draft -> approve gate (same DraftCard)
       tab=Команда -> CommandCenter -> POST /me/accounts/:id/command (SSE)

RIGHT  tab=Очередь -> GET /me/approvals?account_id= -> ApprovalItem[]
           card: target + body + schedule/affects
           Подтвердить -> POST /me/approvals/:id/confirm (atomic claim -> execute)
           Изменить    -> POST /me/approvals/:id/edit {payload}  (re-arm)
           Отклонить   -> POST /me/approvals/:id/reject
           «Подтвердить все» -> POST /me/approvals/confirm-all {ids}
       tab=log/auto/integrations -> existing panels

GENERAL /cabinet/accounts/all -> command bar (streamAccountCommand 'all')
         + ApprovalFeed (no accountId) = cross-account queue
```

## DB / Env / API
- Routes (agents service, port 4100, all `requireSession`):
  - `GET /me/accounts`
  - `GET /me/accounts/:id/entities?kind=` · `GET /me/accounts/:id/entities/:eid/messages`
  - `GET /me/approvals?status=armed&account_id=` (NEW — sibling backend branch)
  - `POST /me/approvals/:id/{confirm,edit,reject}` · `POST /me/approvals/confirm-all` (NEW)
  - `GET /me/accounts/actions?account_id=&limit=`
  - `POST /me/accounts/:accountId/command` (SSE)
  - `POST /me/accounts/:accountId/command/approve`
- New normalized shape: `ApprovalItem { id, platform, account_ref, agent_id,
  action_type, entity_id, group_id, status, preview{title,target,body,
  scheduled_at,affects}, payload, scheduled_at, external_id, error_message,
  created_at, executed_at }` (01-ARCH §1). `Account.entityKinds?` folds the
  platform def's `EntityKind[]` so the kind nav is data-driven.
- Theme: T1.8 retired acid lime — `--af-accent: #4cb782` (+ `--af-accent-soft`,
  `--af-accent-tint`, `--af-on-accent`) in `dark-tokens.css`; `--acid: #4cb782`
  in `globals.css`. Stray hex literals in unrelated subsystems
  (launchpad/token-pages/games/studio/admin/decks) still read `#A6F25C`/`#d4ff00`
  — a follow-up brand-wide sweep, out of scope for this Пульт PR (the token flip
  already recolors every `var(--af-accent)`/`var(--acid)` consumer).
- Env (frontend): `VITE_AGENTS_URL` (agents base), `VITE_API_URL` (auth base).
- Normalized shapes: `Account { id, platform, account_id, handle, display_name,
  status, status_detail, avatar_hint, default }`; `AccountAction { id, platform,
  account_ref, kind, target, status, detail, created_at }`.
- Model catalog: public `GET /llm/v1/models` (via `fetchEnabledModels`); «flow»
  is filtered from that list and re-added by the picker as the auto-router head.

## Failure modes
| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| LEFT zone empty though accounts exist | `getAccounts` returns `[]` on 404/501 | wire `GET /me/accounts` aggregator |
| Approval feed empty though actions armed | `getApprovals` returns `[]` on 404/501/0 | deploy `GET /me/approvals` (sibling backend branch) |
| Подтвердить shows no effect | `confirmApproval` -> `not_available` | deploy `POST /me/approvals/:id/confirm` |
| «Подтвердить все» no-ops | `confirmAll` -> `{confirmed:0,failed:0}` | deploy `POST /me/approvals/confirm-all` |
| Browse «Просмотр» list empty | `getEntities` returns `[]` | deploy `GET /me/accounts/:id/entities` |
| Group pills missing | `deriveGroups` returns 1 group (only «Все») | expected until ≥2 distinct account statuses / Wave-2 `account_groups` |
| Composer shows «скоро» state | `command_not_available` SSE error | deploy `POST /me/accounts/:id/command` |
