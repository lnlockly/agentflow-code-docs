# Cabinet «Пульт аккаунтов»

## TL;DR
`/cabinet/accounts` is a three-zone command center (288 / 1fr / 360) for the
owner's connected social accounts, sibling to `/projects` and `/cabinet/agents`.
LEFT lists accounts across platforms, CENTER is a chat composer (neural-net
model picker + SSE command stream + draft-approve cards), RIGHT has «Лог
действий» (unified action feed) and a DESIGN-ONLY «Автоматизации» tab. The page
is MCP-first/generic — it never branches on a specific platform string — and
every backend read degrades to empty / «скоро» so it renders before the
agents-service endpoints ship.

## Data flow
```
LEFT   GET /me/accounts -> Account[] grouped by platform (PLATFORM_META map)
         + «+ Подключить» -> /account/integrations/telegram | .../kwork/connect

CENTER composer.send -> POST /me/accounts/:accountId/command (SSE)
         model = picker (flow -> null = auto-router)
         events: thread | text | thought | tool_use | draft | action_done | error | done
         draft card «Отправить» -> POST /me/accounts/:accountId/command/approve {draft_id}

RIGHT  tab=log  -> GET /me/accounts/actions?account_id= -> timeline (status-coloured nodes)
       tab=auto -> DESIGN-ONLY static cards + local-state toggles (no engine)
```

## Command-flow: draft → armed approval queue (#656)

A side-effecting command (DM, post, gig respond) never sends straight from the
composer. The backend arms it as an `armed` row in `entity_approval_queue` and
emits a `draft` SSE frame. CommandCenter handles that frame by both rendering an
inline `DraftCard` AND **invalidating the approvals query** so the right-rail
Queue refreshes without waiting for its 8s poll:

```
composer.send ─POST /me/accounts/:id/command (SSE)─▶ backend arms draft
   SSE 'draft' frame ─▶ CommandCenter (case 'draft', CommandCenter.tsx:107)
      ├─ cur.drafts.push(evt.draft)                       (inline DraftCard)
      └─ qc.invalidateQueries(approvalsKey(account.id))   (CommandCenter.tsx:112)
         qc.invalidateQueries(approvalsKey(null))         (General feed)
            ▼
   ApprovalFeed useQuery(['accounts-pult-approvals', id]) refetches immediately
      → the armed card appears in the Queue for «Подтвердить»
   SSE 'done' frame ─▶ end-of-turn reconcile invalidation (CommandCenter.tsx:139)
      (covers a draft armed WITHOUT a discrete 'draft' frame reaching the client)
```

Two #656 polish rules sit alongside the refresh:
- **No empty command bubbles** — a chat bubble renders only when the turn has
  real text (`m.text.trim().length > 0`, `CommandCenter.tsx:201`); the history
  replay filter (`CommandCenter.tsx:62`) drops tool-only rows with no text and
  no drafts so a reload never replays a blank 🪿 bubble.
- The shared key `approvalsKey(accountId)` = `['accounts-pult-approvals',
  accountId]`; `accountId=null` is the cross-account General feed. CommandCenter
  invalidates BOTH so a draft armed in a per-account view also lands in General.

The armed → confirm execution itself lives in the backend
[approval-queue](/subsystems/approval-queue) (`POST /me/approvals/:id/confirm`).

## DB / Env / API
- Routes (agents service, port 4100, all `requireSession`):
  - `GET /me/accounts`
  - `GET /me/accounts/actions?account_id=&limit=`
  - `POST /me/accounts/:accountId/command` (SSE)
  - `POST /me/accounts/:accountId/command/approve`
- Env (frontend): `VITE_AGENTS_URL` (agents base), `VITE_API_URL` (auth base).
- Normalized shapes: `Account { id, platform, account_id, handle, display_name,
  status, status_detail, avatar_hint, default }`; `AccountAction { id, platform,
  account_ref, kind, target, status, detail, created_at }`.
- Model catalog: public `GET /llm/v1/models` (via `fetchEnabledModels`); «flow»
  is filtered from that list and re-added by the picker as the auto-router head.

## Failure modes
| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| LEFT zone empty though accounts exist | `getAccounts` returns `[]` on 404/501 | wire `GET /me/accounts` aggregator |
| Composer shows «скоро» state | `command_not_available` SSE error | deploy `POST /me/accounts/:id/command` |
| Draft «Отправить» shows unavailable notice | `approveAccountCommand` -> `not_available` | deploy `.../command/approve` |
| Action log empty | `getAccountActions` returns `[]` | deploy `GET /me/accounts/actions` (unified `account_action_log`) |
| Kwork gig/exchange detail shows raw `snake_case` keys | `EntityDetail` dumped `meta` verbatim | fixed by `humanizeKey`/`formatMetaValue` in `browse/DialogView.tsx` |
| Armed draft doesn't appear in the Queue until the 8s poll | missing `invalidateQueries(approvalsKey(...))` on the `draft` frame | `src/components/accounts/CommandCenter.tsx:112` (#656) |
| Blank 🪿 bubble replays after reload | tool-only history row passed the replay filter | `src/components/accounts/CommandCenter.tsx:62` (#656 — keep only text/draft/user turns) |
