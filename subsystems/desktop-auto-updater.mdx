# Desktop Auto-Updater (no GitHub API)

## TL;DR
The PyInstaller-frozen `agentflow-desktop` daemon checks for a new release by following the public `releases/latest` HTTP redirect (which exposes the tag in its `Location`), then downloads a published `SHA256SUMS` asset to verify the installer digest. No authenticated GitHub API call, so the updater survives un-authenticated daemons behind shared/corporate NAT IPs. Runs only when frozen; doubles the poll interval on every failed probe (cap 24h) and resets to the configured interval after a clean probe.

**v0.5.0** — release adds a second asset `agentflow-tray.exe` next to the existing installer. The updater still watches `agentflow-desktop-setup.exe` for the version probe; the tray binary updates lock-step because the setup wizard re-runs after the user reboots and refreshes both .exes from the same release. Sharp edge: a tray that's already running when the daemon hot-swaps stays on the old binary until next logon. Documented intentionally for v0.5.0; the auto-respawn path is on the v0.5.x backlog.

## Data flow

```
desktop daemon (frozen .exe / app)            github.com (public, no API)
       │
       │  every AF_UPDATE_INTERVAL_MIN (default 30)
       ▼
start_in_background → check_now()
       │
       │  fetch_latest_release()
       ├──► GET /releases/latest  (follow redirect)
       │◄── 302 Location: /releases/tag/v0.4.5
       │  parse tag with regex /releases/tag/([^/?#]+)
       │
       ├──► GET /releases/latest/download/SHA256SUMS
       │◄── 200 "<hex>  agentflow-desktop-setup.exe"
       │  pluck hex, rewrite as "sha256: <hex>" for _sha256_from_body
       │
       │  _is_newer(remote, local)? _is_safe_major(remote)?
       │  → status="skipped" if major bump
       │  → status="current"  if not newer
       │
       ├──► GET /releases/latest/download/agentflow-desktop-setup.exe
       │◄── 200 (binary)
       │  sha256_of_file vs expected → mismatch → status="error"
       │
       │  copy to <exe_dir>/.<ASSET>.staged
       │  _apply_update():
       │    unix:    os.replace + os.execv (same PID, new binary)
       │    windows: drop .new.exe + update.bat, sys.exit(0)
       ▼
status="applied" — caller logs reason, loop resets backoff
```

## DB / Env / API

- **No DB.** Pure HTTP + filesystem.
- **Env**:
  - `AF_UPDATE_INTERVAL_MIN` — integer minutes between probes. `0` disables, default `30`. Backoff caps at `MAX_INTERVAL_MIN = 24 * 60`.
- **External endpoints** (all unauthenticated, no API rate-limit):
  - `GET https://github.com/lnlockly/agentflow-computer-mcp/releases/latest` — redirect probe
  - `GET https://github.com/lnlockly/agentflow-computer-mcp/releases/latest/download/SHA256SUMS`
  - `GET https://github.com/lnlockly/agentflow-computer-mcp/releases/latest/download/agentflow-desktop-setup.exe`
- **Release contract** — every release MUST publish:
  - asset `agentflow-desktop-setup.exe` (or the platform-equivalent the bundle was built with)
  - asset `SHA256SUMS` containing a line `<64-hex>  agentflow-desktop-setup.exe`
  - tag matching `v?<major>.<minor>.<patch>`; `MAX_MAJOR=0` blocks `v1.x.x` until the constant is bumped by a human
- **Injection points** (for the smoke test) — `check_now(fetch=..., downloader=..., apply=...)`. The CI smoke replaces `fetch` with a stub so the test never touches the network.

## Failure modes

| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| `SHA256SUMS` asset missing from a release | `auto-update: SHA256SUMS unavailable` | `agentflow-computer-mcp/src/agentflow_computer_mcp/auto_updater.py:168` — fallback is `body=""`, which trips the next gate `release {tag} has no sha256 in body — refusing blind download` |
| Release tag URL malformed or unparseable | exception `could not parse tag from redirect URL` | `auto_updater.py:161` — raise `UpdateError`; surfaces as `status="error"` |
| Downloaded asset hash mismatches `SHA256SUMS` | `sha256 mismatch: expected` (logged via `log.error("auto-update: %s", status["reason"])`) | `auto_updater.py:362` — file is discarded, no swap, daemon keeps running |
| Probe crashed inside background loop | `auto-update: probe crashed:` | `auto_updater.py:429` — exception swallowed, delay doubles, loop continues |
| Probe returned status=error (network or http) | `auto-update:` followed by reason text from `result["reason"]` | `auto_updater.py:422` — typical `github fetch failed:` or `download failed:` |
| Update silently disabled at start | `auto-update: disabled via AF_UPDATE_INTERVAL_MIN=0` | `auto_updater.py:408` — env override; no probes spawn |
| Update skipped because we're running source | `auto-update: running from source, polling disabled` | `auto_updater.py:411` — `_is_frozen()` returned `False`; `allow_unfrozen=True` overrides for tests |
| Refusing a major-version jump | reason text `refusing major bump <local> → <remote>` | `auto_updater.py:321` — bump `MAX_MAJOR` constant + ship a release notes link, then re-cut the build |
| Windows swap left a stale sidecar | leftover `agentflow-desktop.new.exe` next to current `.exe` | `auto_updater.py:222` — the next `_replace_windows` deletes it with `contextlib.suppress(FileNotFoundError)` |
| Unix re-exec didn't restart with new binary | no log line — the process just died | `auto_updater.py:204` — `os.execv` raises if the binary has lost +x; `_replace_unix` `chmod 0o755` before swap, verify perms on the staged file |

## Why no GitHub API

The previous implementation hit `api.github.com/repos/<o>/<r>/releases/latest` and parsed a JSON `tag_name`. On shared corporate IPs and multi-user homes the unauthenticated rate limit (60/h) trips before noon. The redirect path uses the same public endpoints a browser would — no rate limit applies — and the digest verification moves from "trust release body" to "trust a deterministically-generated `SHA256SUMS` asset that's signed by the same build pipeline".
