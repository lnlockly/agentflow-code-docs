# Pod Pre-Warm Pool

## TL;DR

Per tenant (`af-tenant-<userId>` vcluster) we keep `TARGET_WARM_COUNT=3` idle pods running the project image with `/workspace` already scaffolded. When the user approves a project the code-exec MCP attempts to claim a warm pod via a k8s label patch; on success the StatefulSet provision skips image-pull because the layer is cached on the same node. State lives in pod labels (`agentflow-pool=warm`, `agentflow-claimed=false|true`) — no DB table needed. Refill cron in `pingers/pod-pool-refill.ts` tops up the pool every 60s. Gated by `POD_POOL_ENABLED=1` (production-on as of 2026-05-14).

## Data flow

```
Boot
  server.ts → setInterval(60s, runPodPoolRefillTick)

Refill tick (every 60s)
  pingers/pod-pool-refill.ts
    SELECT id FROM users WHERE tenant_status='ready' AND tenant_kubeconfig_sealed IS NOT NULL
      ↓ for each tenant id
    loadTenantKubeconfig(ownerUserId)                    helpers/tenant.ts
      ↓
    sweepStalePods(kubeconfigYaml)                       → delete agentflow-pool=warm, phase!=Running
    countWarmPods(kubeconfigYaml)
      ↓ if count < 3
    spawnWarmPod() × (3 - count) sequentially            → kubectl apply warm Pod, wait 60s ready

Project approve / create_project
  code-exec/index.ts:160
    claimWarmPod(kubeconfig, tenantNs, projectId)
      ├─ kubectl get pods -l agentflow-pool=warm,agentflow-claimed=false,phase=Running
      │     ↓ empty → return null → caller does cold StatefulSet apply
      │     ↓ non-empty → pick first candidate
      ├─ kubectl label pod <name> agentflow-claimed=true agentflow-project=<id> --overwrite
      │     ↓ conflict → retry with next candidate
      │     ↓ success
      ├─ delete claimed pod (image is now cached on the same node)
      ├─ kubectl apply StatefulSet (image pulled from local cache, <5s)
      └─ spawnWarmPodAsync() — refill pool depth in background

Project destroy
  code-exec/index.ts:398
    if pod has agentflow-claimed=true:
      returnPodToPool(kubeconfig, podName)
        ├─ kubectl exec — rm -rf /workspace/* /workspace/.[^.]*
        ├─ kubectl label pod <name> agentflow-claimed=false agentflow-project- --overwrite
        └─ pod is now back in the warm pool, claimable by next create_project
```

## DB / Env / API

- **Tables:** none (state lives in pod labels for atomic claim semantics — no DB roundtrip on hot path).
- **Env:**
  - `POD_POOL_ENABLED` — feature flag, must equal `"1"` to activate.
  - `POD_POOL_TARGET_WARM` — pool depth per tenant, default `3`.
- **K8s labels (per warm pod, default ns of `af-tenant-<userId>`):**
  - `agentflow-pool=warm`
  - `agentflow-claimed=false|true`
  - `agentflow-tenant=af-tenant-<userId>`
  - `agentflow-project=<projectId>` (only when claimed)
- **Routes / MCP tools:** none — the pool is internal to `code-exec` MCP `create_project` / `destroy_project`.

## Pool size & quota

Per tenant, 3 warm pods cost `3 × 25m CPU + 3 × 128Mi RAM = 75m / 384Mi` requests. With 13 tenants the cluster headroom is ~975m / 5Gi — well within the ff-france node budget. Warm pods are `emptyDir` (no PVC), so they don't consume PVC quota.

Tune `POD_POOL_TARGET_WARM` per tenant later via the existing per-user `feature_flags` mechanism if the global value over-provisions for low-churn accounts.

## Failure modes

| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| Approve still cold-starts | `pod-pool: pool empty, cold path` | `pod-pool.ts:186` — refill cron isn't keeping up or `POD_POOL_ENABLED` is off. Check `kubectl -n franchise-factory get deploy/agentflow-agents -o yaml \| grep POD_POOL_ENABLED`. |
| Two approvals race for same warm pod | `pod-pool: claim race, trying next` | `pod-pool.ts:212` — expected. The optimistic label patch picks the first writer; losers fall through to the next candidate or cold path. No action. |
| Warm pods never appear | `pod-pool: spawn apply failed` / `pod-pool: spawn wait failed` | `pod-pool.ts:260` / `pod-pool.ts:277` — usually tenant ResourceQuota (`feedback_agentflow_pod_quota.md`). Lift via `expand-quota` internal endpoint. |
| Pool empty even though refill ran | `pod-pool-refill: kubeconfig unavailable` | `pod-pool-refill.ts:70` — `tenant_kubeconfig_sealed` missing for that user. Their vcluster wasn't provisioned cleanly; rerun tenant provisioning. |
| Warm pod stuck in Failed phase | `pod-pool: swept stale warm pods` | `pod-pool.ts:392` — sweep step runs before count step, so next tick respawns. Investigate the Failed reason via `kubectl describe pod warm-pod-<hex>`. |
| Returned pod still has leftover files | `pod-pool: workspace wipe failed, abandoning pod` | `pod-pool.ts:337` — `returnPodToPool` deliberately refuses to recycle a pod it couldn't wipe; pod is left for the next sweep to clean. No data leak between projects. |

## Operational commands

Verify pool is active in production:

```bash
# Confirm env flag is on
kubectl -n franchise-factory exec deploy/agentflow-agents -- env | grep POD_POOL

# Count warm pods in a tenant vcluster (replace 5 with the user id)
kubectl --kubeconfig <(./scripts/dump-tenant-kubeconfig.sh 5) -n default get pods -l agentflow-pool=warm

# Force a refill pass without waiting 60s
kubectl -n franchise-factory exec deploy/agentflow-agents -- node -e \
  "require('./dist/services/pingers/pod-pool-refill.js').runPodPoolRefillTick()"

# Disable the pool without redeploy (rollback path)
kubectl -n franchise-factory set env deploy/agentflow-agents POD_POOL_ENABLED=0
```
