# Projects ↔ Plane Task Binding

## TL;DR
Every AgentFlow project binds to one [Plane](/subsystems/plane-task-manager)
project — its task board, read/written by both the owner (session/owner-key
routes) and the project's agents (project-scoped tasks-MCP tools). The bind is
lazy + idempotent: on first task access a Plane project is created-or-reused and
its UUID cached on `projects.plane_project_id`. AgentFlow itself is now a project
row (`is_platform=true`, owner 1) so `/me/projects` lists the platform and the
owner opens it in the standalone Cloud IDE.

## Data flow
```
Owner (session / owner-key)            Agent (Eliza runtime, MCP)
   │                                      │  tasks MCP mount carries ?project=<af_id>
   ▼                                      ▼
GET/POST/PATCH /me/projects/:id/tasks   list/create/update_project_task
   │                                      │
   └──────────────┬───────────────────────┘
                  ▼
   ensureProjectPlaneBinding(projectId)
     plane_project_id set? → return it
     else create-or-reuse Plane project → cache UUID on projects row
                  ▼
   me-apps-tasks Plane client → Plane REST (tasks.agentflow.website)
     listTaskIssues (grouped by state) / createTaskIssue / updateTaskIssue
```
AgentFlow-as-a-project: the `is_platform=true` row (owner 1) lists in
`/me/projects`; its `/ide` answer returns `{ ready:true, ideUrl: CLOUD_IDE_URL }`
(the standalone code-server, repos at `/home/coder/workspace`) since it has no
per-project pod.

## DB / Env / API
- Tables: `projects` (new column `plane_project_id text`, nullable).
- Env: `PLANE_API_BASE`, `PLANE_API_TOKEN`, `PLANE_WORKSPACE` (same as the tasks
  MCP); `CLOUD_IDE_URL` (default `https://ide.agentflow.website`).
- Routes: `GET /me/projects/:id/tasks`, `POST /me/projects/:id/tasks`,
  `PATCH /me/projects/:id/tasks/:taskId` (owner/team auth via `loadOwnedProject`).
- MCP tools: `list_project_tasks`, `create_project_task`, `update_project_task`
  (project-scoped, mount `?project=<af_id>`); the generic
  `list_tasks`/`create_task`/`update_task` stay workspace-wide.

## Failure modes
| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| Tasks routes return `{configured:false}` | Plane env unset | set `PLANE_*` in the agents secret |
| Agent tool refuses | `project_scope_required` | mount the tasks MCP with `?project=<id>` for that agent |
| Plane project duplicated on re-bind | (none — reuse-by-name) | `findTaskProjectByName` in `services/project-tasks-binding.ts` |
| Platform project missing from `/me/projects` | row absent for owner 1 | `ensurePlatformProjectForOwner` + migration `0091` |
