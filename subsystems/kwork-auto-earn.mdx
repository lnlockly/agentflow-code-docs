# Kwork auto-earn DM loop

## TL;DR
Every 30 minutes the `kwork-bid-monitor-basic` flow reads the public Kwork
wants feed, classifies each want into one of our gig kinds, writes a
per-want LLM pitch, and DMs the buyer via `/sendmessage`. Closed-inbox
buyers and low-confidence classifications get filtered BEFORE the send so
we don't burn the daily DM quota on guaranteed rejections.

## Data flow
```
cron 30m
  └─> kwork.scan_wants (list_wants @ /projects feed)
        └─> ai.classify_wants (TEXT_LARGE, 1 call per tick)
              └─> ai.draft_offer (TEXT_LARGE, 1 call per non-skip want, fan-out 4)
                    └─> kwork.send_offer (closed-inbox pre-skip + conf >= 0.6, max_send=3)
                          └─> tg-bot.send_card (summary to owner bot)
```

## DB / Env / API
- Tables:
  - `kwork_action_log` — **unified per-action audit of record** (migration
    `2026-06-02a-kwork-action-log.sql`). One row per kwork-inbox tool call:
    `owner_user_id`, `account_ref`, `kind`, `target`, `status`,
    `detail_json`, `created_at`. Idx `(owner_user_id, created_at)` +
    `(owner_user_id, kind, created_at)`. Written at the `withActionLog` choke
    point regardless of trigger. `kwork_want_responses` is the conversion
    view layered on top, not the audit. **CI does NOT run migrations — apply
    `2026-06-02a` manually via the postgres pod after merge.**
  - `kwork_want_responses` — anti-double-send ledger. Unique on
    `(owner_user_id, want_id, buyer_user_id)`. Columns: `ok`, `error`,
    `pre_skipped`, `confidence` (forensics — migration
    `2026-05-23a-kwork-want-responses-forensics.sql`).
- Routes:
  - `GET /me/integrations/kwork/actions?limit=50` — read the action log
    (owner-scoped, requireSession).
  - `POST /me/integrations/kwork/start` — cabinet launch entry; ensure the
    replier agent + arm cron (owner-scoped, flow-independent).
- Env: none new. `KWORK_SESSION_JSON` continues to live in
  `project_secrets` keyed by `owner_user_id`.
- MCP tools: `kwork-inbox.list_wants`, `kwork-inbox.get_want` (now returns
  `buyer_inbox_open: boolean | null`), `kwork-inbox.send_message`,
  `kwork-inbox.list_my_kworks`.

## Failure modes
| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| Tick burns send quota on closed-inbox buyers | `pre_skipped_closed_inbox` in `kwork_want_responses.error` | `kwork-send-offer.ts:resolveBuyer` — verify `buyer_inbox_open` extractor still fires against current kwork HTML. |
| Boilerplate template instead of LLM draft | `drafts[i].text === ''` + `llm_ok=false` in `ai.draft_offer` output | `ai-draft-offer.ts:generateDraftForWant` — LLM error path; check `useModel(ModelType.TEXT_LARGE)` is healthy. |
| Low-fit pitches sent (poor reply rate) | `confidence < 0.6` rows with `ok=true` in ledger | Raise `confidence_threshold` in flow node or tighten classifier prompt in `ai-classify-wants.ts`. |
| All wants skipped (`sent_count=0`, `skipped_count=N`) | `pre_skipped_count + skipped_count === wants.length` | Expected when every buyer's inbox is closed for the tick; not a bug. |
| Sent DM contains AgentFlow brand or link | grep `kwork_want_responses` row text — any `agentflow` / `agentflow.website` substring | `ai-draft-offer.ts:stripAgentFlowMentions` — sanitiser must strip both the bare brand and the URL before send. Owner reversed promo policy 2026-05-22. |
| Sent DM opens with "Видел задачу…" / "Заметил…" / "По вашему…" recap | grep ledger text starts with `Видел` / `Заметил` / `По вашему` / `Здравствуйте, видел` | `ai-draft-offer.ts:stripRecapOpener` — extend the banned-opener regex list if a new variant slips through. Buyer already knows what they posted; recap reads as AI-generated. |
| `respond_to_want` returns `anti_bot_html` — kwork returned `<title>Технические работы</title>` on authenticated POST | grep step output for `anti_bot_html` or `shielded_paths` in flow_runs `kwork.respond_to_want` result | `kwork-inbox.ts:submitOfferViaCandidates` — every candidate (canonical `/api/offer/createoffer` + 4 legacy) was shielded. Body still contains `window.unreadDialogCount` proving session valid → it's an anti-bot rate-limit on the seller IP / profile, NOT `auth_expired`. Options: rotate egress IP (warmup-pool), slow the bid cadence, or back off until the shield window expires. |
| `respond_to_want` legacy `unexpected_response` on `/new_offer/save` (PRE-FIX 2026-05-22) | grep flow_runs output for `endpoint: "/new_offer/save"` + `"unexpected_response"` | Fixed by `kwork-inbox.ts:submitOfferViaCandidates` — handler now tries `/api/offer/createoffer` (the live Vue SPA endpoint) FIRST and only falls back to `/new_offer/save` etc. for older A/B rollouts. Old kwork form path is no longer the SPA's submit URL — bundle grep of `new-offer_*.js` confirms `axios.post('/api/offer/createoffer', formData)`. |
