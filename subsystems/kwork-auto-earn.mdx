# Kwork auto-earn DM loop

## TL;DR
Every 30 minutes the `kwork-bid-monitor-basic` flow reads the public Kwork
wants feed, classifies each want into one of our gig kinds, writes a
per-want LLM pitch, and DMs the buyer via `/sendmessage`. Closed-inbox
buyers and low-confidence classifications get filtered BEFORE the send so
we don't burn the daily DM quota on guaranteed rejections.

## Data flow
```
cron 30m
  └─> kwork.scan_wants (list_wants @ /projects feed)
        └─> ai.classify_wants (TEXT_LARGE, 1 call per tick)
              └─> ai.draft_offer (TEXT_LARGE, 1 call per non-skip want, fan-out 4)
                    └─> kwork.send_offer (closed-inbox pre-skip + conf >= 0.6, max_send=3)
                          └─> tg-bot.send_card (summary to owner bot)
```

## Failure modes
| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| Tick burns send quota on closed-inbox buyers | `pre_skipped_closed_inbox` in `kwork_want_responses.error` | `kwork-send-offer.ts:resolveBuyer` — verify `buyer_inbox_open` extractor still fires against current kwork HTML. |
| Boilerplate template instead of LLM draft | `drafts[i].text === ''` + `llm_ok=false` in `ai.draft_offer` output | `ai-draft-offer.ts:generateDraftForWant` — LLM error path; check `useModel(ModelType.TEXT_LARGE)` is healthy. |
| Low-fit pitches sent (poor reply rate) | `confidence < 0.6` rows with `ok=true` in ledger | Raise `confidence_threshold` in flow node or tighten classifier prompt in `ai-classify-wants.ts`. |
| All wants skipped (`sent_count=0`, `skipped_count=N`) | `pre_skipped_count + skipped_count === wants.length` | Expected when every buyer's inbox is closed for the tick; not a bug. |
| Sent DM missing AgentFlow line | grep `kwork_want_responses` row text — no `agentflow.website` substring | `ai-draft-offer.ts:ensureAgentFlowLine` regex (`/AgentFlow/i`, `/agentflow\.website/i`) — confirm the URL filter in `sanitiseOfferText` still whitelists the brand host. |
