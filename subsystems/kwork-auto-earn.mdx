# Kwork auto-earn loop: canon respond + DM fallback

## TL;DR
Every 30 minutes the `kwork-bid-monitor-basic` flow reads the public Kwork
wants feed, classifies each want into one of our gig kinds, writes a
per-want LLM pitch, then runs **two outreach paths in sequence**:

1. **Canonical respond** — for the single highest-confidence want, POST a
   "Предложить услугу" bid to `/new_offer/save`. Lands in the buyer's
   "Предложения" tab (~3x conversion). Burns one of the seller's 30 monthly
   connects, capped at 15 per refill by `kwork-connects-budget`.
2. **DM fallback** — for everything else (and for budget-blocked wants),
   DM the buyer via `/sendmessage`. No connect cost.

Closed-inbox buyers and low-confidence classifications get filtered BEFORE
the send so we don't burn quota on guaranteed rejections.

## Data flow
```
cron 30m
  └─> kwork.scan_wants (list_wants @ /projects feed)
        └─> ai.classify_wants (TEXT_LARGE, 1 call per tick)
              └─> ai.draft_offer (TEXT_LARGE, 1 call per non-skip want, fan-out 4)
                    ├─> kwork.respond_to_want (canon, max_send=1, conf >= 0.7)
                    │     └─ budget check → connect consume → /new_offer/save POST
                    │     └─ refund on transport failure (http_error/captcha/etc)
                    └─> kwork.send_offer (DM fallback, max_send=3, conf >= 0.6)
                          └─ auto-skips wants already covered by canon ok=true row
                                └─> tg-bot.send_card (canon + DM summary)
```

## Connect budget mechanics
- **Seller quota**: kwork gives 30 monthly free connects on the avsee4
  account; refill rolls every ~30 days (no fixed monthly anchor).
- **Our cap**: 15 per refill, leaving 5 reserved for owner-driven manual
  sends. Soft-tuned to stretch across ~22 days between refills.
- **Per-tick cap**: 1 canon respond. The second-highest-confidence want on
  the same tick routes to DM fallback.
- **Daily cap**: 1 (env `KWORK_CONNECT_DAILY_CAP`).
- **Weekly cap**: 7 (env `KWORK_CONNECT_WEEKLY_CAP`).
- **Refill detection**: kwork does NOT expose a remaining-connects API —
  the owner re-seeds via `POST /me/integrations/kwork/connects` after
  each kwork-side refill.
- **Refund rules**: refund on transport failures (`http_error`,
  `network_error`, `rate_limited`, `captcha`, `banned`, `auth_expired`,
  `unexpected_response`, `csrf_token_not_found`, `no_active_gig`) AND on
  `connects_exhausted` (kwork never charged us in either case). Do NOT
  refund on `kwork_rejected` / `already_responded` / `validation` — kwork
  processed and refused, the connect is gone.

## Failure modes
| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| Tick burns send quota on closed-inbox buyers | `pre_skipped_closed_inbox` in `kwork_want_responses.error` | `kwork-send-offer.ts:resolveBuyer` — verify `buyer_inbox_open` extractor still fires against current kwork HTML. |
| Boilerplate template instead of LLM draft | `drafts[i].text === ''` + `llm_ok=false` in `ai.draft_offer` output | `ai-draft-offer.ts:generateDraftForWant` — LLM error path; check `useModel(ModelType.TEXT_LARGE)` is healthy. |
| Low-fit pitches sent (poor reply rate) | `confidence < 0.6` rows with `ok=true` in ledger | Raise `confidence_threshold` in flow node or tighten classifier prompt in `ai-classify-wants.ts`. |
| All wants skipped (`sent_count=0`, `skipped_count=N`) | `pre_skipped_count + skipped_count === wants.length` | Expected when every buyer's inbox is closed for the tick; not a bug. |
| Canon respond never fires despite remaining=21 | `budget_blocked_per_tick_cap` in ledger error | Cron is firing faster than 60s — verify trigger.cron `interval_seconds >= 1800`. |
| Canon respond keeps refunding on `unexpected_response` | grep `unexpected_response` in `kwork_want_responses.error` | Kwork rolled the `/new_offer/save` shape. Check `respond_to_want` MCP candidate list against fresh network tab capture. |
| Connect counter drifts from kwork's reality | owner runs `POST /me/integrations/kwork/connects {remaining: X}` and counter resets | Working as designed — re-seed is the supported sync path. |
| `csrf_token_not_found` on every canon respond | grep `csrf_token_not_found` | Kwork rolled the form HTML. Update regexes in `kwork-inbox.ts:respond_to_want` GET-page parser. |
