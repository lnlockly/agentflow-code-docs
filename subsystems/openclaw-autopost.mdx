# OpenClaw «Автопостинг»

## TL;DR

A one-click cabinet function for OpenClaw-engine devices. The «Функции» card
saves a `brief` + `schedule` + `channel` and flips the in-pod `af-autopost`
skill on. The platform never runs the cron: it pushes one `autopost_config`
frame over the existing devices-ws, and the `openclaw-shim` bridge maps it onto
the loopback Gateway's `config.patch` (`skills.entries.af-autopost.enabled`) +
`cron.add`. The OpenClaw cron then owns the schedule, the flow-LLM draft, and
the channel send. The `openclaw_autopost` table is the cabinet's source of truth
so the toggle survives a pod restart (the bridge re-pushes from the row).

## Data flow

```
cabinet «Функции» (DeviceFunctions.tsx)
  POST /me/devices/:id/autopost { brief, schedule, channel, target? }
    → me-devices/autopost.ts: validate (autopostEnableSchema) + UPSERT openclaw_autopost
    → getConnection(id).send({ type:'autopost_config', enabled:true, ... })   (device WS)
        │  (offline → 409 { saved:true }; bridge re-pushes on reconnect)
        ▼
  openclaw-shim bridge: isAutopostConfig → handleAutopostConfig
    → applyAutopost(gateway, true, cfg)
        config.get   → baseHash
        config.patch → skills.entries.af-autopost.enabled = true (+ config)
        cron.list    → cron.remove every existing `af-autopost` job
        cron.add     → schedule { cron expr }, delivery:announce → channel
        ▼
  OpenClaw cron tick → /af-autopost skill turn
    → flow-LLM draft from brief → channel `send` (+ announce delivery)
```

`DELETE` mirrors the path with `enabled:false`: the patch flips the skill off,
`cron.remove` clears the schedule, and no `cron.add` fires. The brief is kept in
the row so re-enabling reuses it.

## DB / Env / API

- Tables: `openclaw_autopost` (device_id PK → `user_devices.id`, user_id, enabled,
  brief, schedule, channel, target, updated_at). No credentials — the channel
  token lives in the pod env / OpenClaw credentials store.
- Env: none new (the device pod already has its flow-LLM + channel wiring).
- Routes: `GET|POST|DELETE /me/devices/:id/autopost` (requireSession, owner-scoped).
- WS frame: `autopost_config` (server→device, ignored harmlessly by non-OpenClaw daemons).
- Gateway methods used: `config.get`, `config.patch`, `cron.list`, `cron.remove`, `cron.add`.
- Model: routed through the pod's OpenClaw `flow` alias — no model hardcoded.

## Failure modes

| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| Toggle returns 409, config not applied | route returns `device_offline` with `saved:true` | pod asleep — config persisted, bridge re-pushes on reconnect; bring the device online |
| Enable accepted but no cron registered | `autopost apply failed:` | `src/openclaw-shim/bridge.ts:444` (gateway error from `applyAutopost`) |
| Duplicate posts | two `af-autopost` cron jobs | `pickAutopostJobIds` removes ALL name matches before add — `src/openclaw-shim/autopost.ts:112` |
| Post is generic / placeholder | n/a (content) | `openclaw-image/skills/af-autopost/SKILL.md` — brief is the only topic source |
| `invalid_body` on enable | route 400 `invalid_body` | bad cron shape — `autopostEnableSchema` (`me-devices/autopost.ts:27`) requires 5 fields |

## Verify on a live pod

1. **Migration** (CI does not run migrations): apply once via the postgres pod —
   `psql -U agentflow -d agentflow -f migrations/2026-05-31b-openclaw-autopost.sql`.
2. **Enable from the cabinet**: open `/cabinet/devices/:id` on an OpenClaw device,
   fill the «Автопостинг» brief, pick a near-term schedule, press «Включить».
   Expect `202` (or `409 {saved:true}` if the pod is asleep — bring it online).
3. **Confirm the skill + cron landed** in the pod logs:
   `kubectl -n franchise-factory logs <openclaw-pod> | grep "autopost enabled"`
   (bridge logs `autopost enabled schedule="…" channel=telegram`).
4. **Confirm the cron fires**: set a `*/1 * * * *` schedule for the check, then
   grep the pod for the skill turn / a `cron.runs` entry, or watch the configured
   Telegram channel for the drafted post. One run = one post.
5. **Disable**: press «Выключить» → `cron.remove` clears the schedule; the row
   keeps the brief for re-enable.
