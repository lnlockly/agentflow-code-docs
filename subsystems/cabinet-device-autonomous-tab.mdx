# Cabinet Device — «Автономно» tab

## TL;DR
The Phase-0 autonomous UI lives as a tab inside `CabinetDeviceDetail`, not a standalone `/cabinet/autonomous` route. The owner pivot on 2026-05-22 made autonomy per-device — selecting a device implicitly scopes the dispatch target. `DeviceAutonomousPanel` mounts only when the user clicks the «Автономно» tab; it renders goals, a new-goal form, and four sub-tabs (Ступеньки / Сегодня / Уроки / Бюджет) per selected goal. All reads go through `autonomousApi` (cookie-auth `af_session`), no SDK additions.

## Data flow

```
User hits /cabinet/devices/:id
      │
      ▼
CabinetDeviceDetail (default tab='device')
      │
      │  click «Автономно» → setTab('autonomous')
      ▼
DeviceAutonomousPanel({ deviceId: id })
      │
      │  useQuery(['autonomous','goals'])  →  autonomousApi.listGoals()
      │                                       └─► GET /me/autonomous/goals (cookie af_session)
      ▼
goals grid (GoalCard ×N) + NewGoalForm
      │
      │  click GoalCard → setSelectedId(goal.id)
      ▼
SelectedGoalView
      │  useQuery(['autonomous','goal',id]) → autonomousApi.getGoal(id)
      │
      ├── MilestonesPanel  (renders detail.milestones, mutation: markMilestoneDone)
      ├── TodayPanel       (mutation: planToday(id, deviceId) — wires the parent device)
      ├── LessonsPanel     (read-only, client-side filter)
      └── BudgetPanel      (useQuery → autonomousApi.budget())

mutations invalidate ['autonomous','goal',id] / ['autonomous','goals'] / ['autonomous','budget']
react-query refetches → UI updates without a full reload
```

## DB / Env / API

- **No new tables, env vars, or routes on the client side.** All consumed endpoints belong to [`me-autonomous.ts`](/subsystems/autonomous-goals#server-mirror-agentflow-agents-postgres).
- **Endpoints consumed**:
  - `GET  /me/autonomous/goals`
  - `POST /me/autonomous/goals`
  - `GET  /me/autonomous/goals/:id`
  - `POST /me/autonomous/goals/:id/decompose`
  - `POST /me/autonomous/goals/:id/plan_today` — body `{device_id}` is the current device the user is viewing
  - `POST /me/autonomous/goals/:id/pause` / `/resume`
  - `POST /me/autonomous/goals/:id/milestones/:mid/done`
  - `GET  /me/autonomous/budget`
- **Auth** — `agentsGet`/`agentsPost` from `src/lib/agentsApi.ts`; the cookie `af_session` carries the session, no extra header for autonomous endpoints.
- **Routing** — there is no `/cabinet/autonomous` route. Earlier drafts proposed one; PR #412 removed it in favour of the device-scoped tab.

## Failure modes

| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| «Автономно» tab is invisible | none — DOM element missing | check `CabinetDeviceDetail.tsx:315-348` tablist; the button is unconditional, so absence means a stale build of `agentflow-landing` |
| Tab visible but panel crashes with `AgentsApiError` | browser console `AgentsApiError` from `agentsApi.ts` | server-side `/me/autonomous/*` not deployed yet — verify the `agentflow-agents` pod includes `src/routes/me-autonomous.ts` |
| Goals grid empty though the desktop CLI has goals | none | desktop's SQLite is not mirrored to Postgres in v1 — goals created via CLI exist only locally. Use the «Новая цель» button in the panel (which writes via `POST /me/autonomous/goals`) |
| Decompose button stuck in loading | network panel: 502 `llm_call_failed` | `agentflow-agents/src/routes/me-autonomous.ts:540` — LLM router returned an error; re-try, or inspect `ai-router` logs |
| «Сегодня» «Отправить на это устройство» click 404s | network panel: 404 `not_found` from `/plan_today` | goal owner mismatch — `loadOwnedGoal` returns null when `user_id` differs; check the session is for the goal's owner |
| Budget chart shows zero usage despite LLM calls | none | `autonomous_budget_ledger` writes happen only when the worker calls `useModel` — direct planner calls from the desktop CLI write into the local `~/.agentflow/autonomous.db`, not Postgres |
| Mutation succeeded server-side but UI didn't update | none — `useMutation` returned ok | check `invalidateQueries` keys in `SelectedGoalView` — the relevant keys are `['autonomous','goal',id]`, `['autonomous','goals']`, `['autonomous','budget']`; missing invalidation is the most common cause |
| «Уроки» panel shows no lessons though reflection ran | network: `lessons: []` from `GET /me/autonomous/goals/:id` | reflection ran but did not extract any lessons (LLM returned empty array) — re-trigger reflection by waiting for `REFLECT_HOUR_UTC` tick or running the desktop CLI `reflect` command |
