# Projects Dashboard

## TL;DR

`/projects` got a 2026-05-15 premium redesign aimed at marketplace
visual parity. Three widgets sit between the hero and the project grid:
`UserStatsStrip` (live `/me/stats`), `FarmBanner` (CTA into `/farm`),
and `ProductsBanner` (CTA into `/products`). Behind a 15s `refetchInterval`
the grid stays warm with active project status.

The Balance / Marketing / Referrals "control-center" widgets in the
original spec did not ship here — they live in `Account.tsx` and the
referrals stack instead. This page kept the lighter widget set.
`/projects` is a prompt-first creation surface (2026-05-29 rebuild,
UX-OVERHAUL §2). The page leads with a big centered prompt hero ("Опиши,
что хочешь создать…") + example chips + one bold CTA — the "wow" first
moment. On submit it does NOT navigate away: it swaps the hero for an
inline `LiveBuildView` that streams the REAL project lifecycle (ordered
animated steps + embedded preview iframe). Existing projects render below
as polished preview-thumbnail cards. All `.plov-*` styling.

It reuses the working creation API EXACTLY (the old `CreateProjectModal`
path): `createProject(brief)` → fire-and-forget hosted-device claim +
`approveProject` → poll `GET /me/projects/:id`. Only the UI changed.
Generic — no per-kind / per-slug branching; the backend resolves runtime
kind + template from the brief.

## Data flow

```
GET /me/projects (agentflow-agents)                 ─► project grid
  └─ react-query refetchInterval=15_000

UserStatsStrip
  └─► GET /me/stats (agentflow-agents)              ─► contacts/refs/FLOW strip
                                                     or "launch the farm" CTA

FarmBanner
  └─ reads localStorage('af_farm_visited')           ─► copy + link to /farm
     (no network call — copy is static-with-i18n)

ProductsBanner
  └─ static CTA → /products
```

`FarmBanner` does not call `/me/farm/stats` itself; the visited flag
only flips after the user has hit `/farm` once. The live count of
contacts/refs in the active-state copy is currently hardcoded (`340` /
`12`) and pending wire-up to `/me/farm/stats`.

## DB / Env / API

- Routes consumed (all under `agentsBaseUrl`):
  - `GET /me/projects` — main grid source (paged, no params)
  - `GET /me/stats` — UserStatsStrip
  - `GET /me/create-status` — locked-state banner (paid-tier gate)
- LocalStorage keys: `af_farm_visited` — first visit to `/farm` flips the FarmBanner copy
- No new env vars
- Tailwind/CSS file: `projects-premium.css` (`.pdp-*` class prefix)
HeroCreate prompt submit
  └─► POST /me/projects { brief }            (createProject)        ─► { id, slug }
        └─ setBuilding({ id, brief })  →  render LiveBuildView
        └─ runPostCreateBackground(id) (fire-and-forget):
             GET  /me/hosted-devices         (claim daemon if none)
             POST /me/hosted-devices         (size=small kind=daemon preset=simple)
             POST /me/projects/:id/approve   (kicks clone + dispatch)

LiveBuildView (poll loop, 2500ms until status done|failed)
  └─► GET /me/projects/:id (getProject — folds events[])
        status → phase:
          draft|awaiting_approval → "Готовлю проект"
          approved|awaiting_clone → "Подбираю шаблон"
          provisioning            → "Пишу код"
          running                 → "Поднимаю превью" + <iframe preview_url>
          done                    → open workspace CTA
          failed                  → inline error + retry
        early phase > 45s         → calm "в очереди на сборку" card (no dead end)

Grid: GET /me/projects?limit=200   (react-query refetchInterval=15_000)
```

`provisioning` / `awaiting_clone` are runtime-only statuses the backend
lifecycle writes (per workspace CLAUDE.md); the `ProjectDetail['status']`
TS union on the landing branch may be narrower, so `phaseForStatus` takes
a plain `string`.

## DB / Env / API

## Failure modes

| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| Widgets row empty | `UserStatsStrip` returns null when fetch fails | By design — silent hide so the dashboard does not show a broken widget |
| FarmBanner shows "active" copy with no real farm | `localStorage.getItem('af_farm_visited')` returns truthy | User visited `/farm` but did not start. Visit flag does not reflect actual status — bug-prone; backlog: read `/me/farm/stats` here |
| Project grid stale | n/a — `refetchInterval: 15_000` | Already polls every 15s; force-refresh via React Query DevTools |
| Locked banner showing for admin | `createStatus?.locked && !admin_bypass` | Admin bypass uses `users.is_admin=true`; check `/me/create-status` response |
| `pdp-widgets` overflows on mobile | n/a (CSS) | Edit `projects-premium.css` — widget row collapses to single column < 720px |
