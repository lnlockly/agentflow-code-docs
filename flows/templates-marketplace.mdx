# Templates marketplace

## TL;DR

`/templates` lists every row of `agent_boilerplates` returned by
`GET /me/boilerplates`. Each card renders the boilerplate's `workflow_schema`
as a compact SVG DAG thumbnail, so the owner can see *what the template
builds* before committing. Click **Использовать шаблон** → opens
`CreateProjectModal` pre-set to the boilerplate's `kind` with a banner naming
the template. The intake form then POSTs to `/me/projects` exactly like the
generic `/projects` flow.

The detail route `/templates/:slug` reuses the same query cache and shows an
interactive workflow with hover-on-node sync between the SVG graph and the
node list, plus an inferred-secrets panel and a GitHub source link.

## Data flow

```
Browser → /templates
  │ useQuery(['boilerplates'])  (staleTime 5min, gated on isAuthenticated)
  ▼
GET /me/boilerplates  ─── agentflow-agents
  │ returns [{ id, name, kind, title, description, category,
  │            workflow_schema:{nodes,edges}, default_features, skills, ... }]
  ▼
Templates page renders cards
  │ filter by activeTab.match (category|kind) + search term
  │ thumbnail = <WorkflowDiagram variant="compact" />
  ▼
Click "Использовать шаблон"
  │ pickedTemplate = boilerplate
  │ kindToPreset(boilerplate.kind)
  ▼
  ├─ null  → <UnsupportedKindNotice/>  (spa/api/code_only escape hatch)
  └─ kind  → <CreateProjectModal open presetKind={kind}
                                  presetBoilerplateTitle={title}/>
                │ banner: "Шаблон: <title>"
                │ user fills brief
                ▼
              POST /me/projects  ────► standard create-project flow
```

The detail page (`/templates/:slug`) hydrates from the same
`['boilerplates']` query cache — no second network call when the user
clicks through from the grid.

## DB / Env / API

- **Tables:** `agent_boilerplates` — see [Add new kind runbook](/runbooks/add-new-kind) for the schema; relevant columns are `kind`, `category`, `workflow_schema` jsonb (`{nodes:[{id,label,role,icon?}], edges:[{from,to,label?}]}`), `default_features` text[], `skills` text[], `github_url`, `branch`, `subdir`.
- **Env:** none new. `/me/boilerplates` reuses the existing `requireSession` middleware.
- **Routes:** `GET /me/boilerplates[?kind=<value>]` → `{ ok: true, items: BoilerplateListing[] }`.
- **Frontend routes:** `/templates`, `/templates/:slug` (slug = `boilerplate.name`).
- **MCP tools:** none — pure read.

## Failure modes

| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| Empty marketplace with valid session | `[boilerplates] empty result` (route logs) | `agentflow-agents/src/routes/projects.ts` (seed migration / row visibility) |
| Card thumbnail shows "Нет схемы" | `workflow_schema` is null on that row | `agentflow-agents/src/db/seed/boilerplates/` — add a schema for the kind |
| Click "Использовать шаблон" opens `UnsupportedKindNotice` | `kindToPreset` returned `null` (kind in `{spa,api,code_only}`) | `agentflow-landing/src/components/projects/CreateProjectModal.tsx:48` — add a tile for the kind, then extend `kindToPreset` |
| 401 on `/me/boilerplates` for signed-in user | `requireSession: 401 unauthorized` | session cookie / refresh; see [Auth and access](/subsystems/auth-and-access) |
| Hover-sync stuck on a node after mouse leaves | `hoveredNodeId` not cleared | `TemplateDetail.tsx` `onMouseLeave` → `setHoveredNodeId(null)` |
