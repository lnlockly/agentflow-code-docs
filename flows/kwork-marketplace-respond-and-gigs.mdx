# Kwork marketplace: approval-gated отклики + new gigs

## TL;DR
The owner runs two Kwork automations from the marketplace on their LIVE Kwork
account: (1) scan fresh `/projects` → AI-draft a human отклик → TG approval card
→ post on owner approve; (2) draft a new gig → TG approval card → create on
owner approve. Every outward action is approval-gated (no auto-blast — Kwork
bans spammy/GPT bids). Two engines: studio-graph (`*-basic`, runs on cron now)
and the Activepieces fork (`*-ap`, owner publishes in flows.agentflow.website).

## Data flow
```
marketplace install (POST /me/marketplace/<slug>/install)
  studio engine (*-basic):  cron → kwork.scan_wants → ai.draft_replies (flow alias)
                             → tg-bot.send_card  →  owner taps "Отправить"
                             → owner-bot-callbacks-router → kwork-inbox.respond_to_want
  AP engine (*-ap):          schedule → HTTP kwork-rest-bridge → telegram-bot request_approval card
                             (owner publishes + adds bot connection in flows.agentflow.website)
```

## R4 — working buttons constraint (READ BEFORE wiring callbacks)
The official @AIAgentFlow_bot has **no webhook** (`getWebhookInfo.url === ""`) and its `getUpdates` is already consumed by the separate `agentflow-bot` deployment (grammY, `agentflow-bot/src/bot/index.ts:380` `bot.on("callback_query:data")`). Therefore `tg-bot-poller` (which `getUpdates` on `OWNER_TG_BOT_TOKEN`) **cannot also poll the official bot** — two `getUpdates` consumers on one token = Telegram 409. Consequences:
- `callback_data` buttons on a card sent from the official bot are delivered to `agentflow-bot`, NOT to `tg-bot-poller` → the studio `tg_bot_callback_queue` → `tg-bot.handle_callback` pipeline never sees them.
- Working buttons on the official bot must use **approval LINKS / URL buttons**: either the AP fork's `wait_for_approval` (hosted approve/reject links, no custom handler) or an `agentflow-agents` HTTP endpoint the URL button points at. Do not rely on `callback_data` + the poller for official-bot cards.

**Shipped (PR #1005, studio interim path) — prefetch-safe + single-use:**
| Path | Role |
|---|---|
| `agentflow-agents/src/services/kwork-approval-token.ts` | HMAC(`AUTH_JWT_SECRET`) sign/verify of compact tokens (`send`/`skip`/`custom`), 1h TTL, scoped to the pending-ticket id. Constant-time compare. |
| `agentflow-agents/src/routes/public-kwork-approval.ts` | `GET /public/kwork/respond?t=<token>` renders a **CONFIRM page and mutates nothing** (Telegram URL prefetch can't auto-fire). `POST` performs the action ONCE: ✅ `kwork-inbox.respond_to_want` (dry-run-safe) / ✕ skip / ✏️ custom-text. Single-use via the armed-ticket claim; in-browser HTML; gated `FF_KWORK_TG_PIPELINE=1`. The HMAC token IS the auth. |
| `agentflow-agents/src/db/schema.ts` + `db/migrations/0079_kwork_pending_responses.sql` | `kwork_pending_responses` — one `armed` ticket per card; POST atomically claims `armed`→terminal (`sent`/`skipped`/`approved_dryrun`/`send_failed`) + `consumed_at`. Migration via psql post-merge (CI doesn't run migrations). |
| `agentflow-agents/src/services/graph-executor/handlers/tg-bot-send-card.ts` | `approval:'links'` mode (kwork): arms a pending ticket → signs link tokens with its id → official bot (`bot:'platform'`) → stamps card msg id. |

**Prefetch footgun (why GET ≠ action):** Telegram + clients prefetch URLs on render. A plain `GET ...?action=send` would auto-post the отклик with no tap. So the GET only renders a confirm page; the post happens on the confirm `POST`, and the single-use ticket makes replays no-op.

**Legacy callback path:** `tg-bot.handle_callback` does NOT handle want-respond cards (`kwork.reply:<want_id>` → `loadKworkLead(dialog_id)` mismatch → `lead_state_missing`). The links path bypasses the callback handler entirely.

Bot identity note: `AGENTFLOW_BOT_TOKEN` = **@AIAgentFlow_bot** (id 8536951969) — the SAME token the public `agentflow-bot` deployment runs, i.e. the real official bot. `@agentflow_bot` in template copy resolves to a SEPARATE bot `@Agentflow_bot` (id 7906381977) with NO token in the cluster — stale copy, do not target it. Link base: `KWORK_APPROVAL_BASE_URL` (default `https://agentflow.website/_agents`).

## Failure modes
| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| Respond flow never sends a card; first node fails | `step scan_wants (kwork.scan_wants)` + `expected number, received string` | `kwork-scan-wants.ts:optionalIntFromLoose` — string→number coercion for `min_budget`/`category_id`/`limit`. Fixed in agentflow-agents PR #1002. |
| Card never delivered, `no_owner_bot_token` | `resolveOwnerBotToken` returns `no_owner_bot_token` | Set `OWNER_TG_BOT_TOKEN` (+ `OWNER_TG_CHAT_ID`) in `project_secrets` for the owner. |
| AP create-gig flow run errors at list step | bridge `not_found` on `POST /kwork/list-my-gigs` | Bridge pod predates the create-gig routes — rebuild `kwork-rest-bridge` image with the current `server.mjs`. No CI exists for this pod yet (gap). |
| отклик posted to a stranger that reads as GPT/spam | Kwork sends off-platform-penalty notice in inbox | Keep approval-gating ON; draft ≤3 phrases, на «вы», no lists, no off-platform mentions. |
| Owner taps a card button on the official bot, nothing happens | tap recorded in `agentflow-bot` logs, never in `tg_bot_callback_queue`; or `kwork.handle_callback` returns `lead_state_missing` for a `want_id` | Official-bot `callback_data` can't reach `tg-bot-poller` (see R4). Use approval URL links. Also: project-respond cards emit `kwork.reply:<want_id>` but `handle_callback` `loadKworkLead(dialog_id)` has no row for a want → `lead_state_missing`. |
| Card lands on QA bot `@agentflow_e2e_verify_bot` instead of the official bot | card `from.username` = e2e bot | Owner has `OWNER_TG_BOT_TOKEN` = e2e token → `send_card` defaults to `kind:'owner'`. Call `send_card({bot:'platform'})` for owner-facing cards (R3). |
| Respond cards target crowded projects | many `responses_count > 5` in scan output | Pass `max_responses` (default 5) to `kwork.scan_wants`; it now filters server-side (R1). |
| Gig card has no portfolio images / `work_examples_attached:false` | `gen_work_examples` examples all have `image_url:null` | designapi (RU IP) is geo-blocked from the OVH/France egress (task #11, owner-gated — fix = RU proxy / `HTTP_PROXY` for `*.designapi.ink`). Node tolerates null; gig ships text-only; images auto-attach once reachable. |
| Gig token tapped, «Ссылка недействительна» | route logs reject on `kind` mismatch | A `respond` token was used on `/public/kwork/create-gig` or vice-versa — kind-namespacing rejects cross-surface tokens by design. Use the matching link. |

## AP-native flows (studio-graph retirement, PR #1012 + #1015)
The ActivePieces flows on flows.agentflow.website reuse the SAME prefetch-safe /
single-use ticket as the studio path, via thin HTTP endpoints — so AP-native
survives the studio-graph retirement.

| Path | Role |
|---|---|
| `agentflow-agents/src/services/kwork-approval-card.ts` | Shared `armAndSendRespondCard` / `armAndSendGigCard` — arm ticket + sign kind-correct links + official-bot card (`bot:'platform'`) + stamp msg id. dry_run default. |
| `agentflow-agents/src/routes/internal-kwork-cards.ts` | `POST /internal/kwork/respond-card` + `/internal/kwork/gig-card`, `requireInternalSecret` (header `x-agentflow-secret`), gated `FF_KWORK_TG_PIPELINE=1`. Verified: with secret → `200 {ok,pending_id,message_id}`; no secret → 401. |
| `agentflow-agents/scripts/fixtures/ap-kwork-projects-respond.json` | `kwork-projects-respond-ap`: schedule → bridge `/kwork/scan-projects` (`max_responses=5`) → bridge `/kwork/draft` (`{drafts:[…]}`) → `POST /internal/kwork/respond-card`. No `wait_for_approval` (out-of-band link tap). |
| `agentflow-agents/scripts/fixtures/ap-kwork-create-gig.json` | `kwork-create-gig-ap`: manual → `POST /internal/kwork/gig-card` (owner-editable payload). |
| `agentflow-agents/scripts/seed-ap-marketplace-templates.ts` | Seeds the two `kwork-*-ap` rows (engine=activepieces). |

**Secrets via AP connections, never plaintext.** Both `x-bridge-secret` and
`x-agentflow-secret` are `{{connections['kwork_bridge_secret']}}` /
`{{connections['agentflow_internal_secret']}}` in the flow JSON — the owner
creates two Secret-Text connections at publish; the seeded JSON carries no raw
secret. (The legacy `ap-kwork-lead-funnel.json` still uses the
`__AP_BRIDGE_SECRET__` plaintext substitution — migrate it to a connection.)

**Owner publish gate:** publish each AP flow + add the two connections on
flows.agentflow.website (SSO). No official-bot connection needed — the card is
sent server-side by `/internal/*-card`. In-cluster reachability: AP →
`http://agentflow-agents:4100/internal/…`, bridge `http://kwork-rest-bridge:8000`.

**AP gig auto-draft** is a follow-up (`/internal/kwork/draft-gig` wrapping
`kwork.draft_gig`); the studio `kwork-create-gig-basic` already auto-assembles.
