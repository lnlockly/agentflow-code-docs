# Kwork marketplace: approval-gated отклики + new gigs

## TL;DR
The owner runs two Kwork automations from the marketplace on their LIVE Kwork
account: (1) scan fresh `/projects` → AI-draft a human отклик → TG approval card
→ post on owner approve; (2) draft a new gig → TG approval card → create on
owner approve. Every outward action is approval-gated (no auto-blast — Kwork
bans spammy/GPT bids). Two engines: studio-graph (`*-basic`, runs on cron now)
and the Activepieces fork (`*-ap`, owner publishes in flows.agentflow.website).

## Data flow
```
marketplace install (POST /me/marketplace/<slug>/install)
  studio engine (*-basic):  cron → kwork.scan_wants → ai.draft_replies (flow alias)
                             → tg-bot.send_card  →  owner taps "Отправить"
                             → owner-bot-callbacks-router → kwork-inbox.respond_to_want
  AP engine (*-ap):          schedule → HTTP kwork-rest-bridge → telegram-bot request_approval card
                             (owner publishes + adds bot connection in flows.agentflow.website)
```

## DB / Env / API
- Tables: `marketplace_templates` (rows `kwork-projects-respond-ap`, `kwork-create-gig-ap`, engine=`activepieces`); `project_secrets` (`OWNER_TG_BOT_TOKEN`, `OWNER_TG_CHAT_ID` per owner); `kwork_lead_state` (отклик dedupe PK `(owner, dialog_id)`).
- Env (bridge): `AP_BRIDGE_SECRET`, `INTERNAL_API_SECRET`, `AGENTFLOW_AGENTS_URL`.
- Routes: `POST /me/marketplace/:slug/install|run`, bridge `POST /kwork/{scan-projects,respond-to-project,list-my-gigs,categories,create-gig}`.
- MCP tools: `kwork-inbox.{list_wants,respond_to_want,create_kwork,list_my_kworks,list_categories}`, `tg-bot.send_card`.
- Approval card bot (R3): the **official** platform bot **@AIAgentFlow_bot** (id `8536951969`, `AGENTFLOW_BOT_TOKEN` env on `agentflow-agents`). Owner chat `1361064246` (`@avsee4`, in `tg_links`). The QA bot `@agentflow_e2e_verify_bot` (owner's `OWNER_TG_BOT_TOKEN`) is NOT used for owner-facing cards — call `send_card({bot:'platform'})`.

## R4 — working buttons constraint (READ BEFORE wiring callbacks)
The official @AIAgentFlow_bot has **no webhook** (`getWebhookInfo.url === ""`) and its `getUpdates` is already consumed by the separate `agentflow-bot` deployment (grammY, `agentflow-bot/src/bot/index.ts:380` `bot.on("callback_query:data")`). Therefore `tg-bot-poller` (which `getUpdates` on `OWNER_TG_BOT_TOKEN`) **cannot also poll the official bot** — two `getUpdates` consumers on one token = Telegram 409. Consequences:
- `callback_data` buttons on a card sent from the official bot are delivered to `agentflow-bot`, NOT to `tg-bot-poller` → the studio `tg_bot_callback_queue` → `tg-bot.handle_callback` pipeline never sees them.
- Working buttons on the official bot must use **approval LINKS / URL buttons**: either the AP fork's `wait_for_approval` (hosted approve/reject links, no custom handler) or an `agentflow-agents` HTTP endpoint the URL button points at. Do not rely on `callback_data` + the poller for official-bot cards.

## Failure modes
| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| Respond flow never sends a card; first node fails | `step scan_wants (kwork.scan_wants)` + `expected number, received string` | `kwork-scan-wants.ts:optionalIntFromLoose` — string→number coercion for `min_budget`/`category_id`/`limit`. Fixed in agentflow-agents PR #1002. |
| Card never delivered, `no_owner_bot_token` | `resolveOwnerBotToken` returns `no_owner_bot_token` | Set `OWNER_TG_BOT_TOKEN` (+ `OWNER_TG_CHAT_ID`) in `project_secrets` for the owner. |
| AP create-gig flow run errors at list step | bridge `not_found` on `POST /kwork/list-my-gigs` | Bridge pod predates the create-gig routes — rebuild `kwork-rest-bridge` image with the current `server.mjs`. No CI exists for this pod yet (gap). |
| отклик posted to a stranger that reads as GPT/spam | Kwork sends off-platform-penalty notice in inbox | Keep approval-gating ON; draft ≤3 phrases, на «вы», no lists, no off-platform mentions. |
| Owner taps a card button on the official bot, nothing happens | tap recorded in `agentflow-bot` logs, never in `tg_bot_callback_queue`; or `kwork.handle_callback` returns `lead_state_missing` for a `want_id` | Official-bot `callback_data` can't reach `tg-bot-poller` (see R4). Use approval URL links. Also: project-respond cards emit `kwork.reply:<want_id>` but `handle_callback` `loadKworkLead(dialog_id)` has no row for a want → `lead_state_missing`. |
| Card lands on QA bot `@agentflow_e2e_verify_bot` instead of the official bot | card `from.username` = e2e bot | Owner has `OWNER_TG_BOT_TOKEN` = e2e token → `send_card` defaults to `kind:'owner'`. Call `send_card({bot:'platform'})` for owner-facing cards (R3). |
| Respond cards target crowded projects | many `responses_count > 5` in scan output | Pass `max_responses` (default 5) to `kwork.scan_wants`; it now filters server-side (R1). |
