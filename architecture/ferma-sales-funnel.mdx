# Ферма (sales-funnel-tg-farm)

## TL;DR

A marketplace preset (`is_public_listing=true`, showcase rank 7) that lets
an owner attach a sales-funnel AI persona to their own Telegram account.
The agent is `kind: action` — it polls inbound DMs via `agentflow-tg-mcp`
(MTProto StringSession), classifies the lead through a flow with a
`trigger.tg.new_message` node, replies + advances a state machine in
`tg_lead_states`, and surfaces hot leads. The hire path is generic (works
for every action-kind agent with `required_secrets`), but the runtime
glue is sales-funnel-specific.

## Data flow

```
Marketplace → HireDialog → /me/marketplace/sales-funnel-tg-farm/hire
        │
        ▼ (400 missing_required_secrets, stubs pre-seeded — see flows/marketplace-hire)
WorkspaceV2 ?tab=secrets → SecretsPane shows 5 required keys:
        ├─ TG_API_ID         (my.telegram.org)
        ├─ TG_API_HASH       (my.telegram.org)
        ├─ TG_SESSION        (StringSession from tg-mcp add_phone)
        ├─ CALENDLY_LINK     (optional)
        └─ ELEVENLABS_API_KEY(optional, voice)
        │
        ▼ owner pastes values → /me/projects/:id/secrets upserts is_set=true
        │
        ▼ retry /hire (now succeeds) → projectAgents row + agent_hired event
        │
        ▼ owner enables agent_triggers row (cron/event)
        │   FF_AGENT_TRIGGERS=1 required
        │
        ▼ agent-trigger-worker → pollFlowTgNewMessage
        │     ├─ tg-mcp get_dialogs(tg_account_id) — cursor in agent_triggers.cursor
        │     ├─ for each new message → executeFlow(graph, { _trigger: 'tg.new_message', text, chat_peer, message_id })
        │     └─ flow updates tg_lead_states.state (cold|warm|hot|booked|objection|spam)
        ▼
Frontend (TODO — gap #3 in audit): tg_lead_states dashboard pane
```

## DB / Env / API

### Tables
- **`agents`** — preset stored with `slug='sales-funnel-tg-farm'`, `is_public_listing=true`, `category='domain'`, `required_secrets=[TG_API_ID, TG_API_HASH, TG_SESSION, CALENDLY_LINK?, ELEVENLABS_API_KEY?]`.
- **`project_secrets`** (schema.ts:1072) — sealed AES-256-GCM, unique `(project_id, key)`, `source ∈ {agent, owner, platform, user_brief}`.
- **`agent_triggers`** (schema.ts:1765) — owner-scoped cron / `tg.new_message` subscriptions; `cursor` jsonb holds last seen `(dialog_id, message_id)`.
- **`tg_lead_states`** (schema.ts:2127) — unique on `(owner_user_id, tg_account_id, tg_chat_peer)`; `state ∈ {cold|warm|hot|booked|objection|spam}`.

### Env
- `FF_AGENT_TRIGGERS=1` — required for `agent-triggers` routes + worker (501 otherwise)
- `FF_AGENT_MARKETPLACE=1` — required for marketplace catalog list (note: `/hire` not gated)
- `AGENTS_MASTER_KEY` — AES-256 master used by `sealProjectSecretValue`
- `TG_MCP_URL` — Python tg-mcp HTTP endpoint
- `TG_MCP_TOKEN` — bearer for tg-mcp

### Routes
- `POST /me/marketplace/sales-funnel-tg-farm/hire` — see `flows/marketplace-hire.mdx`
- `POST /me/projects/:id/secrets` — upsert TG_*, CALENDLY_*, ELEVENLABS_* values
- `POST /me/agent-triggers` — register `trigger.tg.new_message` cron
- `GET /me/agent-triggers` — list owner subscriptions

### MCP tools (agentflow-tg-mcp)
- `add_phone(phone)` → returns `{ phone_code_hash }`
- `confirm_code(phone, code, phone_code_hash)` → returns `{ string_session }` (paste this as `TG_SESSION`)
- `get_dialogs(string_session, offset)` — paginated dialog list
- `get_messages(string_session, dialog_id, min_id)` — incremental fetch
- `send_message(string_session, peer, text)` — outbound reply

## Failure modes

| Симптом | Лог-строка для grep | Где починить |

| `bad_input` on /hire | Missing `accept_terms:true` in body | `agentflow-landing/src/lib/agentsApi.ts:3691` |
| Poller doesn't fire | `agent-triggers routes return 503` | set `FF_AGENT_TRIGGERS=1` in deployment env |
| Poller fires but no new messages | `tg.new_message get_messages failed` | `agentflow-agents/src/services/agent-trigger-worker.ts:396` — usually TG_SESSION expired or proxy unreachable |
| Lead state stuck in `cold` | `executeFlow` returns without `setLeadState` action | check flow graph has `set_lead_state` node downstream of `trigger.tg.new_message` |
| `tg.new_message cursor read failed` in logs | jsonb cursor corrupted | `agentflow-agents/src/services/agent-trigger-worker.ts:361` |
