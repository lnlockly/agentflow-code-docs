# TG templates matrix

## TL;DR

The `/templates` marketplace and `CreateProjectModal` surface every row of
`agent_boilerplates` whose `kind` starts with `tg_` or whose template scope
is Telegram-adjacent. Migration `2026-05-13-tg-templates-v2.sql` brings the
catalogue from 4 → 10 to match ASCN's TG line-up (cold-base mailing,
AI-shiller, subscription-gate, join-request, voice-transcribe, content
crossposter, plus our existing ферма / визитка / bot-full / mini-app
trio).

## Data flow

```
User picks TG template on /templates           Templates.tsx:57
   ↓ kindToPreset(kind) → CreateProjectModal preset
POST /me/projects { brief, kind, title }       routes/projects.ts:573
   ↓ kind already set → skip classifyBriefKind
runProjectApprovalBackground (kind=tg_*)
   ↓ provision pod → workspace_ready
   ↓ autoCreateTelegramBot (kind ∈ tg_bot / tg_profile_bundle)
   ↓ NOTE: kind=tg_farm skips Bot API — uses MTProto user account
   ↓
graph-executor walker (when FF_GRAPH_EXECUTOR enabled)
   ↓ topo-walks workflow_schema.nodes
   ↓ each id → registry lookup → handler OR coder-agent-delegate
   ↓ emits node_started / node_finished / node_failed / edge_flowing
```

## DB / Env / API

- **Table:** `agent_boilerplates` — `kind, name, title, description, github_url, branch, subdir, skills, workflow_schema jsonb, default_features jsonb, category` (see [`db/schema.ts:1353`](https://github.com/lnlockly/agentflow-agents/blob/main/src/db/schema.ts#L1353)).
- **CHECK constraint:** `kind IN ('landing', 'tg_bot', 'spa', 'api', 'code_only', 'mini_app', 'tg_profile_bundle', 'tg_farm')`.
- **Env:** `FF_GRAPH_EXECUTOR`, `FF_GRAPH_EXECUTOR_KINDS` — the walker that consumes `workflow_schema`. Until those flip on, the schemas are visual hints only.
- **Routes:**
  - `GET /me/boilerplates` — serves the marketplace cards.
  - `POST /me/projects` — accepts `kind=tg_farm` since this PR.

## New node ids needing handler coverage

Owned by `node-handlers-expand` (task #8). The graph executor falls back to
`coder-agent-delegate` for unregistered ids per
[Graph executor §Node handler registry](/architecture/graph-executor#node-handler-registry),
so projects still ship without registrations — but typed handlers are
preferred for determinism.

## Failure modes

| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| `POST /me/projects {kind:'tg_farm'}` rejected | `classify_unknown_kind` | `services/kind-classifier.ts:31` — VALID_KINDS set |
| Migration fails with `kind_check violation` | `new row for relation "agent_boilerplates" violates check constraint "agent_boilerplates_kind_check"` | re-apply `2026-05-13-tg-templates-v2.sql` — DROP+ADD inside transaction |
| Cold-mailer scaffolds Bot API instead of MTProto | `[auto-bot] getMe network error` then `bot_assigned` | `services/projects.ts:1682` should skip `autoCreateTelegramBot` when `kind=tg_farm` (TODO — track in a follow-up; today the call no-ops because MTProto creds live elsewhere) |
| Voice transcriber returns empty text | `[ai-router] TRANSCRIPTION model returned empty` | `subsystems/llm-router` — provider fallback ladder |
