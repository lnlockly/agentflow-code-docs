## DAG → handler map

Each `agent_boilerplates` row carries a `workflow_schema = {nodes, edges}`.
The graph executor resolves every node id through `defaultRegistry`
([`src/services/graph-executor/registry.ts:71`](https://github.com/lnlockly/agentflow-agents/blob/main/src/services/graph-executor/registry.ts#L71))
to a typed handler. Full per-node table:
[Graph handlers](/subsystems/graph-handlers).

| Kind | Seeded DAG (nodes in topo order) | Per-kind on-failure |
|---|---|---|
| `landing` (id=15 landing-full) | `pick_theme → generate_sections → seo_optimize → deploy_caddy` | fail-fast on `deploy_caddy`; continue on `seo_optimize` |
| `tg_bot` (id=12 tg-bot-full) | `request_token → scaffold_aiogram → smoke_test ↔ self_heal_loop → deploy` | fail-fast on `request_token` + `deploy`; continue on `smoke_test` (auto-fix loop) |
| `spa` (id=14 webapp-full) | `scaffold_nest → scaffold_prisma → jwt_auth → {billing_stripe, multi_tenant → admin_panel} → deploy` | fail-fast on `scaffold_nest` + `deploy`; continue on `admin_panel` + `multi_tenant` |
| `mini_app` (id=6 mini-app-fullstack) | `scaffold_vite → tg_webapp_init → routes → deploy` | fail-fast on `scaffold_vite` + `deploy` |
| `tg_profile_bundle` (id=18) | `scrape_tg → render_landing → deploy_landing` and `scrape_tg → scaffold_bot → wire_designapi → deploy_bot → booking_flow` | fail-fast on `scrape_tg`, `deploy_landing`, `deploy_bot`; continue on `booking_flow` |
| `tg_farm` (cold-mailer + AI-shiller rows) | `link_account → import_leads → personalize_template → throttled_send → log_replies` (cold-mailer); `link_account → set_keywords → poll_chats → ai_compose_reply → send_reply` (AI-shiller) | fail-fast on `link_account` (no MTProto creds = full stop); continue on `log_replies` + `send_reply` |
| `api` (id=4 stub) | empty — maestro freestyle | n/a |

## Per-kind UI surface

The `/projects` dashboard renders kind-aware accents on each card via the
`KindAccent` helper in `agentflow-landing/src/components/projects/ProjectCard.tsx:38`.
Each kind has its own lucide icon and an inline context line in the card
meta row:

| Backend `kind` | Icon (lucide) | Subtitle | Source field |
|---|---|---|---|
| `tg_profile_bundle` | `IdCard` | `AI-визитка @<tg_username>` ‖ plain `AI-визитка` | `project.detail_meta.tg_username` ‖ `.username` ‖ `.source_username` |
| `tg_bot` | `Bot` | `@<bot_username>` ‖ `Бот ещё не назначен` | `project.bot_username` |
| `tg_farm` | `Users` | `MTProto · @<tg_username>` ‖ `Аккаунт не залинкован` | `project.detail_meta.tg_username` ‖ `.linked_account` |
| `landing` / `mini_app` / `spa` / other | (none) | plain kind label | `project.kind` |

`detail_meta` is the optional `Record<string, unknown>` on
`ProjectSummary` (`agentflow-landing/src/lib/agentsApi.ts:506`) populated
by Виртуоз / scrape jobs. When the scraper has not yet written the
handle, the accent falls back to the plain kind label without throwing.

For the matching create-time UI (5-tile kind picker), see the
[Frontend entry section in Create project flow](/flows/create-project)
and [Projects frontend](/subsystems/projects-frontend).

### Templates marketplace card thumbnail

`/templates` renders one card per row of `agent_boilerplates`. The thumbnail
is the `workflow_schema` graph rendered at `variant="compact"` via
`agentflow-landing/src/components/workflow/WorkflowDiagram.tsx:1` — the
same component the workspace approve-screen uses, so a template card and
the matching project card stay visually consistent.

When the user clicks **Использовать шаблон**, the page maps the backend
kind to the closest `CreateProjectModal` tile via `kindToPreset()` in
`agentflow-landing/src/pages/Templates.tsx:57`:

| Backend `kind` | Modal preset | Notes |
|---|---|---|
| `tg_profile_bundle` | `tg_profile_bundle` | direct |
| `tg_bot` | `tg_bot` | direct |
| `tg_farm` | `tg_farm` | direct — opens MTProto-aware intake (TG_API_ID/HASH/SESSION) |
| `landing` | `landing` | direct |
| `mini_app` | `mini_app` | direct |
| `spa` / `api` / `code_only` | `null` → `UnsupportedKindNotice` | falls back to a small dialog with a "create from scratch" escape hatch |

The flow then continues exactly like the [Create project flow](/flows/create-project) — modal banner names the picked template, intake form POSTs to `/me/projects` with a brief that mentions the template title so Maestro classifies sensibly.

Note: **`tg_farm` joined the enum in task #11** (migration
`2026-05-13-tg-templates-v2.sql`). The TG-ферма tile in the create
modal now POSTs `kind=tg_farm` to `/me/projects` and provisions a real
project row — the cold-mailer and AI-shiller boilerplates back this
kind. The `/agents/sales-funnel-tg-farm` agent page still exists as the
public agent listing, but it is no longer the only entry point.
Backend skips `autoCreateTelegramBot` for `kind=tg_farm` (MTProto user
account, not a Bot API bot). See [TG templates matrix](/architecture/tg-templates).
