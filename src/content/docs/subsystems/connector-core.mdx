# connector-core

## TL;DR

`connector-core` is the formal contract that turns `Platform → Account →
EntityKind → Entity → Action` into one interface (`Connector`) plus a registry.
A connector is a thin adapter over the existing MCP tools (tg-mcp, kwork-inbox)
— it never re-implements transport. Wave 1 ships the Telegram connector +
connector-backed entity-browse routes; the approval queue (T1.4) and the Пульт
frontend (T1.7) import `getConnector` from here so adding a platform is one
`registerConnector(...)` line plus one connector file, never an
`if (platform === …)`.

## Data flow

«напиши Косте, что готово» → confirmed send (01-ARCHITECTURE §6):

```
Web ─POST /me/accounts/telegram:42/command {text} (SSE)─▶ me-accounts.ts
  command loop (flow model) picks intent {type:'send', payload:{to:'Костя', text}}
  connector.buildAction():
    resolveTarget('Костя') → resolveContact → get_dialogs fuzzy-match → entityId
    Action{ preview:{title,target,body}, dryRun:true }   ← NO send here
  (T1.4) INSERT entity_approval_queue status='armed' ─emit SSE draft {approvalId}─▶ Web
Web renders the action card → Подтвердить
  ─POST /me/approvals/:id/confirm─▶ (T1.4) atomic claim armed→executing
    getConnector('telegram').executeAction() → mcpDirect.callTool('telegram','send_message')
    status→executed, externalId set ─▶ Web flips card to «Отправлено ✓»
```

Entity-browse (T1.3, live now):

```
Web ─GET /me/accounts/telegram:42/connector/entities?kind=dialogs─▶ me-accounts.ts
  requireSession → resolveConnectorAccount (owner-scope) → browseEntities()
  getConnector('telegram').listEntities() → mcpDirect.callTool('telegram','get_dialogs')
  parseDialogs() → Entity[]  (degrades to [] + degraded:true on a connector throw)
```

## DB / Env / API

- Tables: none owned by connector-core (T1.4 adds `entity_approval_queue`). The
  Telegram connector reads `platformTgAccounts` indirectly via the existing
  `list_accounts` tg-mcp tool.
- Env: none new. The connector inherits the tg-mcp transport config from
  `services/mcp-direct.ts` (telegram server `@:4500`).
- Routes:
  - `GET /me/accounts/:id/connector/entities?kind=&q=&limit=` → `{ ok, entities, degraded? }`
  - `GET /me/accounts/:id/connector/entities/:eid/thread?kind=&limit=` → `{ ok, thread, degraded? }`
- MCP tools wrapped: `list_accounts`, `get_dialogs`, `get_messages`,
  `send_message` (telegram server).

## Failure modes

| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| Browse/execute hits an unregistered platform | `connector_not_registered` | `src/connector-core/registry.ts:19` |
| `executeAction` called on a malformed Action | `action_missing_dry_run_flag` | `src/connector-core/connectors/telegram.ts:321` |
| Unknown / unowned account id | `account_not_found` | `src/routes/me-accounts.ts:359` |
| Browse without `kind` | `missing_kind` | `src/routes/me-accounts.ts:357` |
| MCP timeout / tg-mcp down → empty list not a 500 | `degraded: true` | `src/routes/me-accounts.ts:369` |
| Send resolved no target / empty body | `no_target` / `empty_body` | `src/connector-core/connectors/telegram.ts:325` |
