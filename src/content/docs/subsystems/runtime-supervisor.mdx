# Runtime supervisor + preview-health gate

## TL;DR

Every peruser foundation project (kind ∈ {spa, mini_app, landing} with a cloned Next.js boilerplate) keeps running because four invariants hold at all times:

1. `/workspace/<slug>/.ports.env` exists with `PORT=<n>`.
2. `/workspace/<slug>/Procfile` sources `.ports.env` on every supervisor restart.
3. `/workspace/<slug>/.services/web/pid` points at the live web process — adopted from a running PID when missing.
4. `start_service` is idempotent — it returns `already_running` instead of relaunching when (a) the pidfile points at a live PID and (b) any declared port is bound.

Before 2026-05-22 these invariants drifted for legacy projects (Monar / 1292), causing EADDRINUSE relaunch loops, log spam, and preview-503s when `$PORT` expanded empty after a clean-env restart. The reconciler ticker now adopts legacy projects into the contract within ~10 minutes of agent boot.

## Reconcile contract

`runPeruserServicesReconcileTick` is **read-mostly** — never restarts the running web process. Its single mutation is to fill in missing platform metadata:

- `.ports.env` write guarded by `[ ! -f .ports.env ]`.
- `Procfile` rewrite guarded by `! grep -q '[ -f .ports.env ]' Procfile` (sentinel skip when bridge-generated Procfile already has it).
- PID adoption guarded by `[ ! -s .services/web/pid ]` AND `kill -0 "$CANDIDATE"` on the discovered PID.

The script emits one machine-parseable line — `RECONCILE: ports=<0|1> proc=<0|1> pid=<n|none>` — so the agent-side caller records a single structured `project_events.kind='log'` entry without re-grepping stdout.

PID discovery cascade: `lsof -t -i TCP:$PORT -sTCP:LISTEN` → `ss -lntp` (parse `pid=N`) → `/proc/net/tcp` (find LISTEN inode, follow `/proc/<pid>/fd/*` symlinks). The third path is the only one that works in a stripped Alpine-derived workspace image where neither `lsof` nor `ss` ship.

Per-project cooldown: 10 min between attempts. On first success the project lands in the `succeeded: true` slot of the in-memory state map and is skipped forever (until agent restart).

## start_service contract

```ts
{
  project: string,    // peruser slug
  name: string,       // service name (e.g. 'web')
  command: string,    // foreman-style web: line, NOT a full bash script
  cwd?: string,
  port?: number,      // optional — required for the port-bound idempotency check
  mode?: 'idempotent' | 'force', // default 'idempotent'
}
```

**Idempotency probe** runs inside the workspace pod before composing the launch script:

```sh
if [ -f .services/<name>/pid ]; then
  PID=$(cat .services/<name>/pid)
  if [ -n "$PID" ] && kill -0 "$PID" && ( ss -tln | grep ":<port>" || netstat -lnt | grep ":<port>" ); then
    echo "ALIVE:$PID"
  else
    echo "DEAD"
  fi
else
  echo "NOPID"
fi
```

Returns `{ ok: true, status: 'already_running', pid, port }` on `ALIVE:` — no kill, no relaunch. `mode: 'force'` skips the probe and always restarts; use it for code-redeploy / config-change paths.
