# Autonomous wake-loop closure

## TL;DR

The autonomous worker (`autonomous-worker.ts`) generates a daily plan per
active goal and dispatches the **first** task into `device_tasks`. Before
this change, nothing on the server consumed the daemon's `task_complete`/
`task_error` frames, so the rest of the day sat undispatched and goals
without milestones stayed dormant forever. This PR closes the loop:

1. The WS handler in `devices-ws.ts` flips `device_tasks.status` to
   `done`/`failed` on terminal frames and calls
   `consumeDeviceTaskOutcome` which stamps `plan_json.tasks[i].outcome`
   and fans out the next task.
2. Every dispatch (initial + fan-out) is gated by `assertWithinDailyCap`,
   reading from `autonomous_budget_ledger` and either the per-goal
   `daily_budget_usd` column or the env fallback
   `AUTONOMOUS_DAILY_CAP_USD` (default `5.00`).
3. `POST /me/autonomous/goals` immediately fires `decomposeGoalSync` so
   freshly-created goals land with milestones — no more
   `wake_skipped_no_milestone` rut.

The same PR fixes a P0 from cabinet QA: `POST /me/autonomous/goals` with
an ISO `deadline_at` was returning HTTP 500 because postgres-js was
binding a `Date` instance through a path that wanted a string. Now the
route passes the validated ISO string straight to the tagged template.

## Data flow

```
┌─────────────┐       ┌─────────────────────────┐       ┌──────────────────┐
│ POST goals  │──────▶│ autonomous_goals INSERT │──fire▶│ decomposeGoalSync│
└─────────────┘  201  └─────────────────────────┘  &fgt;│ → milestones INS │
                                                       └──────────────────┘

WAKE PASS (07:30 MSK ≈ 04 UTC)
  fetchActiveGoalsWithoutTodaysPlan
    └─▶ for each goal:
          llmPlanToday → INSERT autonomous_daily_plans
          assertWithinDailyCap(userId, goalId)
            └─▶ over cap?  log budget_cap_hit, skip dispatch
            └─▶ ok?         INSERT device_tasks (task_ordinal=0)

DAEMON ───── task_complete frame ─────▶ devices-ws.handleClientTaskFrame
                                          └─▶ finalizeDeviceTask(taskId,'done')
                                                ├─ UPDATE device_tasks SET status='done'
                                                └─▶ consumeDeviceTaskOutcome
                                                      ├─ stamp plan_json.tasks[i].outcome
                                                      ├─ log autonomous_loop_advanced
                                                      └─ assertWithinDailyCap → INSERT next ordinal
```

## DB / Env / API

**Tables**

- `autonomous_goals` — `daily_budget_usd NUMERIC(8,4)` (NULL → env fallback).
- `autonomous_daily_plans.plan_json.tasks[i].outcome = {status, completed_at, summary}` — stamped by the consumer.
- `device_tasks.status` CHECK now allows `('queued','dispatched','done','failed')`.
- `autonomous_budget_ledger` — read by the cap helper for today's SUM.

**Env**

- `AUTONOMOUS_DAILY_CAP_USD` — float USD, default `5.00`. Used when `autonomous_goals.daily_budget_usd` is NULL.
- `AUTONOMOUS_WAKE_HOUR_UTC` — unchanged, default `4`.

**Routes**

- `POST /me/autonomous/goals` — now auto-decomposes; accepts `deadline_at` as ISO string without 500.
- `POST /me/autonomous/goals/:id/decompose` — re-uses `decomposeGoalSync`.

**Internal exports**

- `consumeDeviceTaskOutcome(deviceTaskId, 'done'|'failed', summary?)` from `services/autonomous-worker.ts`.
- `assertWithinDailyCap(userId, goalId?)` from `services/autonomous-budget.ts`.
- `decomposeGoalSync(userId, goalId)` from `routes/me-autonomous.ts`.
