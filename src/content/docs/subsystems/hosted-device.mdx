# Hosted Device

## TL;DR

Hosted Device — это StatefulSet в персональном vcluster пользователя
(`af-tenant-<userId>`), управляемый через REST поверх `/me/hosted-devices`.
Два режима: `kind=plain` (python:3.11-slim с `/health`-заглушкой —
дешёвая проверка что vcluster жив) и `kind=daemon` (полноценный
`ghcr.io/lnlockly/agentflow-daemon:latest` с Xvfb + Chromium + Playwright
+ всеми af_* инструментами — Mac-аналог, только в облаке).

Кабинетная страница `/cabinet/devices/hosted/:id` показывает живой pulse
по статусу, события Kubernetes, веб-терминал, стрим логов и кнопки
питания.

## Data flow

```
Browser                                                                
  │                                                                    
  │ POST /me/hosted-devices {name,size,kind}                           
  ▼                                                                    
agentflow-agents (Hono)                                                
  │ INSERT hosted_devices row (status=provisioning)                    
  │ render kind-specific manifest                                      
  │ kubectl --kubeconfig=<sealed user kc> apply -f -                   
  ▼                                                                    
vcluster af-tenant-N (default ns)                                      
  │ Service + StatefulSet                                              
  │ Pod scheduled, image pulled, container running                     
  ▼                                                                    
  │ (kind=daemon) pod boots → daemon opens WS /_devices/connect          
  │   `hello` handler flips hosted_devices.status provisioning→running   
  │   for the row whose user_device_id == ctx.deviceId (event-driven)     
  ▼                                                                    
GET /me/hosted-devices/:id  →  live_phase из kubectl get pod (lazy refresh)
GET /me/hosted-devices/:id/events  →  kubectl get events --sort        
POST /me/hosted-devices/:id/exec   →  kubectl exec -i pod -- sh -c     
GET /me/hosted-devices/:id/logs    →  SSE: kubectl logs -f --tail=200  
POST /me/hosted-devices/:id/power  →  kubectl scale / rollout restart  
DELETE /me/hosted-devices/:id      →  kubectl delete sts + soft delete 
```

Все kubectl вызовы используют **sealed kubeconfig** из колонки
`users.tenant_kubeconfig_sealed` — никакого cross-tenant доступа.

## DB / Env / API

- **Таблица**: `hosted_devices(id UUID, user_id, name, size, status, vcluster, sts_name, created_at, last_status_at, deleted_at)`.
- **Env**: на стороне agentflow-agents не нужно ничего сверх обычного (kubeconfig внутри pod юзера хранится в `users.tenant_kubeconfig_sealed`, расшифровывается через `unsealValue`).
- **Routes**:
  - `POST   /me/hosted-devices` — `{name?, size, kind?}` → 201 row.
  - `GET    /me/hosted-devices` — список (50 свежих, без deleted).
  - `GET    /me/hosted-devices/:id` — детали + `live_phase`.
  - `GET    /me/hosted-devices/:id/events` — kubectl events, newest-first.
  - `POST   /me/hosted-devices/:id/exec` — `{command, timeout_s?, shell?}` → `{stdout, stderr, exit_code, duration_ms}`.
  - `GET    /me/hosted-devices/:id/logs` — SSE `event: line | err | end`.
  - `POST   /me/hosted-devices/:id/power` — `{action: 'start'|'stop'|'restart'}`.
  - `DELETE /me/hosted-devices/:id` — soft delete + kubectl delete sts/svc.
- **MCP tools**: пока нет; будет в `agentflow-mcp-server` когда стабилизируется.

## Failure modes

| Симптом | Лог-сигнатура для grep | Где чинить |
|---|---|---|
| 409 `tenant_not_ready` | `tenant_kubeconfig_sealed IS NULL` | прогнать tenant-bootstrap для юзера |
| Pod вечно Pending | events → `FailedScheduling: 0/N nodes available` | расширить ResourceQuota или освободить ноды |
| 500 `apply failed` | `[hosted-devices] apply failed` | проверить sealed kubeconfig (мог протухнуть) |
| Daemon Pod в CrashLoopBackOff | kubectl logs → `Xvfb: command not found` | пересобрать образ (Dockerfile отбросил пакет?) |
| `/exec` возвращает `exit_code=126` | stdout пустой, stderr `command not found` | пользователь команды на `sh -c` (не bash builtin) |
| SSE `/logs` мгновенно `end` | stderr из kubectl `pod not found` | подождать readiness или перезапустить через `/power restart` |
| `/power restart` 500 | stderr `forbidden: cannot patch sts` | sealed kc выписан без `apps/statefulsets/patch` (старые юзеры) |
| `{template:'goose'}` (или любой template) даёт python-заглушку, recipe-dispatch молча no-op | pod `image: python:3.11-slim` + `name: runtime`, в логах нет `[coder-shim] connecting`; create-ответ `kind:"plain","template":"coder"` | `resolveCreateKind` в `me-hosted-devices.ts` — template без явного `kind` теперь форсит `kind:'daemon'` (PR #980). До фикса: всегда слать `kind:'daemon'` вместе с template |
| Daemon WS-connected (`[device] online`) но `hosted_devices.status` залип `provisioning` (cabinet показывает «провижн» вечно; warm-row не выглядит ready) | строка `hosted_devices` `status='provisioning'` хотя `user_devices.status='online'` и есть `last_seen`; нет `hosted_device_status_flip_failed` | До фикса: `hosted_devices.status` уходил из `provisioning` ТОЛЬКО через ленивый kubectl-чек в `GET /me/hosted-devices/:id`. Теперь WS `hello` handler флипает `provisioning/error → running` по `user_device_id == ctx.deviceId` (event-driven). `agentflow-agents/src/services/devices-ws.ts` (hello) |

> **Footgun (исправлено, PR #980):** `template` выбирает ТОЛЬКО daemon-образ
> и бессмысленен для `plain`. Раньше `POST { template:'goose' }` без `kind`
> проходил canary-gate, но падал в `kind:'plain'`, где handler сбрасывал
> template обратно в `'coder'` и рендерил python-заглушку — «online»
> устройство без daemon, без devices-ws bridge, молча игнорирующее каждый
> `agent_run_recipe`. `resolveCreateKind(body, kind, template)` теперь
> коэрсит `kind→'daemon'` когда указан template и `kind` не задан явно.

## kind=plain vs kind=daemon

| | plain | daemon |
|---|---|---|
| Образ | `python:3.11-slim` | `ghcr.io/lnlockly/agentflow-daemon:latest` |
| Что делает | `/health` HTTP сервер на :8080 | Xvfb на :99 + `agentflow-desktop run --headless` |
| Память | 64 МБ floor | 384 МБ floor (Chromium резидент ~150 МБ) |
| Стартует за | ~5 с | ~20-30 с (initialDelaySeconds=20 для readiness) |
| Когда выбирать | проверить что vcluster жив, дёшево | реально что-то делать через af_* |

`kind` поле задаётся в `POST /me/hosted-devices`. По умолчанию `plain`.
