# Activepieces marketplace

## TL;DR
Activepieces (MIT, self-hosted, 4 pods in `franchise-factory`) replaces the
hand-written marketplace. Users build no-code flows from a 280+ piece catalog.
A standalone `kwork-rest-bridge` pod exposes AgentFlow's MCP servers (Kwork +
Telegram MTProto) to AP flows over plain HTTP. `POST /me/flows/sso` provisions
an AP user per AgentFlow owner and returns a JWT.

**SEAM 2 (2026-05-29):** the marketplace UI is a REBRANDED separate app at
`flows.agentflow.website` reached via SSO **redirect**, NOT an iframe (AP embed
mode is paid EE; iframe CSS-hacks break on upgrade + are bad on mobile). The
cabinet `/flows` launcher calls `/me/flows/sso`, then redirects the browser to
`flows.agentflow.website/sso-handoff#token=<jwt>&projectId=<id>`. A tiny nginx
page (`flows-sso-handoff`) persists the token to `localStorage` (`token` +
`projectId`) and redirects to `/`; the AP SPA's `AllowOnlyLoggedInUserOnlyGuard`
sees a valid token and lands the user authenticated. Integration level =
Level 1 (SSO + redirect), not a fork (the fork patches live on branches in
`lnlockly/agentflow-flows` but the live CE pods still run upstream 0.83.0).

## Data flow

```
cabinet/flows
   │  POST /me/flows/sso   (requireSession; af_live_* | bearer | cookie)
   ▼
agentflow-agents → activepieces-sso.provisionApUser(ownerUserId)
   │  first call:  AP invite → accept → sign-up   (AP REST, invite-only)
   │  later calls: AP sign-in (sealed password)
   │  → ap_user_links { owner_user_id → ap_user_id, ap_project_id, sealed pw }
   ▼
{ jwt, apProjectId, publicUrl }
   ▼  (SEAM 2 — redirect, NOT iframe)
cabinet /flows (FlowsLaunch) → window.location.assign(
     flows.agentflow.website/sso-handoff#token=<jwt>&projectId=<apProjectId> )
   ▼
flows-sso-handoff (nginx): localStorage.token = jwt; localStorage.projectId = id
   → location.replace('/')  → AP SPA logged-in guard → flows dashboard (authed)

flow run (AP worker pod)
   │  HTTP piece → kwork-rest-bridge
   │    auth: x-bridge-secret + (Bearer af_live_* | body.ownerUserId)
   ▼
   ├─ /kwork/*  → MCP /internal/mcp/kwork-inbox  (x-mcp-auth: INTERNAL_API_SECRET)
   └─ /tg/*     → MCP agentflow-tg-mcp:4500/mcp  (x-mcp-auth: MCP_AUTH_SECRET)
                    → Telethon MTProto → real Telegram
```

`Bearer af_live_*` → ownerUserId resolution: the bridge calls
`GET /me/flows/whoami` with the key in `x-api-key` (cached). No HMAC secret is
duplicated into the bridge.

### Install (SEAM 5 — catalog → IMPORT_FLOW)

```
/marketplace  «Install»  →  POST /me/marketplace/:slug/install (requireSession)
   │  load marketplace_templates row by slug
   ▼
 engine='legacy'        → clone studio graph into /me/flows (copy-to-studio)
                          → { ok, engine:'legacy', flow:{slug}, studio_url }
 engine='activepieces'  → activepieces-install.importFlowForOwner(ownerUserId, tmpl)
                            │  provisionApUser(ownerUserId)  → { jwt, apProjectId }
                            │  POST /api/v1/flows {projectId,displayName} → empty flow id
                            │  POST /api/v1/flows/:id {type:'IMPORT_FLOW', request:tmpl.workflow.ap_flow}
                            ▼  store marketplace_template_installs(owner,slug → apFlowId)
                          → { ok, engine:'activepieces', apFlowId, editUrl, already }
```

Idempotent on `(owner_user_id, template_slug)` — a second install reuses the
stored `ap_flow_id`. `engine='activepieces'` template `workflow` jsonb shape:
`{ ap_flow:{ displayName, trigger }, edit_path?:'/flows/{flowId}' }`. The
`ap_flow` is AP's own template export (`GET /api/v1/flows/:id/template` →
`flows[0]`), replayed verbatim.

  branding after the handoff.

## Building flows programmatically
Hand-built `UPDATE_TRIGGER`/`ADD_ACTION` envelopes fail AP's strict validator
(`body/ Invalid input`). Use **`IMPORT_FLOW`** (`POST /api/v1/flows/{id}`
`{type:'IMPORT_FLOW', request:{displayName, trigger:{…nextAction chain…}}}`) —
the server decomposes it into validated ops. Then `LOCK_AND_PUBLISH` +
`CHANGE_STATUS{status:'ENABLED'}`. Trigger `type` is the enum **value**
`PIECE_TRIGGER`; action `type` is `PIECE`.

**Verified live 2026-05-29 (AP v0.83.0).** Two more constraints that cause the
`body/ Invalid input` 400 even with `IMPORT_FLOW`:
- `trigger.settings.pieceVersion` MUST be an **exact** version (`"0.1.17"`), not
  a `~`/`^` semver range. A range fails the validator.
- `trigger.settings` MUST carry `inputUiInfo:{}` + `propertySettings:{}` next to
  `pieceName/pieceVersion/triggerName/input`.

The reliable source of a valid `request` is AP's own export
`GET /api/v1/flows/:id/template` → `flows[0]` (displayName + full trigger chain).
SEAM 5 stores that export verbatim as the template's `workflow.ap_flow` and
replays it on install.

## Failure modes
| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| Flow run `INTERNAL_ERROR`, no steps | `Error: Authentication type is required` | HTTP piece `authType` must be `'NONE'` (uppercase); webhook trigger `authType` `'none'` |
| Webhook 200 but no run created | (worker `EXECUTE_WEBHOOK` then nothing) | webhook trigger `input` missing `{authType:'none'}` |
| Run stuck `RUNNING` then worker restart | `OOMKilled` on `activepieces-worker` | worker memory limit raised to 2Gi |
| Approval step `FAILED` | `Bad Request: unsupported parse_mode` | `request_approval_message` `parse_mode` must be `'None'` (plain text) |
| Bridge `Bearer` path 502 | `api_key_resolve_failed_404` | `/me/flows/whoami` not deployed yet (deploy agents) |
| SSO 503 | `activepieces_disabled` / `ap_admin_jwt_not_configured` | set `FF_ACTIVEPIECES_ENABLED=1` + `AP_ADMIN_JWT` |
| `/flows` shows "Автоматизации скоро откроются" | (FlowsLaunch catches AgentsApiError 503) | flag/admin-jwt not set — same fix as SSO 503 |
| Handoff page shows "Не передан токен входа" | (handoff `fail()` — no `token` in fragment) | cabinet reached `/sso-handoff` directly; open Flows from the cabinet |
| `flows-sso-handoff` CrashLoopBackOff | `open() "/run/nginx.pid" failed (30: Read-only file system)` | nginx.conf must set `pid /tmp/nginx.pid` + temp paths under `/tmp` (rootfs is read-only) |
| AP redirects to `/sign-in` after handoff | (token expired / wrong key) | re-call `/me/flows/sso` for a fresh JWT; handoff writes keys `token`+`projectId` |
| Install IMPORT_FLOW 400 | `ap_import_flow_failed_400_` + `body/ Invalid input` | template `workflow.ap_flow` has a `~`/`^` pieceVersion or missing `propertySettings`/`inputUiInfo` — re-export via `/template` |
| Install 500 | `template_missing_ap_flow` | `engine='activepieces'` row missing `workflow.ap_flow.{displayName,trigger}` — fix the seed |
| Install 503 | `activepieces_disabled` (from importFlowForOwner) | AP env not set on agents — set `FF_ACTIVEPIECES_ENABLED=1` + `AP_ADMIN_JWT` |
