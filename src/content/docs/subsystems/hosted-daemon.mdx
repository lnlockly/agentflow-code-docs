# Hosted Daemon (kind=daemon)

## TL;DR

`kind=daemon` запускает полноценный AgentFlow Desktop runtime
(`ghcr.io/lnlockly/agentflow-daemon:latest` — Xvfb + Chromium +
Playwright + computer-use tools) внутри vcluster пользователя. WS
handshake идёт через тот же `/me/devices/connect`, что и Mac-демон, —
оба авторизуются как rows в `user_devices`. Cabinet `/cabinet/devices/hosted/:id`
показывает task composer для kind=daemon (та же поверхность что
`CabinetDeviceLive` для Mac, без MJPEG-стрима).

| `ghcr.io/lnlockly/agentflow-daemon-universal:<sha>` | `docker/Dockerfile.universal` | xvfb, fluxbox, chromium+driver, x11vnc, novnc, websockify, ffmpeg, playwright | ~1.4 GB |

Legacy tag `ghcr.io/lnlockly/agentflow-daemon:<sha>` is aliased to
`-universal` in `.github/workflows/docker-image.yml` so existing

`renderDaemonManifest` keep pulling without coordination. The cabinet
selector + manifest rewrite to per-variant tags lands in the
DB+UI / resolver follow-up PRs.

## Data flow

```
Cabinet «Создать»
   │ POST /me/hosted-devices {kind=daemon, size, name}
   ▼
me-hosted-devices.ts
   ├── mint user_devices row    (enrollment_token, TTL 30d)
   ├── mint api_keys row        (af_live_*, name=hosted:<base>)
   ├── newRotationSecret        (хэш в hosted_devices.rotation_secret_hash)
   └── INSERT hosted_devices    (kind, user_device_id, rotation_secret_hash)
   │
   │ wakeTenantVcluster(userId)
   │  → agentflow-api POST /internal/users/:id/wake-vcluster
   │  → kubectl scale sts user-<id> --replicas=1 if hibernated
   │  → kubectl wait pod ready (120s)
   │
   │ kubectl apply -f <manifest>  (с env-вбросом всех 4 секретов)
   ▼
af-tenant-<userId>:<pod>  (daemon container)
   │ entrypoint.sh
   │  ├── Xvfb (always)
   │  ├── (опц.) fluxbox+x11vnc+novnc если AF_ENABLE_SCREEN=1
   │  └── write_hosted_auth():
   │        ├── POST /me/hosted-devices/<HOSTED_ID>/reenroll
   │        │       {rotation_secret: AF_HOSTED_ROTATION_SECRET}
   │        │      → {enrollment_token, device_id, ttl_sec}
   │        └── ~/.agentflow/auth.json (mode 0600)
   ▼
agentflow-desktop run --headless
   │ ws connect wss://agentflow.website/_agents/_devices/connect
   │ headers: x-api-key, x-device-id, x-enrollment-token
   ▼
devices-ws.ts performHandshake
   │ enrollment_token path → user_devices.status='online'
   │ + freshSecret в hello_ack
   ▼
Daemon в /cabinet/devices/hosted/:id
   │ DaemonTaskPanel
   │ POST /me/devices/<user_device_id>/dispatch_task {task}
   │ SSE /me/devices/<user_device_id>/tasks/stream
```

## DB / Env / API

**Tables:**
- `hosted_devices` — `id`, `user_id`, `kind` ('plain'|'daemon'), `user_device_id`
  FK → user_devices(id), `rotation_secret_hash` (SHA-256 hex)
- `user_devices` — стандартный row, `device_secret_hash` сбрасывается на
  каждом `/reenroll` чтобы старый secret больше не подходил
- `api_keys` — row с `name='hosted:<base>'` для опознания: при DELETE
  hosted-device можно revoke этот key точечно (TODO в hosted cleanup).
  `scopes=["device:ws","device:reenroll"]` (вместо `[]` full-owner) —
  documentary до тех пор пока enforcement не подключён к
  `requireSession`/`devices-ws` (отдельный backlog item)

### Shell whitelist (`AF_SHELL_WHITELIST`)

Hosted-daemon scopes default to `shell_whitelist=[]`. Empty whitelist
means every `code_run_command` raises `shell_whitelist is empty;
shell.exec disabled` (`scope.py:51`) → the autonomous loop's session
terminates with `=== COMPLETION_BLOCKED ===` after the first
`git fetch` / `pytest` / `npm install`.

`docker/entrypoint.sh` now exports a sensible baseline whenever the env
var is not set:

```
ls, cat, head, tail, grep, find, wc, tree, pwd, whoami, env, echo, date, uname, which, file, stat
git, gh
node, npm, yarn, pnpm, npx, tsc
python, python3, pip, pip3, uv, pytest, ruff, black, mypy
docker, kubectl
curl, wget, jq
mkdir, rmdir, rm, cp, mv, touch, chmod, ln
tar, gzip, gunzip, unzip, zip
bash, sh, awk, sed
make, cmake, go, cargo, rustc
```

Parsing rules (see `config.py:parse_shell_whitelist_env` +
`tests/test_shell_whitelist_env.py`):

- comma-, newline-, and whitespace-separated all work, in any mix
- blank lines and `# comments` ignored
- duplicates collapse, first occurrence wins (stable order across boots)
- env entries come first; an existing `~/.agentflow/computer-scope.toml`
  `shell_whitelist` extends the env baseline (env-only entries first,
  file-only entries appended)
- per-task scope on the WS `task_dispatch` frame still wins last —
  owner narrows or widens per dispatch via `POST /me/devices/:id/scope`

Argument-level guard for recursive `rm` lives in
`scope.py:check_shell` — every shape (`-r`, `-R`, `-rf`, `-fr`, `-rfv`,
`--recursive`) raises `ScopeDenied("rm with recursive flag is denied")`
even when `rm` itself is whitelisted.

**Pod env** (только при `kind=daemon`):
- `AF_DEVICE_ID` — UUID из user_devices
- `AF_HOSTED_DEVICE_ID` — UUID из hosted_devices (для /reenroll URL)
- `AF_ENROLLMENT_TOKEN` — initial one-time token (30d TTL), используется
  если /reenroll недоступен
- `AF_HOSTED_ROTATION_SECRET` — long-lived `afh_<hex>`, постоянный весь
  lifetime пода. Эквивалент service-account-token внутри vcluster.
- `AF_API_KEY` — `af_live_<hex>`, scope=`["device:ws","device:reenroll"]`,
  для devices-ws.ts `x-api-key` header
- `AF_API_URL` — `https://agentflow.website`
- `AF_SHELL_WHITELIST` — comma/newline/whitespace-separated programs
  the daemon may pass to `code_run_command`. Default baked into
  `docker/entrypoint.sh` (see "Shell whitelist" above). Override per-pod
  by setting this env in the pod manifest renderer
  (`me-hosted-devices.ts:renderDaemonManifest`).

**Routes:**
- `POST /me/hosted-devices` (requireSession) — создаёт kind=daemon
- `POST /me/hosted-devices/:id/reenroll` (NO auth — rotation_secret IS the auth)
- `DELETE /me/hosted-devices/:id` (requireSession) — soft-deletes paired user_devices

**MCP tools:** не задействуются — flow проходит через REST.

## Failure modes

| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| Daemon контейнер в CrashLoopBackOff с "no_credential" в логах | `[entrypoint] no enrollment_token available` | проверь что AF_ENROLLMENT_TOKEN либо AF_HOSTED_ROTATION_SECRET в env пода (`kubectl describe pod`) |
| `/reenroll` 401 при старте | `[entrypoint] /reenroll failed` | hosted_devices.rotation_secret_hash NULL — это старый row (до миграции), пересоздай hosted device |
| WS handshake `device_not_found` | `[devices-ws] device_not_found` | hosted_devices.user_device_id NULL — backend bug, проверь что INSERT user_devices прошёл в POST handler |
| Pod OOMKilled через 30s | `Reason: OOMKilled` в `kubectl describe pod` | size='small' для kind=daemon — UI должен был форснуть medium, но кто-то прокликал API напрямую |
| Daemon селtест вместо handshake | `[entrypoint] AF_API_KEY missing — running selftest only` | AF_DEVICE_ID не пришёл в env, manifest renderer не сработал — проверь backend logs `[hosted-devices] api_key mint failed` |
| POST /me/hosted-devices 500 + no rows written | `[hosted-devices] provision tx rolled back` | один из INSERTов внутри `sql.begin` упал — три row (user_devices/api_keys/hosted_devices) откатились вместе; ищи root cause по сообщению после префикса |
| Chromium падает на старте | `Failed to launch the browser process` в логах daemon | `--no-sandbox` не передан или Xvfb не поднялся — `kubectl logs <pod> -c daemon \| head -50` |
| Autonomous goal queued таск, daemon online (heartbeat жив), но `task_dispatch` в логах daemon не появляется и `device_sessions` не растёт | `device_tasks` row `status='queued'` или `'dispatched'` без последующего `[device] queued_tasks_dispatched` и без `ws task_dispatch id=<uuid>` на стороне daemon | Backend в `me-autonomous.ts:plan_today` или `autonomous-worker.ts:wake/fan-out` пропустил вызов `dispatchOrQueueDeviceTask` и просто INSERT-нул queued row. Helper в `routes/me-devices.ts:dispatchOrQueueDeviceTask` обязан вызываться для каждого нового device_task — он смотрит `getConnection(deviceId)` и пушит WS frame для уже подключённого daemon. Голый INSERT работает только если daemon переподключится (heartbeat keep-alive это блокирует). |
| POST /me/hosted-devices succeeds, row сидит в `status='provisioning'` навсегда у юзеров 18 / 164 / 279, при этом юзер 1 всё ок | `[hosted-devices] wake_vcluster_not_ready id=<uuid> user=<id> … detail=wake_http_403` (RBAC) OR `detail=pod_ready_wait_failed:` (vcluster pod scheduling/image-pull fail) | RBAC drift: проверить `kubectl get clusterrolebinding agentflow-api-tenant-admin` — должен существовать (не закоммичен в `agentflow-api/k8s/deployment.yaml`, только в проде). Если ready=false но wake.woken=true → vcluster pod не поднялся в 120 s — смотреть `kubectl -n af-tenant-<id> describe pod -l app=vcluster,release=user-<id>` |
