# kwork-connector

## TL;DR

The Kwork connector is a thin adapter over the `kwork-inbox` MCP server. Every
read tool (`list_dialogs`, `list_wants`, `list_my_kworks`, `get_dialog`) returns
typed errors as data — including auth/cookie failures. Before this fix the
connector's `arrayFrom`/`parse*` helpers collapsed any `{error}` envelope into
`[]`, so an expired session looked identical to a genuinely empty inbox: the
Пульт's Диалоги showed «пока пусто» even though the real reason was «Kwork
cookies истекли». The connector now detects auth/cookie errors via
`kworkReauthError`, raises `ConnectorError('reauth_required', 'kwork')`, and the
browse route surfaces a typed `needsReauth:true, reason:'reauth_required'` empty
state for the UI.

## Cookie-refresh requirement

Kwork sessions are stored as cookies (raw header or Playwright `storage_state`
JSON) in `project_secrets` / the credential vault under `KWORK_SESSION_JSON`
(resolved by `resolveSessionCookies` / `resolveCredential('kwork')`). Kwork
cookies expire — when they do, the MCP serves a `/login` redirect or the «Вход
на сайт» HTML on an authenticated path, which `kworkRequest` maps to
`{error:'auth_expired'}`. There is no silent refresh: the owner must paste a
fresh session via Settings → Secrets (or the in-Пульт reconnect flow). Until
they do, every kwork read returns `needsReauth` and no live data — by design, so
the UI never renders stale or fake dialogs.

## Data flow

```
Web ─GET /me/accounts/kwork:<id>/connector/entities?kind=dialogs─▶ me-accounts.ts
  browseEntities() → getConnector('kwork').listEntities('dialogs')
    mcpDirect.callTool('kwork-inbox','list_dialogs', {KWORK_SESSION_JSON})
      ├─ valid cookies   → {ok,dialogs:[…]} → parseDialogs → Entity[]
      ├─ expired cookies → {error:'auth_expired'} → kworkReauthError ≠ null
      │     → throw ConnectorError('reauth_required','kwork')
      │     → browseEntities catches → {ok:true, entities:[], needsReauth:true,
      │        reason:'reauth_required'}      ← UI shows «Переподключите Kwork»
      └─ transient err   → {error:'rate_limited'|'http_error'|…} → []  (degraded:true)
```

`auth_expired`, `session_secret_not_found`, `session_secret_unseal_failed`,
`session_secret_empty`, `bad_secret_key_format`, and `creds_error*` are treated
as reauth. `rate_limited`, `banned`, `captcha`, `http_error`, `network_error`,
`wants_not_found` stay on the existing degrade-to-empty path (transient /
platform-side, not a session problem).

## DB / Env / API

- Secrets: `KWORK_SESSION_JSON` (project_secrets / vault kind `kwork`) — the
  session cookies. Refreshed by the owner, never auto-rotated.
- Routes (response shape extended, not broken):
  - `GET /me/accounts/:id/connector/entities?kind=` → `{ ok, entities, degraded?, needsReauth?, reason? }`
  - `GET /me/accounts/:id/connector/entities/:eid/thread?kind=` → `{ ok, thread, degraded?, needsReauth?, reason? }`
- MCP tools wrapped: `list_dialogs`, `list_wants`, `list_my_kworks`,
  `get_dialog`, `respond_to_want` (kwork-inbox server).
