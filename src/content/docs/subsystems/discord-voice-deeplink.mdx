# Discord voice deeplink

## TL;DR

A toolbar button in the chat-room header that opens
`https://discord.com/channels/<guild>/<channel>` in a popup window. Visible
only when the Matrix room is bridged to a Discord channel by mautrix-discord.
Replaces a 3-4 week LiveKit WHIP + DAVE E2EE build with a half-day deeplink.
Mautrix-discord does not bridge voice — this is the pragmatic interim.

## DB / Env / API

- Tables: none
- Env: none
- Routes: none new — uses existing `POST /me/events` via `src/lib/track.ts`
- Matrix state events read: `m.bridge`, `m.room.canonical_alias`

## Source priority

`buildDiscordDeeplink` evaluates two metadata sources from the sync payload:

1. **`m.bridge` state event** — content shape `{ network: "discord", channel: { id, type, guild: { id } } }`. Written by current mautrix-discord versions.
2. **`m.room.canonical_alias`** — pattern `#_discord_<guild>_<channel>:agentflow.website`. Fallback for older bridge versions.

Returns `null` when neither yields both ids; the button hides.

## Failure modes

| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| Button renders for non-Discord room | `canonicalAlias is null and bridgeInfo is null` reaching `buildDiscordDeeplink` | `src/lib/discord-deeplink.ts:46` |
| Popup blocked | `window.open` returns null (no log; user complains) | document; rely on browser user-gesture allowlist |
| User not authed in browser Discord | Discord login page shown in popup | acceptable; no cabinet impact |
| Bridge metadata missing | `bridgeInfo is null` despite room being discord-bridged | `parseSync` not seeing `m.bridge` — check Dendrite room state |

## Out of scope

- In-cabinet voice (LiveKit WHIP / DAVE E2EE): separate 3-4 week effort. Discord's DAVE encryption is mandatory for new voice deployments and requires a custom WHIP relay with mlspp.
- Channel picker UI: not needed — one Matrix room maps to one Discord channel.
- Voice-channel participants display: handled by Discord itself in the popup.
