# Devices — unified routing

## TL;DR

Local computers (Mac/Win/Linux installer daemons) and hosted-daemon pods
(kind=daemon hosted runtimes inside the per-user vcluster) used to live
under two separate cabinet URLs: `/cabinet/devices/:id` for local and
`/cabinet/devices/hosted/:id` for hosted. They've always shared the same
`user_devices` row substrate — the hosted row was just the linked image
of the pod. This rewrite collapses the URL surface to a single
`/cabinet/devices/:id` (where `:id` is the `user_devices.id`) and routes
the legacy hosted URLs through a redirect component.

The Live page (MJPEG, task composer, action timeline, cost ledger,
sessions) now works identically for local daemons and hosted-daemon
pods. Hosted-only meta (vcluster, size, preinstall) renders as a compact
sub-section under the page header.

## Data flow

```
User clicks card on /cabinet/devices
   │
   ├── Local Mac (user_devices.id = ud-1, no hosted row)
   │     └── /cabinet/devices/ud-1                           (CabinetDeviceDetail)
   │     └── /cabinet/devices/ud-1/live                      (CabinetDeviceLive, kind=local)
   │
   ├── Hosted daemon (hosted_devices.id = hd-7, user_device_id = ud-9)
   │     └── /cabinet/devices/ud-9                           (CabinetDeviceDetail)
   │     └── /cabinet/devices/ud-9/live                      (CabinetDeviceLive, kind=hosted,
   │                                                          renders <HostedSubSection />)
   │
   └── Legacy bookmark to /cabinet/devices/hosted/hd-7
         └── HostedDeviceRedirect fetches /me/hosted-devices/hd-7
               ├── kind=daemon → <Navigate to=/cabinet/devices/ud-9 replace />
               └── kind=plain  → renders CabinetHostedDeviceDetail (no unified surface yet)


GET /me/devices/:id  (backend resolver)
   │
   │ SELECT ud.*, hd.* FROM user_devices ud
   │   LEFT JOIN hosted_devices hd ON hd.user_device_id = ud.id
   │  WHERE ud.user_id = $userId AND (ud.id = $id OR hd.id = $id)
   │
   ├── ud.id matched + no hosted row    → { kind: 'local',  hosted: null }
   ├── ud.id matched + hosted row joined → { kind: 'hosted', hosted: {…} }
   └── hd.id matched (ud.id ≠ $id)      → { kind: 'hosted', hosted: {…},
                                            device.id = ud.id }
                                            ← Frontend useEffect redirects URL to ud.id
```

## DB / Env / API

- Tables: `user_devices` (id, scope_json, last_seen, deleted_at), `hosted_devices` (id, user_device_id FK, kind, vcluster, sts_name, size, preinstall_json)
- Env: none new — relies on existing `requireSession` auth
- Routes:
  - `GET /me/devices/:id` — unified, accepts either id type, returns `{ device, kind, hosted }`
  - `GET /me/hosted-devices/:id` — unchanged; still used by HostedDeviceRedirect + plain pods
  - `POST /me/hosted-devices/:id/power` — unchanged; hosted-only start/stop/restart pod
- Cabinet routes:
  - `/cabinet/devices/:id` — primary, accepts user_devices.id
  - `/cabinet/devices/:id/live` — Live page for both kinds
  - `/cabinet/devices/hosted/:id` — legacy, redirects via HostedDeviceRedirect
  - `/cabinet/devices/hosted/:id/live` — legacy, redirects via HostedDeviceRedirect
  - `/cabinet/devices/hosted/new` — unchanged create-wizard

## Failure modes

| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| Hosted bookmark renders detail page even when daemon kind | (none — silent fallback) | `agentflow-landing/src/pages/HostedDeviceRedirect.tsx:65` — check `user_device_id` came back from API |
| Live page stuck on legacy URL after click | (none — useEffect skipped) | `agentflow-landing/src/pages/CabinetDeviceLive.tsx:494` — verify `device.id !== id` branch |
| `GET /me/devices/:hostedId` returns 404 for plain hosted pod | `not_found` | Expected — plain pods have no user_devices row. Use `/me/hosted-devices/:id` |
| Hosted sub-section never appears on Live page | response missing `kind: 'hosted'` | Check backend JOIN — `hosted_devices.user_device_id` may be NULL on older rows |
