# Kwork Integration (`POST /me/integrations/kwork`)

## TL;DR

Desktop daemon scrapes Kwork cookies from the operator's logged-in
browser and POSTs them to AgentFlow. The endpoint validates the cookie
shape, seals the payload into `project_secrets.KWORK_SESSION_JSON`,
forks the `kwork-account-replier` preset as a fresh project owned by
the caller, and provisions an agent on the user's default team. Same
cookies posted twice return the original project with the secret
refreshed in place.

This file documents the daemon-fed surface only. The paste-JSON UX
under `/me/integrations/kwork/connect` is described in
`me-integrations-kwork.ts` header and is kept on a separate router so a
regression in one cannot break the other.

## Data flow

```
agentflow-desktop daemon
   │  scrapes cookies via Playwright storage_state()
   │  POST /me/integrations/kwork
   │  body: { cookies: [{name,value,domain,path,...}], project_name? }
   ▼
me-integrations.ts: dispatchKworkIntegration(ownerUserId, body)
   ├── zod parse                              → 400 no_cookies on shape miss
   ├── any cookie name matches kwork regex?   → 400 no_kwork_session_cookie
   ├── getPreset('kwork-account-replier')     → 409 preset_missing if gone
   ├── hashCookies(sorted JSON)               → 16-hex digest
   │
   ├── SELECT user_integrations WHERE hash = …
   │     │  HIT  → UPDATE project_secrets value_encrypted, return 200 created=false
   │     │  MISS → fall through
   │
   ├── INSERT projects (kind='integration_kwork', status='idle')
   ├── INSERT project_secrets (KWORK_SESSION_JSON, sealed payload)
   ├── INSERT project_secrets (KWORK_TEAM_ID) IF user has default team
   ├── provisionAgent({preset character, slugBase='kwork-account-replier'})
   ├── INSERT team_members (teamId, agentId) IF team known
   ├── INSERT user_integrations (user_id, 'kwork', project_id, cookie_hash)
   ▼
201 { ok, project_id, project_slug, agent_id, secret_key, created:true }
```

## DB / Env / API

- **Tables:**
  - `user_integrations` — idempotency anchor `(user_id, kind, cookie_hash)` UNIQUE.
  - `projects` — fresh row `kind='integration_kwork'`.
  - `project_secrets` — sealed `KWORK_SESSION_JSON` (load-bearing) + `KWORK_TEAM_ID` (optional).
  - `agents` + `team_members` — populated by `provisionAgent`; best-effort.
- **Env:** `AGENTS_MASTER_KEY` (32-byte base64) — fail-loud if absent; required by `sealString`.
- **Routes:**
  - `POST /me/integrations/kwork` (this page, daemon-fed)
  - `POST /me/integrations/kwork/connect` (paste-JSON UX, separate router)
- **Preset slug:** `kwork-account-replier` (must be `status='active'` in `agent_presets`).

## Failure modes

| Symptom | Log signature for grep | Where to fix |
|---|---|---|
| Daemon POST returns 400 on every cookie batch | `no_kwork_session_cookie` | `agentflow-agents/src/routes/me-integrations.ts:147` — extend `KWORK_COOKIE_NAME_RE` if Kwork rotates names |
| 409 on first call to a freshly seeded cluster | `preset_missing` | Reseed `kwork-account-replier` via `scripts/re-instantiate-presets-from-json.ts` |
| Same cookies create N projects | (no log — see `user_integrations` row count per user) | Bootstrap migration didn't run; check `CREATE TABLE IF NOT EXISTS user_integrations` in `services/bootstrap-schema.ts:372` |
| 500 fork_failed with `slug_collision` | `[integrations/kwork] … fork_failed` | Slug entropy is 5 random bytes → 5 retries; if hit, the alphabet at `makeProjectSlug` needs more entropy |
| 201 but `agent_id: null` in response | `[integrations/kwork] provision_failed user=…` | Inspect Eliza runtime logs in the user's vcluster — provisionAgent failed but secret + project landed; retry by re-POSTing same cookies |
